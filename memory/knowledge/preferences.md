# 用户偏好与拍板（L2 · 主题 · 常驻）

> ★ 标记 = 用户明确纠正过，**不可被自动覆盖**，只能由用户本人改。门禁违反过，代价很大。

## ★ 流程门禁（违反过，代价很大）

1. **K-018 · 需求未澄清不动手** —— 先走需求澄清，产出《需求确认》，用户点头前一行代码都不写。
   来源：用户原话「我提出一个需求，你就直接动手，这是绝对不允许的」
2. **待决策只进 `docs/07-架构与决策/ROADMAP.md`**；`docs/08-参考/PROGRESS.md` 只记已完成。
   来源：事故 —— 铃铛 09-14 被发现却记进 PROGRESS → 失踪 7 天
3. **K-019 · 功能做完先开环境给用户测**（统一入口 **18080**）—— 用户不通过不得进文档 / 推送环节。
   ★ **禁止自己跑完沙箱就宣布完成**（沙箱无 nginx 层，测不出真实问题）
4. **K-020 · 重建生产 docker 是最后一步，单独问用户**，不顺手做。
5. **改任何东西先做「横向同类扫描五问」** —— 漏问 = 同类问题只修了一处。

## ★ 版本策略（K-027 · 2026-09-23 拍板）

> **服务器用什么版本，本地就用什么版本** —— 同一份统一入口编排（18080）、同一份代码，**数据也保持一致**。

- **老三端口彻底废弃**（本地与服务器都不再用，相关资产一并删）
- **只推 gitee**，不推 GitHub
- 同步流程见 `docs/06-部署/本地与服务器同步.md`

## ★ 产品已定案（别再"纠正"回去）

- **K-021 · 待办两端都要**（教务端 + AI 工作台）—— 用户被质疑后重申「我确实要两端」
- **K-016 · 推进顺序**：教务系统闭环**优先于一切新功能**；AI 工作台须先收集老师意见
- 教务端「独立菜单项 + 铃铛 tab」都保留
- 待办**双端共用一张表** + 按 `owner_id` 过滤（不是两套表）
- 铃铛只有「通知 + 待办」两个 tab ——「消息」已砍

## 沟通方式

- 先给结论再给理由；不同意直说。
- 该详细时不惜笔墨，该一句话时不多写一个字。
- 不做"很好的问题！"这类填充式客套。
