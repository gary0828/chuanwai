## ★ 流程门禁（违反过，代价很大）

1. **K-018 · 需求未澄清不动手** —— 先走需求澄清，产出《需求确认》，用户点头前一行代码都不写。
   来源：用户原话「我提出一个需求，你就直接动手，这是绝对不允许的」
2. **待决策只进 `docs/07-架构与决策/ROADMAP.md`**；`docs/08-参考/PROGRESS.md` 只记已完成。
   来源：事故 —— 铃铛 09-14 被发现却记进 PROGRESS → 失踪 7 天
3. **K-019 · 功能做完先开环境给用户测**（统一入口 **18080**）—— 用户不通过不得进文档 / 推送环节。
   ★ **禁止自己跑完沙箱就宣布完成**（沙箱无 nginx 层，测不出真实问题）
4. **K-020 · 重建生产 docker 是最后一步，单独问用户**，不顺手做。
5. **改任何东西先做「横向同类扫描五问」** —— 漏问 = 同类问题只修了一处。

## ★ 推进顺序（K-032 · 2026-09-23 用户改口，覆盖"先做 AI 工作台"）

> 用户先说「开始对 AI 工作台做开发」，澄清 4 问后**当场改口**：
> 「算了，先不搞 AI 工作台了，**先把教务系统搞完善吧**」。
> → 与 D14「教务系统闭环优先于一切新功能」一致，**AI 工作台那 4 个澄清问题全部作废**。
> → 本轮范围由用户指定：**补 P1 硬伤（C3 自助改密码 + C2 头像）**，不是 Phase 1 / C4 走查 / Gate 3 技术债。
> → **服务器原地升级延后**：本地改完并用户实测通过后再一次性同步。

**本轮 4 项决策（用户全部采纳推荐值，勿轻易推翻）**

| 决策 | 结论 |
|---|---|
| 形态 | 顶栏**现有下拉**加「个人中心」→ **独立页面**（`remaining.ts` 静态路由、**不进菜单**，与 `/ai-admin` 同理） |
| 改密口径 | 校验原密码 + ≥8 位 + 新旧不同 + **成功后吊销本人全部凭证（强制重登）**（与 H2 一致） |
| 头像范围 | `users.avatar` + 本人自助上传；**员工管理页列表也显示头像** |
| 可改字段 | 姓名 + 手机号 + 头像（**用户名/角色不可自助改**） |

> ★ 用户当场纠正的知识点：**顶栏下拉是 pure-admin 自带的**（原本只有「退出登录」）——
> 新入口要**加进现有下拉**，不要另造一套。
