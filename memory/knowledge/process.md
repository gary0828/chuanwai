## 写验证脚本的规矩（K-011）

- ★ **只测 admin 会漏掉整类权限问题** —— 涉及权限的改动必须**双角色对照**（admin ＋ teacher）。
- 浏览器验证要用**生产构建产物**，不要用 dev server（dev 无 nginx 层，测不出真实问题）。
- 断言要**打印实际值**，别只打 PASS/FAIL（否则像 K-029 那样误报时无从判断）。

## 内容清点：静态扫 + 运行时探针，缺一不可（K-037 · 2026-09-23）

> 做「界面显示的值来自哪」这类清点时，**两种手段都要用，各自能捞出对方看不见的东西**。

- **静态扫**（grep/读代码）能查出：写死的展示数据、`data:[` 内联图表数据、**越界外链**。
- **运行时探针**（`_verify_test/probe-empty-fields.mjs`：登录后拉全部列表接口，列出**所有行都为空**的字段）
  能查出静态扫**看不见**的东西：**某字段在真实数据里恒为空**。
  ★ 2026-09-23 实跑结果：`remark` 在 **6 个模块**恒为空 —— 静态扫完全看不出这是"模式"，只有跑一遍才发现。
- ★★ **但「恒为空」≠「缺陷」**：必须再溯源**有没有录入入口**（表单/导入/接口写入点）。
  实测 `remark` 在 exams / payments / leads 等处**都有录入入口**，只是演示数据没填 → **不是缺陷**。
  **只看数据为空就下结论，会误报一整批。**
- 反过来，**静态扫看不出"渲染了但没人赋值"**（如 `v-if="noticeItem.avatar"` 而组装方从不赋 `avatar`）——
  这类要读**数据生产端**，别只看消费端。
- 报告须写明**前提**：本地是演示/种子数据，空字段不等于生产恒空。

## Vue 模板里的插值不会在静态属性里求值（K-038 · 2026-09-23）

> ★ `description="近 {{ days }} 天"`（**没有冒号**）= 静态属性，Vue 3 **原样输出**，用户直接看到 `{{ }}`。
> 必须写成 `:description="`近 ${days} 天`"`（或 `:description="'近 ' + days + ' 天'"`）。

- 排查命令（一次扫全项目）：grep `[a-zA-Z-]+="[^"{}]*\{\{`
- 2026-09-23 清点结果：全项目（`src` + `ai-workbench`）仅 `attendance/statistics/index.vue` 2 处
- ★ 这是**从 Vue 1 迁移过来的人最容易犯**的错：Vue 1 支持属性内插值，Vue 2/3 已移除，
  且**不报错、不警告**，只在"运行时"表现为丑文案（如空态提示）

## 记忆系统自身（K-030 · 用户 2026-09-23 拍板）

> ★ **有用优先，体积可超。** 考核「是否真帮上开发 + 省 token」，**不考核文件大小**。

- 体积上限是**软上限**：超了只提示，不算失败；护栏查的是**结构性**问题（见 §下方）
- 省 token 的杠杆是 **按需加载**，不是把文件压小 → 用 `node memory/route.mjs <改动的文件…>` 决定该读什么
- **索引不是容器**：`knowledge/_index.md` 一行一个**主题文件**；细节放主题文件里
- **不写清单**（不存能从 `grep` / `git log` 拿到的东西）：代码结构、git 历史、中间调试过程 → 只存**结论**
- **用前先验证**：记忆是提示不是真相；引用"某文件/某端口存在"前先 `grep`/`ls` 确认。
  ★ **代码的当前状态永远赢过记忆。**
- **陈旧比没有更危险**：发现记忆与事实不符 → **立即改**，不要"回头再说"
- 不引数据库、不引向量库（<1 万条时文件方案准确率更高且零基础设施）

## 结构性护栏（`node memory/check.mjs` 会拦）

| 检查 | 级别 |
|---|---|
| 必备记忆文件缺失 / **在 git 中消失** | ERROR |
| 知识条目指向的详情文件不存在（死链） | ERROR |
| 敏感数据混入记忆（密钥、口令） | ERROR |
| 同一 K-id 出现在多个主题文件（多源真相） | ERROR |
| 主题文件未被 `_index.md` 收录（孤儿） | WARN |
| 条目 `active` 但超过 90 天未验证（僵尸） | WARN |
| 文件超软上限 | WARN |
| 日志超 6KB（应 Promote 蒸馏） | WARN |

## 记忆的能力边界（K-031 · 说实话）

**记忆系统 = 外部记忆。** 模型跨会话**没有记忆**，"永久记忆"只能等于
「**这些文件可靠地被找到 → 被读到 → 被验证**」。所以三个环节缺一不可，缺哪个断哪个。

| 能做到 | 做不到（别指望） |
|---|---|
| 跨会话 / 跨模型 / 跨机器记住关键事实与决策（git 追踪 + 路由） | AI"自己记得"、永不遗漏、永不犯错 |
| 低成本检索（索引 + 主题文件 + `grep`），零基础设施 | **自动判断哪条已过时**（只能靠体积/龄期 WARN + 用前验证） |
| 把"为什么"沉淀下来（日志 → 主题文件的 Promote） | 记住**没写下来的**（口头讨论、临时判断） |
| 防误删（git 追踪 + 结构护栏） | **保证一定被执行** —— 这是纪律问题，靠平台注入层（`.workbuddy/memory/MEMORY.md`）兜底 |

**结论**：本项目规模（几百 ~ 几千条）下，**文件 + 路由**是当前最可靠的做法（优于向量库）。
真正的风险**不在技术，而在"开局没读 / 读了但没验证"**。

## ★ K-050 · "功能测试通过" ≠ 用户能用：**静默即缺陷**（2026-09-26 真实事故）

**事故**：`/api/students/import` 接口测试**全绿**，但用户**完全无法使用**批量导入 ——
缺陷出在"用户选文件"这一步（前端 `before-upload` 参数用错，见 `frontend.md` K-049），
**API 层测试天然覆盖不到**。用户的原话正是「**没有任何反应**」。

**三条判据（本项目自此采用）**：

1. **任何一次用户操作都必须有明确反馈**（成功 / 失败 / 处理中）→ **静默一律按 P0/P1 处理**，
   不接受"功能其实是好的，只是没提示"。
2. **全局响应拦截器只兜底 HTTP 错误**（`src/utils/http/index.ts`）。
   以下两类**不会被兜底**，必须各页自己处理：
   - **请求根本没发出去**（前端参数/逻辑错，如本次）
   - **HTTP 200 但 `success: false`**（业务失败）
   → 凡遇"点了没反应"类反馈，**先查这两条**。
3. 凡"**要点 / 要选 / 要传 / 要填**"的环节，**必须走真实 UI 操作**（Playwright）才算测过。
   既有 `server/scripts/e2e-lifecycle.mjs` 覆盖的是**后端生命周期**，不代表 UI 可用。

**落地资产（可复用）**：

| 文件 | 用途 |
|---|---|
| `docs/08-参考/业务流测试计划-*.md` | 业务流 + 检查点 + **分级判据** |
| `_verify_test/business-flow.py` | UI + 跨模块对账 + **自动清理测试数据** |
| `_verify_test/repro-student-import.py` | 「导入无反应」复现诊断（可回归） |

**测试数据卫生**：自动化脚本必须**清理自己产生的数据**（本项目用 `IMP/IMOK/流程测试` 前缀标记，
脚本末尾按前缀删除）。**清理顺序**：先删订单 → 再删学员 → 再删线索（学员有报班记录时会被拒绝删除）。

## ★ 验证脚本的三层分工（2026-10-03 建立）

同一个功能要"真的能用"，需要三层断言，**缺一层就漏一类缺陷**：

| 层 | 手段 | 能抓什么 | 抓不到什么 |
|---|---|---|---|
| **① 数据契约** | `.mjs` 打接口，断言**每个字段名** | 字段拼错（`revenue_by_course` vs `courseRevenue`）、权限码| 前端 options 结构写错 |
| **② 渲染存在性** | Playwright 断言 **canvas 数量 + 非零尺寸 + 非空像素** | options 结构错、ref 失效、容器 0 高度 | 图画歪了不好看 |
| **③ 人工看截图** | `evidence/*.png` 我自己 Read 一遍 | 标签重叠、配色刺眼、布局塌陷 | —— |

★ **10-03 实测**：② 层断言写宽松（只判 `canvas > 0`）时，**漏斗整页不渲染都没被发现**，
直到 ③ 层看截图才暴露。→ **断言要按"卡片"逐张判`drawn + empty >=卡片数`，
且必须区分「画出」与「按设计空态」两种合法结果**，否则要么漏缺陷、要么被合法空态误报。

## ★★ K-078 · 批量给测试脚本注入参数时，要当心**脚本间的写法差异**

**场景**：`course_id` 变必填后，7 个既有验证脚本全挂，需要统一注入。

**做法**：在脚本的请求封装函数（`call`/`api`）**内部**加注入 —— 一处改动覆盖该脚本所有调用点，
比逐个调用点手改稳（少了必然的遗漏）。

**但踩了三个坑**：

| 坑 | 现象 | 修法 |
|---|---|---|
| **body 形态不同** | 多数脚本传**对象** body（由请求层 stringify），而 `verify-qbank.mjs` 传**字符串** body（自己先 stringify）。只处理对象 → 该脚本**静默不注入** → 建题 400 → 后面 `JSON.parse(undefined)`，**错误现象离真因极远** | 注入函数同时支持对象与字符串两种 body |
| **箭头函数没有函数体** | `const call = (tk,p,o={}) =>\n  fetch(...)` 是**单表达式**箭头函数，插入的语句会跑到函数外并被当成表达式 | 改成带 `{}` 的函数体 + `return` |
| **注入正则覆盖不全** | 只覆盖 `questions`/`import`/`ocr`，漏了 `taxonomy/kp`（新增知识点也要学科）→ 那个用例失败 | 正则扩展为 `(questions\|ocr/\|taxonomy/(kp\|chapter))` |

**★ 教训**：**自动化注入脚本本身需要"验证注入是否真的生效"** ——
我一开始没验，导致「以为注入了、其实静默跳过」，而错误现象（JSON.parse(undefined)）
指向的是完全无关的地方。**改完一个脚本，立刻单独跑一次看结果**，比批量改完再一起跑更快定位。

## ★ K-079 · 本机 `http_proxy` 会让 curl 走代理 → 本地服务测试必须 `--noproxy '*'`

**症状**：`curl http://127.0.0.1:18080/qb/` 返回 **HTTP 000**（连不上），
但容器内 `wget 127.0.0.1:80/qb/` 正常、端口也在 LISTENING。

**根因**：本机设了 `http_proxy=http://127.0.0.1:1620`，curl 把请求发给了代理，
代理转发本地回环地址时失败。`curl -v` 里能看到 `Uses proxy env variable http_proxy`。

**修法**：本地服务一律 `curl --noproxy '*' ...`。
★ 与推送 gitee 时要 `git -c http.proxy= -c https.proxy=` 是**同一类问题**（工程机上有代理）。

## 「只在 onMounted 拉一次」+ 异步建立会话 = 竞态；且注入式 UI 测试查不出来（K-081 · 2026-10-09）

**症状**：老师从教务端（顶栏点「题库」）进入后，**学科下拉框点不动**，
且列表**不带 `course_id`**（把各学科的题混在一起显示）。而从别处进 / 直连有时又是好的 —— **时好时坏**。

**根因（两条叠在一起，缺一不成）**：
1. `App.vue` 的 `onMounted` 里调 `loadSubjects()`，而它要与 `Sso.vue` 的 `await verify()` **并发**
   （Vue 子组件 `onMounted` 先于父组件，且 verify 本身是 async）→ 常抢在验票前发出 → **401**
   → `subjectList` 永久为空 → 切换器 `:disabled`；且 `currentSubjectId` 停在 0 → 请求不带学科。
2. 验票成功后只 `router.replace("/")`，**App 不会重新挂载** → 没有任何代码会补这一次请求。

**修法**：`watch(isRealUser, v => v && ensureSubjects())` —— 会话一出现就补拉，
覆盖"会话由任何路径后到"的所有情况。**比在 Sso.vue 里补调一次更稳。**

**★★ 更重要的教训：546 项断言全绿，一个 bug 都没抓到。**
不是断言写错了，是**测的东西不对**：
- 所有 UI 套件都是「先往 `localStorage` 注入 session，再 `reload()`」——
  **把免登落地这条真实路径整条绕过** ⇒ 竞态永远复现不出来。**自测全绿 ≠ 用户能用。**
- 没有一条断言检查「**点完之后状态真的变了**」⇒ K-080 的 TypeError 也漏掉。
- ⇒ 规矩：**入口类功能必须有一条走真实链路的断言**（这里：走 `/#/sso?ticket=` 的整页跳转），
  并且断言要卡在**行为真的发生**（URL 变了 / 控件真的可用 / 请求真的带了参数），
  不能只验"控件存在"（同 K-073）。

**★ 怎么用日志定位这类问题**（很值，比读代码快）：
```
docker logs attendance-server --tail 25
```
`[req] POST /login 200` / `GET /subjects 401` / `POST /sso/verify 200` / `GET /facets 200` …
—— **请求序列本身就把竞态画出来了**：缺一个 `GET /subjects 200`，就是它。

**★ 写这种测试时的坑**：`page.goto("/qb/#/")` → `page.goto("/qb/#/sso?ticket=…")`
**只换 hash，浏览器不重新加载页面**，Vue 还带着内存里的旧会话 ⇒ 这条测试等于没测冷启动。
必须**先跳到不同路径**（如教务端 `/`）再进票据地址，或 `reload()`。
