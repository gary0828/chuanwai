### 一、记忆系统

1. **★★ 日志无限膨胀，「Promote 到主题文件」这条规则从未被执行**
   - 实证：`node memory/check.mjs` 报 **6 个日志文件全部超 6KB**（`2026-09-23.md` 已达 **59 KB**），
     每次都是 WARN 但从不处理 → 日志退化成流水账，跨会话"读日志接续"的成本高到不现实
   - 建议：把软上限变成**硬门禁**（超 2 倍即 `check.mjs` 非零退出），或加定期归档动作

2. **★★ 跨会话恢复：做过一次（6/6），但已 8 天未复验 —— 且"必读"通道会被跳过**
   - **修正上一条初稿的误判**：09-23 12:00 其实做过「零上下文新会话盲测」，**6/6 全对**、自评"能接手"
     （见 `memory/archive/2026-09-23.md`；我当时没查到就下了"从未验证"的结论 —— 本身也是"没扫全"的例子）
   - 真实缺口有两条：
     (a) **盲测已过 8 天**，期间记忆规模翻倍（迁到 v25、菜单重构 3 次、日志涨到 59KB）→ **该复验**
     (b) **"必读 4 份"这条通道依赖模型遵守** —— 本次会话我只读了其中 2 份（`CURSOR` + `preferences`），
         因为上下文没断就"懒得读"。**通道存在 ≠ 每次都被走**。
   - 建议：把"只读记忆能否接上"做成可跑的脚本（而非靠自觉），并定期复验

3. **★ 同一件事写三遍**：平台记忆 `.workbuddy/memory/` + 项目 `memory/logs/` + `CURSOR`
   - 实证：09-30 同一次开发我在两处写了高度重复的记录
   - 成本：双倍维护 + 可能不一致；建议明确"一件事只写一处，其余给指针"

4. **★★★ 知识条目与「可执行检查」脱节（最关键）**
   - `testing-and-verification` skill 里明明写着「**扫代码必须用 ripgrep**，shell 的 `grep -r`
     在本环境会静默返回空」，**我这次仍用 shell grep 扫文档** → 漏了 7 处残留，
     还把 ADR-013 里 Q3 的出处**写错了**（真出处是 `server/docs/021-*-PRD.md`，我写成了 API.md）
   - 对比：**迁移版本连续性**从不出错，因为执行器会**强制报错**（`if (m.version !== current + 1) throw`）
   - → **教训：写在文档里的规则会被遗忘，写在代码里的约束才可靠。**
     建议把关键铁律做成脚本/钩子（如扫描类检查统一走 ripgrep、pre-commit 校验）

### 二、skill

1. **★★★ 4 个项目级 skill 全部无法通过 Skill 工具加载（最严重）**
   - 它们放在 `.workbuddy/skills/`，而 Skill 工具只扫 `~/.workbuddy/skills/`
   - 实证：本次 `Skill(feature-dev-flow)` → **`Can not find skill`**
   - 受影响的是项目**最核心的约定**：`feature-dev-flow`（5 道门禁）、
     `testing-and-verification`（六条验证铁律）、`frontend-page-authoring`（两端差异）、`memory-protocol`
   - 现状靠 `MEMORY.md` 里一条"实测补丁"（记得直接 Read）撑着 →
     **新会话若没读到那条补丁，整套门禁等于不存在**
   - 建议：把这 4 个 skill 同步到用户级目录（或改为可加载形式），从根上消除对"记性"的依赖

2. **★ skill 的规则与实际执行方式不匹配**
   - `grill-me` 要求"逐个分支追问"，我实际用 AskUserQuestion **一次问 3–4 个**（更省用户时间）
   - `feature-dev-flow` 门禁 3 要求"用户不通过不得进 ④"，但用户**两次**主动要求跳过实测直接推送 →
     skill **没写这种情况怎么办**，我只能临时补"按用户决定执行 + 如实标注"
   - 建议：把"批量提问"与"用户主动跳过门禁"的处置补进 skill

3. **★ `code-review-and-quality` 加载了但用不上**
   - 它是"给人看的五轴 checklist"，**没有可执行部分** → 我实际只做了口头过一遍 = 等于没审
   - 对比：项目自己的 `e2e-lifecycle.mjs` / `verify-*.py` 是**真能跑**的
   - 建议：把可自动化项（lint / 类型 / 依赖审计 / SQL 参数化扫描）做成脚本纳入门禁
