## 09:20 | Fact | 服务器 18080 整页白屏的根因 = `.env.production` 被 gitignore 吞掉

- 来源: 用户报障（昨天服务器部署，白屏）+ 现场控制台报错
- 症状: `http://192.168.1.222:18080` 白屏；控制台 `Uncaught TypeError: Cannot read properties of undefined (reading 'split')  at index-<hash>.js`
- **根因（已用代码 + git 双向证实）**:
  1. `src/router/index.ts:77` 模块加载即执行 `createRouter({ history: getHistoryMode(import.meta.env.VITE_ROUTER_HISTORY) })`
  2. `src/router/utils.ts:338-340`：`getHistoryMode(routerHistory)` **无默认参数**，直接 `routerHistory.split(",")` → 传 undefined 必崩
  3. 为何 undefined：`.env.production` 定义 `VITE_ROUTER_HISTORY="hash"`，但 `.gitignore:20` 的 `.env.*` 把它一起忽略了（`!.env.example` 只放行样例）；`git check-ignore` 证实 `.env.production/.env.development/.env.staging` 全部 ignored 且 not tracked
  4. 触发路径：部署文档 `docs/06-部署/校区部署与升级.md:159/541` 用 **`git clone`** 取码 → 新克隆没有 `.env.production` → `vite build` 把 `VITE_ROUTER_HISTORY` 内联成 `undefined` → 崩
- **关键澄清（用户误判）**: 白屏与 `LLM_API_KEY` **无关**——它是后端变量、无 `VITE_` 前缀，Vite 根本不读它；「AI 配置中心」页面（`src/views/ai-admin/index.vue`，管理 llmApiKey/llmBaseUrl/llmModel/…）也已经存在且走 DB。这次炸的是 pure-admin 的**构建期路由变量**，属另一条线
- 同类扫描: 工作台 `ai-workbench/src/router.ts:117` 用**硬编码** `createWebHashHistory()`，无 env 依赖 → 无同类 bug；崩溃仅限教务端
- 影响面: 任何「git clone 到干净机器 + 本地 vite build」的部署都会白屏；本地开发（有 `.env.production`）与「拷整个目录」部署不受影响
- 待用户拍板: ① 构建期 env 是否入库 ② docker 统一到哪一形态 ③ LLM Key 是否彻底移出 .env

## 09:50 | Fact | 重部署会不会丢数据？—— 结论 + 文档补强

- 来源: 会话（用户：「服务器现在已经好了，但如果现在我要重新部署的话，服务器上的数据怎么办？」）
- 结论: **不会丢**。数据在宿主机 `<项目目录>/server/data/`（compose `- ./server/data:/app/data` bind mount，`server/Dockerfile` 另有 `VOLUME` 兜底），
  重建镜像 / 删容器 / `docker compose down`（不加 `-v`）都不影响；上传的 Logo 等在 `server/data/assets`，一并保留
- ★ **唯一真风险**: 另开**新目录** `git clone` 起服务 → 新目录没有 `server/data/` → 后端首启**自动建表 + 写种子演示数据**（老师会看到假班级），真数据仍留旧目录
- 附带: `.env`（含 `JWT_SECRET`）也在项目目录里且被 git 忽略 —— 换目录必须带上，否则密钥变、全员强制重登
- 本次无 DB 结构变化（仍 v19），不需要额外迁移
- 文档补强: `docs/06-部署/校区部署与升级.md` §5 升级五步法 —— 补「③ 先 `docker rm -f` 清旧同名容器」（本次 Docker 统一引入的**一次性**动作）+ 「必须同目录 pull，不要新目录 clone」说明
- 关联: K-026
