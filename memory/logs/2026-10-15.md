## 下午 · 「使用指南」单页（面向非技术背景的校区老师）

### Decision · 四个决策点（用户逐项拍板）

| 决策 | 结论 |
|---|---|
| 菜单位置 | **顶级菜单项**「使用指南」（rank 9，admin 与 teacher **两份数组都要加**） |
| 承载形式 | **静态 Vue 单页**，文案抽到独立 `content.ts`（零新依赖、改文字不碰模板） |
| 内容颗粒度 | **36 个页面每个都写分步操作**（不止四大业务流） |
| 角色区分 | **一份通用指南，只标注角色**（不按角色隐藏章节） |
| 推送范围 | 连同本地全部未提交改动一起推（含 v29，提交信息须标注「用户尚未实测即要求推送」） |
| 排除口径 | e2e 试点工程 / 一次性诊断脚本 / 数据库与截图（复核）/ 题库与工作台演示数据 |

### ★ 关键认知：菜单是**后端下发**的

`src/router/modules/` 只有 `error.ts` / `home.ts` / `remaining.ts` 三个文件 ——
教务系统的全部菜单在 `server/src/routes/auth.js:19` 的 `ROUTES` 常量里，按角色下发到
`GET /api/auth/async-routes`。**前端加菜单无效，必须改后端**（已在 `frontend.md` K-048 记过，本次再验一次）。
`ROUTES` 有 admin / teacher **两份数组** —— 只加一份，老师就看不到指南（而老师恰恰最需要它）。

### ★ 新增的可执行门禁（把"文档写对"变成会失败的东西）

| 脚本 | 作用 | 结果 |
|---|---|---|
| `_verify_test/extract-ui-facts.mjs` | 静态抽取 47 个 .vue 的真实控件名（按钮/弹窗/列名/页签/表单项） | 产出 `_tmp/ui-facts.md`，作为**写文档的事实来源**，杜绝凭印象编造按钮 |
| `_verify_test/check-guide.mjs` | 内容一致性 + 可读性，**16 项** | 首跑抓出 **3 个真问题**（漏了指南自己的章节、某步 93 字、5 处技术术语） |
| `_verify_test/ui-guide.py` | 浏览器实证，**双角色 36 项** | 全绿 |

`check-guide.mjs` 里两条最值钱的断言：
- **A3 覆盖完整性**：后端菜单里**每个**叶子页面都必须在指南里有章节（36/36）——
  这一条让「全部功能都要写到」从口号变成机器判据；
- **B3 术语密度**：正文中「引号之外」不得出现 接口/字段/数据库/部署 等词 ——
  引号内的界面控件名（读者会在屏幕上看到同一个词）不算术语。首跑抓到 5 处，已全部改写。

### ★ 两个"看着对其实错"的坑

1. **hash 模式下不能用 `<a href="#xxx">` 做页内锚点** —— 那会把 `#/guide` 换成 `#xxx`，**路由直接被顶掉**。
   本页一律用 JS `scrollIntoView`，不碰 URL。已写成断言（点目录后地址仍是 `#/guide`）。
2. **红色警告框一开始有 71 个**（每个功能卡的注意事项都用了 danger）。
   满页红字会让读者对红色脱敏、反而漏掉真正危险的那几条 →
   改为「功能级注意 = 黄色，红色只留给不可撤销的操作（5 处）」。

### ★ 上传排除测试数据 → K-085（永久规则）

用户原话：「上传时必须排除测试数据，因为上一次上传包含大量测试数据导致部署混乱，此要求需作为永久记忆长期遵守。」
- 执行点 = `.gitignore` 里新增的专门一节；规则写进 `memory/knowledge/git-local.md` **K-085**。
- 复核发现：**数据库与截图早已排除**（`server/data/`、`evidence/`），`git ls-files` 证实**从未跟踪过任何 .db** ——
  真正夹带的只可能是 e2e 试点工程与一次性脚本。
- 与 10-01 的决定（`_verify_test/*` 脚本是资产要入库）**有冲突面**：
  对「一次性脚本」与「e2e 试点」开例外；**v29 的 5 个回归套件临时排除**并就地标注「待用户点头后恢复」。
- 顺手修 `preflight.mjs`：`SKIP_DIRS` 加 `.e2e`（录制缓存是生成物且已排除入库，扫它只产生**无法处理的假阳性**）。
