用户在 18080 实测题库，报两个问题：① 学科下拉框无法点击 ② 最下方「返回教务系统」点击无效果。

### 诊断手段
1. Playwright 无凭据复现（直接访问 `/qb/`）→ 抓到 **JS 堆栈**：
   `TypeError: Cannot set properties of undefined (setting 'href')`

3. 横向 grep 全仓 `location.href` → 发现同类第 2 处 + 正确写法对照

### 根因 ①：学科切换器点不动 = **SSO 验票与 loadSubjects 的竞态**（不是"没登录"）

后端日志（用户那一次进入）：
```
POST /login      200   ← 教务端登录
GET  /subjects   401   ← 题库 App 挂载即拉学科，此时票据还没验 → 401
GET  /facets     401
POST /sso/ticket 200   ← 教务端签发票据
GET  /subjects   401   ← ★（第二次，仍未带 token）
POST /sso/verify 200   ← 验票成功、存会话
GET  /facets     200   ← 列表/筛选正常
GET  /questions  200
（★ 全程没有 GET /subjects 200）
```

- `loadSubjects()` **只**在 `App.vue` 的 `onMounted` 跑一次；它与 `Sso.vue` 的 `await verify()` **并发**，
  常常先发出（Vue 子组件 onMounted 先于父组件，且 verify 是 async）→ 无 token → 401。
- `subjects` 为空 → `:disabled="subjectList.length === 0"` → **切换器永久禁用**。
- 验票成功后只 `router.replace("/")`，**App 不重新挂载** → 没有任何代码会补这一次请求。
- ★ **连带问题（同根因，更隐蔽）**：`currentSubjectId` 停在 0 → `withSubject()` 不写 `course_id`
  → 列表请求**不带学科过滤** → 后端 `courseFilter` 返回空条件 → **把所有学科的题混在一起显示**，
  直接违反「按学科隔离」的设计。★ 这是"界面死"与"数据串"同一个 bug 的两个面。
- 因为是竞态，**时好时坏**：verify 偶尔先完成时看起来正常。

### 根因 ②：`location.href` 写在**模板**里 —— 编译成 `_ctx.location` → undefined

```html
<!-- question-bank/src/App.vue:98 -->
@click="() => (location.href = crmUrl())"     <!-- ❌ 点击 → TypeError，什么都不发生 -->
```
`<script setup>` 的模板编译会给未绑定标识符加 `_ctx.` 前缀，而 `location` **不在** Vue 的全局白名单里
（白名单只有 `Math/Date/JSON/console/...`，没有 `window/location`）→ `_ctx.location` 为 undefined
→ `undefined.href = ...` 抛错并被吞掉 → **点击无任何反馈**（K-050「静默即缺陷」的典型）。

**同类第 2 处（必须一起修）**：`question-bank/src/views/Sso.vue:72` 的
`@click="() => (location.href = '/')"` —— 免登失败页的「返回题库首页」按钮**同样是死的**，
而且目标 `/` 就是题库首页 → 逻辑上是死循环，应该是「返回教务系统」。

**正确写法的对照**：`ai-workbench/src/App.vue:84` 是 `window.location.href = crmUrl();`
—— **在 script 里**。⇒ 错因很明确：题库是从工作台照抄的，**抄的时候把 `window.` 丢了、还把它搬进了模板**。

### 横向同类扫描结论
| 位置 | 形态 | 判定 |
|---|---|---|
| `question-bank/src/App.vue:98` | 模板里 `location.href` | ❌ 坏（就是反馈 ②） |
| `question-bank/src/views/Sso.vue:72` | 模板里 `location.href` | ❌ 坏（同类，未报但在） |
| `ai-workbench/src/App.vue:84` | script 里 `window.location.href` | ✅ 正确 |
| `src/layout/frame.vue` / `welcome/FeedbackPanel.vue` | script 里 `window.location` | ✅ 正确 |

### ★ 最重要的教训：**546 项断言全绿，却没抓到这两个 bug**
不是断言写错了，是**测的东西不对**：
- 所有 UI 套件都是"先把 session 注入 `localStorage` 再 reload" → **绕过了 SSO 落地这条真实路径**
  → 竞态 ① 永远复现不出来（这解释了为什么自测全绿而用户一进就坏）
- 没有任何断言检查「点按钮后 URL 真的变了」→ ② 的 TypeError 也就漏掉了
- ⇒ 待补断言：**必须有一条走真实免登链路的 UI 断言** + **"点击后状态真的改变"类断言**
  （同 K-073 的教训：断言要卡在"行为真的发生"上，而不是"控件存在"）
