## 08:35 | Question | 用户质疑「新功能太复杂看不懂」+「是否和数据管理重复」

- 来源: 会话（用户原话「你解释一下你新做的那几个功能都是干什么的？我看起来怎么这么复杂？看不懂。并且我觉得你新作的功能是不是和数据管理里面的有些内容重复了？」）
- 影响: 无代码改动（本轮只做解释 + 比对）；产出一个「模板 vs 实例」图解 widget
- 关联: G1+G2（v21 课次实体 / 任课关系）

### 核查结论（已读代码验证，不是凭印象）

**「数据管理」到底是什么** —— 它是 `server/src/routes/auth.js:180/344` 里的一个**菜单分组** `/data`，
不是功能模块。内含（admin）：班级管理 / 学生管理 / 课程管理 / 课程表 / 学期管理 / 调课审批 / 补课管理；
（teacher）：班级管理 / 学生管理 / 课程表 / 补课管理。

**逐项比对**

| 新功能 | 数据管理里的邻居 | 结论 |
|---|---|---|
| 周课表（sessions） | 课程表（schedules） | ❌ 不重复：**模板 vs 实例**。schedules 一条记录 = 每周重复的一节课；class_sessions 一条 = 某天某节具体的课 |
| 任课关系 | 课程管理里的「授课教师」 | ❌ 不重复：`courses.teacher` 是**手填文本**（`src/views/attendance/courses/index.vue:31`），不与 users 关联；teaching_assignments 是结构化关联表。证据：schedules 页冲突检测用 `r.teacher || ""` 做**文本比较**（`schedules/index.vue:174`） |
| 节次时间 | 学期管理 | ❌ 不重复：一个是学期起止，一个是第 N 节的钟点 |
| 回填报告 | 数据备份（系统管理） | ❌ 不重复：备份 = DB 文件；回填报告 = 历史数据挂课次的成功/失败清单 |

### ⚠️ 唯一一处真重叠（未解决，待用户拍板）

**「调课」有两个入口、两套语义，都叫调课：**

1. `数据管理 → 调课审批`（`server/src/routes/adjustments.js`）：teacher 申请 → admin 审批 →
   通过后 **UPDATE schedules**（`adjustments.js:146`）→ **改的是模板，以后每周都变**
2. `考勤管理 → 周课表 → 课次详情 → 调课`（`POST /sessions/:id/reschedule`，admin 直接操作）：
   原课次标「已调课」+ 新建新课次 + 双向关联 → **改的是某一节，不影响以后**

语义确实不同，但**术语撞车**，用户会困惑。已向用户提出三个选项（改名 / 审批通过后联动停课次 / 把单次调课并入审批流）。

### 另一个易混点（未解决）

周课表挂在「考勤管理」下，课程表挂在「数据管理」下 —— 两个都长成星期网格，
但数据不同。建议要么改名（课程表→「排课模板」），要么把周课表挪到「数据管理」里与课程表并列。
