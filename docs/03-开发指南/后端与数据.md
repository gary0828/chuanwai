# 后端与数据库约定

> 目的：改后端 / 动数据库前必读。这里的每一条都是**踩过坑才写下来的**。

---

## 1. 数据库

- **版本连续，跳号会终止启动**（`migrations/index.js` 会抛「迁移版本不连续」）。
  `PRAGMA user_version` 即当前版本。
- ★ **什么才需要迁移**：只有**新建 / 改动表结构**才要。
  **往既有 K-V 表（`settings`）加键 = 纯数据写入，不占版本号。**
  - 例：`todos` 建表 → 占 v19；`site.*` 只是往 v6 的 `settings` 加行 → 不占
- 迁移文件：`server/src/migrations/0NN-name.js`，导出 `{ version, name, up(db) }`，
  **并在 `migrations/index.js` 的数组里登记**（否则不会执行）。
- 表结构与版本历史同步维护在 **`server/database.md`**（权威）。

## 2. ★ `db` 是 `node:sqlite` 的裸封装

`server/src/db.js` 全文就一句 `module.exports = db`，其中 `db = new DatabaseSync(...)`。

```
✅ db.prepare(...)      ✅ db.exec(...)
❌ db.transaction(...)  ← 不存在！
```

**我误按 better-sqlite3 的 API 写过一次 `db.transaction(fn)`**，运行时报
`db.transaction is not a function`，而且**前端只看到 `{"success":false,"message":"..."}`，
堆栈只在后端日志里** —— 排查时要去看容器日志。

✅ 正确写法（照 `migrations/index.js`）：

```js
db.exec("BEGIN");
try {
  /* ... */
  db.exec("COMMIT");
} catch (e) {
  db.exec("ROLLBACK");
  throw e;
}
```

## 3. ★ 删数据后必须 checkpoint，否则重启"复活"

SQLite 用 WAL。直接 `DELETE` 后若不做 checkpoint，数据可能仍在 WAL 里，
**容器重启后旧数据又回来了**（2026-09-21 实测）。

```js
db.exec("DELETE FROM ...");
db.exec("PRAGMA wal_checkpoint(TRUNCATE)");   // ★ 这步不能省
```

验证方式：重启容器后再查一次。

## 4. 路由与审计

- 新路由：新建 `server/src/routes/xxx.js` → 在 `server/src/index.js` 挂载
  （`app.use("/api/xxx", require("./routes/xxx"))`）
- **同时在 `AUDIT_MODULES` 加模块名**（审计日志的中文名），否则审计里显示为未分类
- ⚠️ 匹配是**前缀正则**：`/^\/api\/notices/` 不会误匹配 `/api/notifications`（`notic` 后一个是 `e` 一个是 `a`），
  但新增路径时要留意有没有被更短的正则吃掉

## 5. 待办生成器（`server/src/utils/todo-generator.js`）

- 幂等：一条来源 = 一条待办；已完成但条件又出现 → **回写为「待办」**而非新增
- 触发：① `GET /api/todos` 内按需（**60 秒节流**）② `index.js` 的 `setInterval` 每 6 小时
  （+ 启动 30 秒后，**`unref()`**，零新依赖）③ admin 手动 `POST /api/todos/generate?force=1`
- 阈值走 `settings` 表同名键，缺失用代码里的默认值（**加键不占版本号**）

## 6. 工作台会话（`ai-workbench/src/session.ts`）

- ★ **`?token=` 传的是已验证的 agentToken，不是 ticket**。
  `agentTicket` 换会话走 `/api/ai/sso/verify`（票据由 `/api/ai/sso/ticket` 签发，60 秒、一次性）
- `agentToken()` 优先读 URL 的 `token` 参数（**仅供本地联调**，会留在浏览器历史里）
