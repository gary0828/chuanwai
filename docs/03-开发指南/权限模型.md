# 权限模型

> 目的：任何涉及"谁能看到什么"的改动前必读。
> 完整业务流程梳理见 `../archive/业务流程与权限梳理报告-2026-09-12.md`；本文只沉淀**硬规则与踩过的坑**。

---

## 1. ★ 人群分离（最重要的一条）

| 端 | 使用者 |
|---|---|
| **教务端** `src/` | **校区负责人** |
| **AI 工作台** `ai-workbench/src/` | **一线老师** |

★ **老师要用的功能一律收在工作台**，教务端「成长档案」保留但**只读**。

## 2. 权限四层

1. **菜单不下发**（`server/src/routes/auth.js` 的 `ROUTES[role]`）
2. **接口 403**
3. **字段脱敏**
4. **导出不含费用**

**财务与招生线索：全部 `requireRole("admin")`**（`routes/leads.js` 每一个端点都是）。

## 3. ★ 凭证放行：读写同权，边界在归属校验

工作台凭证 `type=ai_agent`（`server/src/middleware/auth.js`）只放行少数前缀：
`/api/agent`、`/api/ai`、`/api/growth`、`/api/todos`。

★ **放行是"读写同权"放行整段前缀** —— 老师既要看也要改。
★ **安全边界靠路由内的归属校验（如 `canManage`），不靠"挡住读"。**

> 反面教材：曾"放行写、挡住读" → 老师能写却看不到，整页 403。

管理动作（如 `PUT /api/growth/thresholds` 改全局阈值）**单独排除**，仅 admin。

## 4. ★ 自动生成的记录也要按归属过滤

**先例**：`notifications` 的 `notificationScope()` —— 老师只看
`class_id IN (SELECT id FROM classes WHERE head_teacher_id = ?)` 的班。

**新做自动生成时照抄这套，不要自己发明。**（待办生成器就是照它设计的）

### 待办归属矩阵（L3）

| 事件 | 收件人 | 老师可见 | 依据 |
|---|---|---|---|
| 学员余额/课时不足 `tuition_low` | **仅 admin** | ❌ **绝不给** | 数据源 `orders`（**财务表**，含 `amount`） |
| 线索待跟进 `lead_follow` | **仅 admin** | ❌ **绝不给** | `leads.js` 全程 `requireRole("admin")` |
| 连续缺勤 `absent_streak` | 班主任 + admin | ✅ 仅本班 | 教学口径 |
| 课评欠录 `eval_missing` | 班主任 + admin | ✅ 仅本班 | 教学口径 |

**★ 待办的 owner 由「事件类型」决定，绝不是"生成给所有人"。**

## 5. ★ 字段白名单与脱敏（ADR-005）

- **字段白名单是默认姿势**：公开/免登录端点只返回白名单内的非空项
- 出网（调 LLM）**一律脱敏**：学员姓名 / 家长姓名 / 电话 / 金额 / 身份证 / 住址 **不出网**
- 允许出网：内部学员编号、年级学科教材版本、结构化指标数值、知识点名称
- ★ **自动生成的待办正文也受此约束**：`orders.amount`、`leads.phone` 一律不查、不写入文案

## 6. ★★ 密钥铁律

**任何密钥不得出现在前端任何位置**（localStorage / 打包产物 / URL 都不行）。
**凡是前端能读到的位置 = 公开。**

模型调用一律走服务端 `POST /api/ai/generate`；工作台**不提供任何密钥输入入口**。
