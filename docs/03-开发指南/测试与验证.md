# 测试与验证

> 目的：写验证脚本 / 断言前必读。**测试全绿不等于没问题 —— 先审断言，再审被测物。**

---

## 1. ★★ 断言铁律

1. **绝不写「失败态也算通过」的断言**
   实录：`side_ok is True or side_ok is None` —— `None`（元素根本没找到）被当通过 = **空断言**，
   直接掩盖了 `/assets` 404 的严重 bug。改成三态：找不到 → **明确报失败**；找到但值不对 → 失败。

2. **权限类功能必须「双角色对照」测**
   同一页分别以 admin / teacher 登录，断言**看到的与看不到的都对**
   （列表可见范围、专属控件的有无）。
   ★ **"我用管理员测过了"不等于权限没问题。**（2026-09-21 由用户点出才补）
   参考 `_verify_test/ui-todos-teacher.py`

3. **静态资源类问题不能只看根路径**
   `/` 200 但页面白屏 = JS 404。断言里必须包含「**入口 JS 可获取**」+「**无 requestfailed**」，
   别只断言页面标题存在。

4. **不要把组件库内部结构当成违规**
   Element Plus 的 radio/checkbox/select 内部都有隐藏原生 `<input>`
   （如 `.el-radio-button__original-radio`）。扫"有没有裸露原生控件"时要**排除 `.el-*` 内部**，否则必误报。

5. **测试脚本自身的坑**：跨多次请求时，辅助字段要**每次重新计算**
   （如 `owner_id` 的辅助属性，第二次请求的对象上没有）。

## 2. ★ 扫代码必须用 ripgrep（Grep 工具）

**`grep -r` + 通配符在本环境会静默返回空**。
我据此得出过错误结论「工作台不用 Element Plus」，实际相反。

→ **扫代码一律用 Grep 工具**。**"扫不到"要先怀疑命令，再下结论。**

## 3. Playwright 注入登录态（pure-admin）

登录态 = **三者缺一不可**：

- Cookie `authorized-token`
- Cookie `multiple-tabs`
- localStorage `user-info`（**裸 key，无 `pure-` 前缀**）

**症状**：cookie 注入成功 → 3 秒后变空。根因：SPA 引导时读不到 `user-info` →
走 else `removeToken()` **把刚注入的 cookie 一并清掉**。

★ **登录页有 canvas 验证码 → 自动化只能走接口登录 + 凭证注入**
（`_verify_test/ui-site-info.py` 里有完整实现；注意 `expires` 是 `YYYY/MM/DD HH:MM:SS`，要转毫秒）。

## 4. 造数与清理

- 造数脚本（如 `server/scripts/seed-growth.mjs`）跑完**必须 `docker restart attendance-server`**
- 清理测试数据后**必须 `PRAGMA wal_checkpoint(TRUNCATE)`**，否则重启后复活
- 临时改阈值/数据做验证时，**先备份值，验完还原并复核**
