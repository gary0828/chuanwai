# 文档规范

> 全项目文档（根目录 `*.md` 与 `docs/`）统一遵守本规范。
> 目的只有三个：**找得到**（结构固定）、**信得过**（一处真相）、**读得下**（排版一致）。

---

## 1. 目录结构

```text
README.md              项目入口：这是什么、怎么跑起来（≤ 8 KB）
CONTRIBUTING.md        参与开发：环境、流程、门禁、文档同步义务
CHANGELOG.md           版本变更记录（Keep a Changelog 格式）
AGENTS.md / CLAUDE.md  会话启动入口（只放指针，不放正文）
WORKBUDDY.md           AI 开发硬约束（根目录，工具自动加载）
docs/
├── 00-导航.md          文档总索引（MOC）
├── 01-文档规范.md      本文件
├── 02-快速开始/        安装与启动、账号与权限
├── 03-开发指南/        代码定位、前后端约定、测试、环境坑
├── 04-API/             接口契约（人类可读 + 机器可读）
├── 05-配置/            环境变量与大模型配置
├── 06-部署/            部署、升级、回滚、运维约定
├── 07-架构与决策/      路线图 + ADR 决策记录
├── 08-参考/            进度档案、第三方上手指南
└── archive/            时点性报告（只读存档，不再修改）
```

**放哪的判断依据**

| 内容性质 | 归属 | 例子 |
| --- | --- | --- |
| 会长期为真的做法 | `03-开发指南/` | 迁移规则、脱敏白名单 |
| 会变的计划 | `07-架构与决策/ROADMAP.md` | 排期、优先级 |
| 已完成的事实 | `08-参考/PROGRESS.md` 或 `CHANGELOG.md` | 本次改了什么 |
| 某个时点的结论 | `archive/YYYY-MM-DD-*.md` | 评估报告、审计报告 |
| 三个月后会被质疑的决定 | `07-架构与决策/ADR/ADR-NNN-*.md` | 为什么不做多校区 |

## 2. 文件命名

| 规则 | 说明 |
| --- | --- |
| 目录用 `NN-名称` 编号 | 体现阅读顺序，`00` 是索引 |
| 活动文档**不带日期** | 文档是活的，日期会过期 |
| 归档文档**带日期** | `archive/` 内保留原命名，日期即版本 |
| ADR | `ADR-NNN-一句话结论.md`，编号三位、只增不改 |
| 大小写 | 目录全小写（英文）；文件名中文或英文均可，同目录内保持一种风格 |

## 3. Front-matter

每份文档的开头**可选**加三行元信息，字段固定为 `title` / `status` / `updated`：

```yaml
---
title: 部署与升级
status: active        # active（在用）| draft（草稿）| archived（只读存档）
updated: 2026-09-21
---
```

`status: archived` 的文档**只追加 `Correction:` 区段**，不得改写正文。

## 4. 标题与排版

1. **H1 全篇唯一**，就是文档标题；正文从 H2 起。
2. H2 用阿拉伯数字编号（`## 1. 安装`），H3 用 `### 1.1`（**不用**「一、二、三」「〇」「§」）。
3. 中英文与数字之间加一个空格：`用 Docker Compose 部署`；代码、路径、命令用反引号包裹。
4. 代码块必须标注语言：```` ```bash ```` / ```` ```ts ```` / ```` ```yaml ````。
5. 表格：表头与分隔行之间不留空行，每列宽度不必强行对齐（渲染后会错位），但**列数必须一致**。
6. 提示语统一：说明用 `>` 引用块；风险用 `> ⚠️`；禁令用 `> ❌`。
7. 链接一律用**仓库相对路径**（`docs/04-API/API.md`），不用绝对磁盘路径，不用 `file://`。
8. 状态标记统一：✅ 完成 / ⏸ 未开始 / ⚠️ 有风险 / ❌ 禁止。

## 5. 术语表（同一概念只用这一个词）

| 术语 | 含义 | 不要写成 |
| --- | --- | --- |
| 教务管理系统 | 本系统主体（前端 `src/` + 后端 `server/`） | 考勤系统、attendance-system（仅用于容器/镜像名） |
| 学员 | 被服务的孩子，`students` 表 | 学员/学生混用（代码标识符仍为 `student`，UI 文案「学生」逐步迁移） |
| 家长 | 学员监护人，只是档案字段，**无账号** | 家长端、家长用户 |
| 员工账号 | 登录系统的 `users` 记录 | 用户、会员 |
| 管理员（`admin`） | 机构校长/教务，权限全集 | 超管、root |
| 教师（`teacher`） | 授课老师，按班级隔离数据 | 老师端、讲师账号 |
| 班主任 | `classes.head_teacher_id` 绑定的教师 | 带班老师 |
| 课时包 | `orders` 上的 `total_hours` / `remaining_hours` | 课时余额、剩余课次 |
| 课消 | 课时消耗（`hour_consumptions`） | 消课、耗课 |
| 线索 | 招生线索，`leads` 表 | 潜客、商机 |
| 家校通知 | `notifications` 表（缺勤/成绩/请假） | 消息、短信、推送（系统不出网） |
| AI 教学工作台 | 独立站点 `ai-workbench/`，简称「工作台」 | AI 端、助手端 |
| 数据资产 | `server/data/assets/` 下的产出文件 | 附件、素材 |
| 迁移脚本 | `server/src/migrations/0NN-*.js` | 升级脚本、DDL |
| 数据版本 | `PRAGMA user_version`，如 `v19` | schema 版本、db 版本 |

**端口与地址**：前端 `8080`（Docker）/ `8848`（vite dev）；后端 `3000`；工作台统一入口 `/ai`；Dify `:8081`（仅部署时用到）。

## 6. 写作纪律

1. **一处真相**：同一事实只写在一处，其它地方放链接。复制粘贴 = 必然过期。
2. **会变的与不变的分开**：计划可改；**ADR 只追加不修改**，要改就新增一条并标记取代关系。
3. **不知道写哪就先别新建**：先在 `memory/logs/YYYY-MM-DD.md` 记一行，下次整理时再决定归属。
4. **改代码就要改文档**：
   - 改接口 → `docs/04-API/API.md` + `docs/04-API/openapi.yaml`
   - 改表结构 → `server/database.md` + 新迁移脚本
   - 改部署/环境 → `docs/06-部署/` 或 `docs/05-配置/`
   - 新增约定/踩坑 → `docs/03-开发指南/` 对应文件
   - 发布版本 → `CHANGELOG.md`
5. **体积红线**：根目录 `README.md` ≤ 8 KB；`00-导航.md` ≤ 10 KB；单份指南 ≤ 15 KB。超了就拆文件或降级为索引。

---

## 7. 归档规则

- 带日期的时点性报告（评估、审计、调研、测试报告）→ 移入 `docs/archive/`，**原文不动**，在 `00-导航.md` 留一行索引。
- 归档 ≠ 删除：任何「当初为什么这么做」都必须能在 `archive/` 里 grep 到。
- 已落地的设计方案（如记忆系统设计）同样进 `archive/`，并在文件头注明「已落地，现状见 XXX」。
