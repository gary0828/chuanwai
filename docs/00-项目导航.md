# 项目导航（唯一入口）

> 这是整个项目的 **Map of Content**。所有文档从这里进入。
> **找不到答案时先回这里，不要新建文档。**

---

## 一、三条铁律（防止文档腐化）

1. **单一事实源**：同一件事只在一处定义。要引用就**双链** `[[文件名]]`，**绝不复制粘贴**。复制 = 双份 = 必然过期。
2. **会变的 与 不变的 分开**：计划、进度会变，可以改；**决策理由不变，只追加**。
3. **不知道写哪就问**：宁可先记在 `.workbuddy/memory/YYYY-MM-DD.md` 日志里，也不要顺手新建一份"XX说明.md"。

## 二、权威范围表（你想知道什么 → 查哪里）

| 你想知道… | **唯一权威** | 不要去查 |
| --- | --- | --- |
| 系统能做什么（对外说明） | [[README]] | PROGRESS / ROADMAP |
| 现在做到哪了（已完成的） | [[PROGRESS]]（位于 docs/） | ROADMAP |
| 接下来做什么（待做的计划） | [[ROADMAP]]（位于 docs/） | PROGRESS |
| **为什么这么定（决策理由）** | `docs/decisions/` | ROADMAP（只有结论，没有理由） |
| 数据库长什么样 | `server/database.md` | 迁移脚本（只看增量变更） |
| 接口怎么调 | `docs/api.md` | 后端源码 |
| 接口的机器可读定义 | `docs/openapi.yaml` | — |
| 开发时的硬规则 / 红线 | [[WORKBUDDY]]（项目根目录） | — |
| 代码在哪（目录结构与定位索引） | docs/项目地图.md | 全项目扫描 |
| 本机环境坑 / 开发踩坑 | [[WORKBUDDY]] §八 | PROGRESS（已去重，2026-09-12） |
| 这次会话干了什么 | `.workbuddy/memory/YYYY-MM-DD.md` | — |
| 项目长期不变的事实 | `.workbuddy/memory/MEMORY.md` | — |

> **最常见的错误**：在 PROGRESS 里写计划、在 ROADMAP 里写进度。这两份文件一旦混淆，进度就永远对不上。

## 六、用 Obsidian 打开本项目（可选，但强烈推荐）

**做法**：Obsidian →「打开本地仓库」→ 选本项目根目录。**不要复制文件到别的 vault**——复制就是双份，必然过期。

**必配（不做会卡死）**：设置 → 文件与链接 →「已忽略的文件」，加上这些：

```
node_modules/
server/node_modules/
dist/
evidence/
_verify_test/
.git/
server/data/
pnpm-lock.yaml
package-lock.json
```
> 本机 AI 工具另有 `.aiignore` / `.cursorignore` / `.copilotignore` / `.ignore` 四份同内容规则（见 WORKBUDDY.md §十）

> 不配的话 Obsidian 会扫描 `node_modules/` 的几十万个文件：启动卡死、关系图谱被依赖包污染成蜘蛛网。

**建议插件（只推真正必要的，别一上来装一堆）**：
- `Dataview`（可选）：把本导航页的 ADR 表格变成自动生成的动态索引
- 核心插件「模板」：给 ADR 建个模板，避免格式漂移

**建议设置**：设置 → 编辑器 →「严格换行」**关掉**（中文写作友好）。

**注意**：`.obsidian/` 是工作区配置，不要提交进 git（加到 `.gitignore`）。
