# Dify 上手指南

> 编写日期：2026-09-14 ｜ 本机 Dify 实测状态见 §一
> 目标读者：想用 Dify 自己搭一个给老师用的 AI 助手的人

---

## 1. 先搞清楚：现在到底需不需要 Dify

### 当前本机状态（实测）

| 项 | 状态 |
| --- | --- |
| 容器数 | **15 个**（postgres / redis / weaviate / api / worker / web / nginx / sandbox / plugin_daemon …） |
| 内存占用 | **约 2.5 GB**（`api` 434 MB + `worker` 427 MB + `worker_beat` 424 MB + `api_websocket` 420 MB 是大头） |
| 初始化 | ✅ `{"step":"finished"}`，管理员账号已建（2026-09-14 06:00） |
| 模型供应商 | ❌ **一个都没配** —— 现在打开 Dify 建任何应用都跑不起来 |
| 应用数 | 0 |

### 什么时候需要它

| 你想做的事 | 用现有 AI 工作台 | 用 Dify |
| --- | --- | --- |
| 备课方案、教案、授课流程 | ✅ 已有，9 个场景已可用 | 可以，但没必要 |
| 学情分析与家长反馈文案 | ✅ 已有 | 可以，但没必要 |
| **上传教材/教案，让老师提问「这份讲义里第几单元讲了什么」** | ❌ 不支持 | ✅ **这才是 Dify 的主场** |
| **多步推理：先查知识点 → 再找错题 → 再生成专项练习** | ❌ | ✅ 工作流能力 |
| 老师自由对话式提问（不限定场景） | ❌ | ✅ 聊天助手 |
| 老师自己改提示词、调 Agent | ❌ | ✅ 可视化编排 |

**结论**：教学流程类需求已被 AI 工作台覆盖，**Dify 的价值在「知识库 + 自由编排」**。等到你要让老师查自己的教材资料、或者想随手改提示词时再开机，不必现在就让它常驻 2.5 GB 内存。

### 不用的话怎么关

```bash
# 停止并释放资源（数据不会丢，下次还能启回来）
docker compose -f dify/docker/docker-compose.yaml stop
```

## 2. 第一步：配模型供应商（**不做这步，一切都免谈**）

1. 浏览器打开 **<http://localhost:8081>**，用初始化时建的管理员账号登录
2. 右上角头像 → **设置** → **模型供应商**
3. 找到 **DeepSeek**（没有的话在「添加模型供应商」里搜），填：

   | 字段 | 值 |
   | --- | --- |
   | API Key | `sk-xxxxxxxx`（**与教务系统 `.env` 里的 `LLM_API_KEY` 可用同一个**） |
   | 模型 | `deepseek-chat`（Dify 侧名称，会映射到当前可用模型） |

4. 右上角头像 → **设置** → **模型供应商**里确认出现绿色可用标记

> ⚠️ **DeepSeek 的模型名陷阱**：旧别名 `deepseek-chat` / `deepseek-reasoner` 已于 **2026-07-24 停用**，当前真实可用的是 `deepseek-flash` / `deepseek-v4-pro`。
> DeepSeek 对未知模型名**仍返回 200** 而不是报错，所以配错了一开始不会报错，要到生成时才出怪问题。若报错请改用 `deepseek-flash`。

## 3. 第二步：建第一个给老师用的 Agent

推荐从**最简单的聊天助手**起步，别一上来就搞工作流。

### 路径

**工作室（Studio）** → **创建空白应用** → 选类型 → 填名称/图标 → 创建

### 三种类型怎么选

| 类型 | 适合 | 教师场景举例 |
| --- | --- | --- |
| **聊天助手** | 多轮对话、有记忆 | 「学困生转化助手」：老师描述学员情况，反复追问沟通话术 |
| **文本生成**（完成） | 一次给料一次出结果 | 「家长会发言稿生成器」：填班级+学员情况 → 出稿 |
| **Agent**（对话流） | 需要调用工具、多步 | 「单元复习规划师」：自动查知识点库再排计划 |
| **工作流** | 固定流程编排、可发布为工具 | 「错题归因流水线」：错题 → 归知识点 → 出同类题 |

### 一个可直接抄的例子：备课小助手（聊天助手）

**提示词**（复制到编排页）：

```
你是资深学科教研员，帮培训机构教师备课。

约束：
1. 只使用教师在对话中提供的信息，没有的信息明确说"未提供"，不得编造；
2. 输出用中文，直接给可执行的内容，不要写"我作为一个AI"这类客套话；
3. 涉及学员姓名时一律用"学员A/学员B"代替，不输出任何真实姓名、电话、金额；
4. 每次输出包含：① 本节目标 ② 重难点的突破设计 ③ 课堂时间轴（分钟级）
   ④ 一个能引出认知冲突的提问 ⑤ 分层作业建议。

格式用 Markdown，控制在 600 字以内。
```

**模型选择**：DeepSeek `deepseek-chat`（注意局部变量 `temperature` 调 0.7 左右更适合创意类文案，0.2 更适合结构化输出）。

**下一步**
右上角 **调试/预览** 里先试几轮 → 满意后点 **发布** → 得到 **WebApp 链接**。

## 4. 第三步：怎么给老师们使用

### 三种方式（推荐中间那条）

| 方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| ① **WebApp 链接**（推荐先试用） | 应用发布后点「访问网站」，把 URL 发给老师 | 零开发、老师会点链接就会用 | 界面是 Dify 的，与教务系统不统一 |
| ② **嵌入教务系统**（推荐正式用） | 发布 → 「嵌入网站」→ 复制 iframe 代码，加到教务系统某个 Vue 页面里 | 老师无感知切换 | 需要我改前端代码 + 处理登录态传递 |
| ③ **开放 API** | 应用 → 「访问 API」→ 拿 API Key 自己调用 | 可完全自定义界面 | 要写后端代理，不能把 Key 放浏览器 |

### ⚠️ 安全红线（必须先看）

1. **任何 Dify API Key 都不能写在网页/前端里** —— 工作台现有的「Dify 工作流」模式是把 Key 存在浏览器 localStorage 的，**仅限于你自己在内网调试**，不要用它给老师使用。正式用必须走方式 ③，由教务后端代持 Key（与 DeepSeek 的接法一致）。
2. **不要把 8081 端口暴露到公网**（不要做内网穿透、不要映射路由器端口）。Dify 的 WebApp 链接默认无鉴权，任何人拿到都能用，会产生你的 token 费用。
3. **提示词里写死脱敏约束**（像上面示例那样），并告诉老师不要粘贴真实家长电话 / 金额。

## 5. 第四步（真正值钱的一步）：挂知识库

这是 Dify 相对现有工作台的**唯一不可替代能力**。

1. 顶部 **知识库** → **创建知识库** → 选择来源「上传文件」
2. 拖入：教材 PDF、往期教案、错题集合、校本讲义
3. **分段设置**（关键，直接影响检索质量）：

   | 参数 | 建议值 |
   | --- | --- |
   | 分段方式 | **自动分段清洗** |
   | 最大分段长度 | **500–800 tokens**（讲义类）；题目类用 200 |
   | 检索方式 | **混合检索（向量 + 全文）** ← 中文效果明显好于纯向量 |
   | Top-K | 3–5 |
   | Score 阈值 | 0.5 |

4. 处理完成后，回到你的应用 → 编排页 → **上下文** 里勾选这个知识库
5. 调试时打开「引用溯源」，确认它真的引用了你的文档而不是自己在编

> **中文检索质量**很大程度取决于分段而非模型。文档加载后先自己问 5 个问题，回答不对就调分段重试，别急着加大模型参数。

## 6. 成本与资源

| 项 | 数值（2026-09-14 实测/官方报价） |
| --- | --- |
| Dify 自身内存 | 约 **2.5 GB**（15 容器） |
| DeepSeek `deepseek-flash` | 输入 ¥1/百万 token（缓存未命中），输出 ¥9/百万 |
| 单次教师提问实际成本 | 约 **¥0.005–0.02** |
| 50 名教师每人每天 10 次 | 约 **¥30/月** 量级（视提示词长度） |

建议给 Dify 应用设置**额度上限**：Dify 右上角头像 → 账单/用量，或直接在 DeepSeek 后台设月度限额，防止提示词循环把额度打爆。

## 7. 我建议你现在就这样安排

1. **明天部署校区时：不要启动 Dify**（省 2.5 GB 内存，少 15 个容器故障面）。AI 需求用教务系统自带的 AI 工作台 + 服务端 DeepSeek，已经够用。
2. **试运行两周后**，如果老师反馈「想要能问自己教案资料的地方」，再回来启动 Dify：
   ```bash
   docker compose -f dify/docker/docker-compose.yaml up -d
   ```
3. 然后按本文二→三→五的顺序做：**配模型 → 建聊天助手 → 挂知识库**。
4. 给老师用的渠道**先用 WebApp 链接小范围试用**，确认好用后让我把它嵌进教务系统（我会在后端代持 Key，不暴露给浏览器）。
