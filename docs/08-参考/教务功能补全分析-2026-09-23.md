## 0. 先明确一件事：「商用」指什么

「商用」有两种含义，会导出完全不同的架构，必须先分清：

| 含义 | 内容 | 成本 | 结论 |
|---|---|---|---|
| **A. 对外售卖（SaaS）** | 多租户、租户隔离、计费订阅、跨租户运维 | **架构级**（推翻 ADR-001，DB 层要加租户维度） | ❌ **不做** |
| **B. 商用品质 + 独立部署交付** | 一套系统交付给**一个机构**独立部署；功能完整度、配置化程度、交付物（报表/PDF/打印）、合规基线达到商用标准 | **功能级**（现有「一机构一套 Docker」形态天然支持） | ✅ **已确认采用** |

> ★ **✅ 用户 2026-09-23 拍板：采用 B。**
> 走 B **不需要动架构**（现有单机 Docker + 单端口统一入口已经就是"一机构一套"），
> 只需把**功能完整度与配置化**补齐；走 A 则要重做数据层（本文件不按 A 展开）。

**走 B 意味着三件事**：
1. **功能完整度**按商用标准做（不能出现"这个功能只对我这家机构有"）
2. **配置化**成为硬指标（机构名/Logo/学科/年级/班型/评价量表/考勤课消规则/打印模板 都可配，不写死在代码里）
3. **交付物**要达到"能拿出去给家长/校长看"的水准（成绩单、结课报告、作业报告、PDF + 打印）

## 1. 定位升级带来的 6 项决策重新裁决

> 这是 v2 最需要你拍板的一节。**每一条都给出建议值 + 理由**，你可以逐条改。

| # | 决策 | 原结论 | **v2 建议** | 理由 |
|---|---|---|---|---|
| D1 | 多校区 / 多租户 | 不做（ADR-001） | ✅ **已拍板：仍不做多租户**；但必须做到「**换一家机构只改配置，不改代码**」（机构信息、Logo、学科、年级、班型、评价量表、规则矩阵、打印模板全部可配） | 商用的真正门槛不是多租户，而是**配置化**。硬编码是目前最大的商用障碍 |
| D2 | 家长端 / 出网触达 | 不做（ADR-002） | ✅ **已拍板：仍不做在线家长端**；改为**把"对外交付物"做扎实**：成绩单 / 结课报告 / 作业报告 / 学员卡 的 **PDF + 打印**（含机构 Logo 与确认签章位） | 用"纸质/PDF 交付"替代"在线家长端"，**规避出网与账号体系这两块最贵的成本**，同时拿到 90% 的实际价值（家长会、面谈、续报说服） |
| D3 | 角色模型 | 2 角色；自定义 RBAC = Non-goal | ✅ **已拍板：维持双角色** —— **管理员级 / 教师级**，**不新增财务、教务等岗位角色**。岗位分工需求改用「二次确认 + 审计留痕 +（可选）能力开关」承接（见 §4.9） | 用户裁决：机构内除教师外统一归"管理员级"。对 5–15 人机构，**角色少 = 配置简单、人员流动时不用调整角色**；自定义 RBAC 仍是成本黑洞 |
| D4 | 作业 | Non-goal | ✅ **已拍板：改为必做** —— 定位为「**作业数据展示平台**」，不做题库/在线作答/自动批改 | 用户明确要求。详见 **§5 专章** |
| D5 | 财务边界 | 只做学员账户（ADR-003） | ✅ **已拍板：补「优惠 / 赠课 / 课时有效期 / 冻结」**；仍不做发票、线上支付、总账、提成绩效 | 商用的售卖方式离不开折扣与赠课，且它们**直接影响收入口径与退费计算**，绕不过去。⚠️ **ADR-003 被部分修订**，口径字典须同步 |
| D6 | 主数据 | 无学科/年级主数据（`courses.grade` 是文本、无学科表） | ✅ **已拍板：补「学科」与「年级」主数据**（可先用字典表，不必立刻上树） | 商用要覆盖不同学科的机构；也是报表与作业看板的必备维度 |

> ⚠️ **D1 / D3 是"重申维持"**（多租户仍不做、双角色不变），**不是扩展**；
> **D2 / D5 / D6 是实质性扩展**，会进 ADR 修订。
> ✅ **D1–D6 六项已全部拍板**（2026-09-23）。落地见 4 份 ADR：**ADR-009**（课次实体与课消归属）·
> **ADR-010**（学员生命周期状态机）· **ADR-011**（数据修正留痕）· **ADR-012**（商用化定位与边界修订）；
> 候选与打分见 `ROADMAP.md` **§5.2（G 系列）**。**D3 / D4 已在 v2.1 拍板，D1 / D2 / D5 / D6 于 v2.2 拍板。**

## 2. ★ 呈现方式：什么功能用什么形态最好

> 这是 v2 新增的核心维度。**同一个功能，呈现方式选错，做出来就是"功能有但没人用"**。
> 本节给出原则 → 映射 → 反面清单，下文每张功能表都带「呈现方式」列。

### 2.1 六条呈现原则

| # | 原则 | 说明 |
|---|---|---|
| 1 | **一个数据，一个家** | 同一指标只有一个**主视图**；其他位置只做"摘要 + 跳转"，不重复维护（重复 = 双份口径 = 必然打架） |
| 2 | **看趋势用图 · 看个体用表 · 看时间用历 · 看关系用树 · 看流程用向导 · 看异常用列表** | 一句话选型口诀 |
| 3 | **默认视角 = 使用者的第一个问题** | 校长第一问是"哪里出问题了"，老师第一问是"我今天要做什么"，教务第一问是"有什么待办"。**工作台必须按角色分化** |
| 4 | **能标异常，就不打分** | 沿用 ADR-005（课评只标异常）。**录入成本是数据能否持续的唯一变量**——老师不填，再漂亮的分析都是零 |
| 5 | **批量录入必须用矩阵网格** | 行 = 学员，列 = 项目，顶部一个"全班默认良好/已交"，老师只点异常。**禁止逐个弹窗** |
| 6 | **可导出即可交付** | 任何对外交付物必须有 PDF/打印形态（替代家长端的核心手段） |

### 2.2 功能性质 → 最佳呈现（决策表）

| 功能性质 | **最佳呈现** | 典型功能 | 常见错误做法 |
|---|---|---|---|
| 事务型档案（增删改查） | **列表 + 抽屉详情** | 学员/员工/课程/线索 | 只剩表格，详情另开整页再返回 |
| 状态流转型 | **待办列表 + 状态标签 + 时间线** | 请假/调课/退费/补签审批 | 画复杂流程图 |
| **时间占用型** | **周历（时间网格）+ 冲突高亮** | 排课/教室/教师课表/停课日历 | ❌ 做成表格列表（最常犯） |
| 层级型 | **树 + 面包屑** | 课程体系/知识点/组织/菜单 | 做成扁平下拉 |
| 指标监控型 | **看板卡 + 趋势图 + 下钻** | 经营/考勤/作业/续报总览 | 做成大宽表 |
| 对比型（横向比） | **分组柱状 + 排名列表** | 班级/教师/学科横比 | ❌ 用饼图（>5 类不可用饼图） |
| 转化型 | **漏斗图 + 环节转化率** | 招生漏斗、续报漏斗 | 做成表格 |
| 分布型 | **直方图 / 箱线 + 分位数** | 成绩分布、课时分布 | 只给一个平均值 |
| **批量录入型** | **矩阵网格 + 一键默认值** | 点名/成绩录入/课评/作业登记 | ❌ 逐个弹窗（老师会放弃） |
| 多步业务变更 | **向导（≤3 步）+ 结果预览** | 报班/插班/转班/升班/结课 | 做成一张大表单 |
| 规则配置型 | **矩阵表格**（行=状态，列=规则） | 考勤×课消规则、评价量表 | ❌ 埋进代码常量 |
| 对外交付型 | **PDF + 打印模板**（含 Logo、签章位） | 成绩单/结课报告/作业报告/学员卡 | 只做页面截图 |
| 提醒型 | **铃铛 + 待办中心** | 各类预警（不出网） | ❌ 做成邮件/短信 |
| 关系型 | **关系图 / 桑基图** | 课程进阶路径、线索转化链路 | 做成列表 |

### 2.3 本项目已犯 / 易犯的反面清单

| # | 反面案例 | 正确做法 |
|---|---|---|
| 1 | 把**排课**呈现为列表 → `schedules` 现在只有表格式管理 | 上**周历视图**（班级/教师/教室三视角切换）+ 冲突红标 —— 这是 A1「三维课表」的由来 |
| 2 | 把**批量录入**做成逐个弹窗 | 点名、成绩、课评、作业登记统一上**矩阵网格** |
| 3 | 用**饼图**表达班级/学科分布（类别常 >5） | 换分组柱状或排名列表 |
| 4 | 把**交付物**做成页面截图 | 做 PDF 模板（这正是 D2 替代家长端的抓手） |
| 5 | 把**规则**写进代码（如"请假是否扣课时"） | 抽成**配置矩阵**（A6） |

## 4. 扩展功能总表（**决策版** —— 这就是"我们要做什么"）

> 阅读方式：**呈现方式**列是本 v2 的核心增量。P0–P3 定义见 §7。
> 每行都经过 v1 的"作用 / 必要性"论证（v1 详见本文件历史版本与 `PRD借鉴分析-2026-09-23.md`）。

### 4.0 工作台（跨模块首页）

| 功能点 | 作用 | 呈现方式 | 优先级 |
|---|---|---|---|

| 教师时间可用性（兼职老师） | 排课不排到不可用时段 | 周历可用性网格（灰=不可用） | **P3** |
| 整学期批量排课 | 每学期省数小时 | **向导**（选模板 → 预览 → 生成） | **P3** |

### 4.3 报班与班务变更（原"选课"的培训语境等价物）

## 5. ★ 作业模块专章：做一个「作业数据展示平台」

### 5.1 定位：为什么教务系统必须有作业，但**不做批改**

| 角色 | 职责归属 | 理由 |
|---|---|---|
| **AI 工作台** | 作业的**创作面 + 批改面**（作业设计、批改、评价、家长反馈文案） | 这是 AI 的强项，也是你说的未来重点 |
| **教务系统（本模块）** | 作业的**数据面**（布置了什么、谁交了、完成得怎么样、趋势如何） | 校长/教务/班主任**必须能看见作业情况**，这跟 AI 无关；而且**数据面是 AI 面的事实依据**（AI 分析的输入来自这里） |

> **一句话**：教务系统管"作业发生了什么"，AI 工作台管"作业怎么教得更好"。
> 这与 ADR-008「系统是唯一数据源、AI 是加工厂」完全一致。

### 5.2 ★ 关键问题：数据从哪来（这是本模块成败的唯一变量）

**不能靠"新增一个表单让老师填"** —— 会立刻烂尾（这正是 `ROADMAP.md` R1 风险）。
三条来源，按优先级：

| # | 来源 | 说明 | 地位 |
|---|---|---|---|
| 1 | **教师/班主任在教务端快速登记** | 课后 30 秒，**批量矩阵 + 只标异常**（与课评 ADR-005 同一哲学，见 §5.4） | **主数据源** |
| 2 | **AI 工作台作业模块回写** | 未来工作台做完批改，把状态回写到教务系统（单向：工作台 → 教务） | 增量源（未来） |
| 3 | ❌ 家长/学生端提交 | 不出网、无账号（ADR-002） | 不做 |

> ★ 来源 1 的设计哲学直接复用本项目**已被验证**的两条经验：
> **① 只标异常**（ADR-005 课评：全班默认良好，老师只点异常）；
> **② 嵌入既有流程**（提交点名后顺手登记作业，不新开一个"去填作业"的入口）。

### 5.3 数据模型（概念层）

> 挂到 **课次（A1）** 上 —— 这是作业与"哪节课布置的"建立精确关联的前提。

**`assignments`（作业）**

| 字段 | 说明 |
|---|---|
| `assignment_id` | 唯一 ID |
| `session_id` | **关联课次**（A1）—— 有了它才能算"应布置课次/布置率" |
| `class_id` / `course_id` / `subject` | 班级 / 课程 / 学科（学科见 D6 主数据） |
| `title` / `type` | 作业标题 / 类型（课后练习·预习·背诵·试卷·作品·其他） |
| `assigned_at` / `due_at` | 布置时间 / 截止时间 |
| `est_minutes` | 预计用时（用于**作业量监控**） |
| `is_required` | 必做 / 选做 |
| `created_by` | 布置人 |

**`assignment_submissions`（每生一条）**

| 字段 | 说明 |
|---|---|
| `student_id` | 学员 |
| `status` | **未布置 / 待提交 / 已提交 / 缺交 / 免做** |
| `submitted_at` | 提交时间（用于算"按时率"） |
| `is_late` | 是否迟交 |
| `quality` | **优 / 良 / 合格 / 待改进**（四档，不打分 —— 老师打不出"62 分"这种精度） |
| `graded_by` / `graded_at` | 批改人（教务端批改可留空，由 AI 工作台回写） |
| `remark` | 备注（可选） |

> ⚠️ **只增不改**：一旦登记，修改要走 **A3 数据修正留痕**（原值—新值—原因—操作者—时间）。
> 作业完成率会进入经营/教学看板，不能无痕改。

### 5.4 ★ 录入设计：30 秒完成一个班的登记

| 步骤 | 界面 | 说明 |
|---|---|---|
| 1 | 从「今日课表」点该节课 → 进入**作业登记** | **不新开入口**，嵌入点名后的既有流程 |
| 2 | 填 3 个字段：作业标题 / 类型 / 截止时间（可复用上次） | 其余默认 |
| 3 | **矩阵网格**：全班默认「已提交 · 合格」 | 一屏一班的点按 |
| 4 | 只点异常：未交的、迟交的、质量待改进的 | **正常情况下 80% 的班无需任何点击** |
| 5 | 提交 | 落 `assignments` + `assignment_submissions` |

> **设计铁律**：**默认值必须是"通常情况"**。若默认"未提交"，老师要点全班 → 必然放弃。
> 这与课评「全班默认良好」是同一决策（ADR-005），**请勿在实现时改掉**。

### 5.5 呈现方式：三层看板

**① 校级总览（校长 / 管理员级）**

| 指标 | 口径 | 呈现 |
|---|---|---|
| 作业布置率 | 已布置作业的课次 ÷ 应布置课次 | 指标卡 + 趋势线 |
| 提交率 | 已提交人次 ÷ 应交人次 | 指标卡 + 趋势线 |
| 按时提交率 | 按时提交 ÷ 应交 | 指标卡 |
| 缺交率 | 缺交人次 ÷ 应交 | 指标卡 + **连续缺交学员名单** |
| 批改覆盖率 | 已批改 ÷ 已提交（**教师侧考核项**） | 指标卡 + 教师横比 |
| 学科 / 年级分布 | 作业量与完成率按学科/年级 | **分组柱状 + 排名列表** |
| 作业量异常 | 某科/某班作业时长异常偏高 | 分布图 + 异常标注 |

**② 班级看板（班主任）** — 班级视角的上述指标 + **未交名单（一键转待办）** + 与平行班的横比。

**③ 个人视图（学员 360 的「作业」页签）** — 该学员的作业时间线、缺交记录、质量趋势。

**④ 对外交付**：作业报告 **PDF**（班级版 / 个人版），用于家长会与面谈（D2 的交付物之一）。

### 5.6 与既有能力的接线

| 接线点 | 做法 |
|---|---|
| 课次（A1） | `assignments.session_id` → 支撑"布置率"与课次详情内展示 |
| 成长时间轴（v18 `student_timeline`） | 新增事件类型 `assignment`（**注意：event_type 是后端白名单，需同步扩展**） |
| 待办自动生成（L3） | 新增 `assignment_missing`（连续欠交 → 班主任待办），与既有 `eval_missing` 同类 |
| 学员 360 | 新增「作业」页签 |
| 成长阈值（v18 `growth_thresholds`） | 新增阈值键（如"连续欠交 N 次预警"），**不硬编码** |
| 报表中心 | 归入「教学」域 |

### 5.7 本模块**明确不做**（边界）

| 不做 | 归属 |
|---|---|
| 题库 / 组卷 / 在线作答 / 自动阅卷 / 错题本 | ❌ 不做（`ROADMAP.md` Non-goals；且 AI 工作台定位为创作面） |
| 作业的完整批改与逐题反馈 | → **AI 工作台**（教务端只登记结果档位） |
| 家长/学生在线提交作业 | ❌ 不出网（ADR-002） |
| 作业的 AI 评价与个性化建议 | → **AI 工作台** |

> **交付判据（DoD）**：校长打开作业看板，**3 秒内**能回答"这个月全校作业提交率多少、哪个班最差、哪个老师最少批改"。

## 6. 商用就绪度检查表

> 用于判断"离一个可交付的商用产品还差什么"。这一节是 v2 新增，**直接回答"商用"二字**。

| # | 商用能力 | 现状 | 缺口 |
|---|---|---|---|
| 1 | **配置化**（机构信息/Logo/学科/年级/班型/评价量表/规则矩阵/打印模板） | 部分（站点信息、Logo 有；其余写死） | ★ **最大缺口** |
| 2 | **数据字典与口径字典** | ❌ 无 | S4 |
| 3 | 操作留痕与**修正留痕** | 部分（有 `audit_logs`，无字段级与修正链） | A3 |
| 4 | 报表与导出 | 部分（12 指标 + 分模块） | 经营漏斗、七域报表 |
| 5 | **打印 / PDF 交付物** | ❌ 基本没有 | D2 的核心抓手 |
| 6 | 多岗位角色 | ✅ **已拍板不做**（双角色：管理员级 / 教师级） | 无缺口 —— 岗位分工由「二次确认 + 导出审计 + 修改留痕 +（可选）能力开关」承接 |
| 7 | 新手引导 / 操作卡 | 部分（Phase 0.6 一页纸） | 产品内引导 |
| 8 | 备份与恢复 | ✅ 有（补自动化与演练） | P1 |
| 9 | 审计日志 | ✅ 有 | 导出审计 |
| 10 | 权限矩阵文档 | 部分（`权限模型.md` 有骨架） | 完整矩阵表 |
| 11 | 数据迁移（导入导出全套） | 部分（仅学员有导入） | 批量导入矩阵 |
| 12 | 版本与升级（CHANGELOG / 迁移脚本） | ✅ 有 | — |
| 13 | **隐私与合规基线**（未成年人） | ❌ 无 | 借鉴 PRD §13 |
| 14 | 性能与并发 | ✅ 200–500 学员规模足够 | — |

> ★ 结论：**"商用"的真正门槛是第 1、2、5、13 项**（配置化 / 口径字典 / 交付物 / 合规），
> 而不是功能数量。功能我们已经有了 55%，缺的是"**能让另一个机构拿去用**"的那一层。

## 7. 分期路线（P0–P3）

### P0 · 地基与数据可信（**建议先做**，约 12–16 人日）

| # | 事项 | 模块 | 为什么是 P0 |
|---|---|---|---|
| P0-1 | **指标口径字典（S4）** | 10 | 成本最低、收益最高；一切报表的前提 |
| P0-2 | **课次实体（S1）+ 课消挂课次（A7）** | 2 | 教室/代课/停课/进度/作业登记的共同载体 —— **合并做，避免返工** |
| P0-3 | **任课关系表 + 归属过滤扩展（S2）** | 5/9 | 当前任课老师看不到自己的班 = 功能级故障 |
| P0-4 | **学员生命周期状态机（S3）** | 1 | 与 P0-1 同批，避免二次返工 |
| P0-5 | **成绩修改留痕 + 缺考区分（A3）** | 4 | 对外可信度最高的数据 |
| P0-6 | **危险操作二次确认 + 审批** | 9 | 不可逆操作（退费/删除/导入/改成绩）；**双角色下它是岗位隔离的主要替代手段（D3）** |
| P0-7 | **学员 360 页签骨架** | 1 | 后续所有学员数据的"家" |

### P1 · 教务闭环补全 + 作业上线（约 25–32 人日）

- **班务类**：插班折算 · 转班调班 · 班级容量 · 报班冲突 · **优惠/赠课/有效期（D5）**
- **排课类**：三维课表（周历）
- **教学类**：班级成绩分析 · 考试类型扩展 · 教师工作量 · 教师请假联动
- **考勤类**：考勤×课消规则矩阵 · 补签审批
- **结课类**：结课评定 · **续报提醒与续报率**
- **★ 作业类**：作业登记（矩阵）· 作业总览看板
- **管理与交付**：导出审计 · 密码策略 · 权限矩阵文档 · 能力开关（可选）· **备份自动化** · **批量导入矩阵** · 导入健壮性 · **隐私合规基线**
- **呈现层**：角色化工作台 · 今日课表 · 异常提醒 · 校长概览

### P2 · 作业深化 + 交付物 + 经营分析（约 28–36 人日）

- **作业**：班级作业看板 · 作业报告 PDF · 连续欠交预警
- **交付物**：打印模板中心 · **成绩单** · **结课报告/证书** · 作业报告
- **排课治理**：教室与三重冲突 · 代课 · 停课日历 · 教学大纲与进度
- **学籍**：异动台账 · 多监护人 · 附件 · 重复检测 · 标签
- **课程**：体系分层 · 进阶路径
- **成绩**：多元考核 · 知识点掌握矩阵
- **经营**：经营漏斗一页 · 报表七域 · 目标与达成率 · 同比环比 · 看板角色差异化 · 数据质量看板
- **系统**：统一导出中心 · 字段级变更历史 · 财务对账导入 · 回收站/软删除 · 消息中心 · 公告签收
- **移动**：手机快速点名

### P3 · 商用打磨与长尾（约 20–28 人日）

候补名单 · 整学期批量排课 · 教师资质矩阵 · 教师时间可用性 · 课时规则配置（冻结/赠送细则）· 补考重考 · 听课评课 · 教师培训档案 · 教师考勤 · 教案沉淀 · 考勤异常批处理 · 档案完整度 · 作业量分布监控 · 自定义报表 · 定时导出 · 学习周期统计 · 结业归档 · 临时授权 · 打印公示版 · **配置化收口**（D1 的配置项全部可配）

## 9. 明确不做（修订版）

> v2 相对 v1 的**唯一变化**：作业从"不做"移到"必做（数据展示型）"。
> 其余**全部维持**，并且因定位升到"商用"而**更需要重申**。

**架构层面**
1. 多租户 / SaaS 化 / 跨机构汇总 / 学员转校（D1：走"一机构一套 + 配置化"）
2. 自定义字段 / 自定义角色 RBAC（D3：**维持双角色**，不新增岗位角色；需要时用"能力开关"）

**家校层面**
3. 家长端 / 学生端 / 家长账号体系与家校绑定（D2：用 PDF + 打印交付替代）
4. 短信 / 微信模板 / App 推送等**任何出网触达**
5. 在线作业提交（家长或学生端）

**教学层面**
6. 题库 / 组卷 / 在线作答 / 自动阅卷 / 错题本
7. 作业的完整批改与 AI 评价（→ AI 工作台）
8. 直播课 / 双师 / 录播
9. 学历教育语义直接移植：学分制 / 绩点 / 毕业审核规则引擎 / 选课轮次与志愿抽签 / 学位授予 / 学籍上报对接

**财务层面**
10. 发票 / 电子发票 / 线上支付 / 日结总账 / 会计凭证
11. 员工提成 / 课时工资 / 绩效工资（**注**：教师"课时数统计"是教学管理数据，做；"按课时算钱"不做）

**其他**
12. 考勤硬件（刷卡机 / 人脸机 / 大屏）· 移动端 App / 小程序 · 进销存 · 加盟商管理
13. 为"以后可能出网"预留的触达适配层（典型过度设计）
