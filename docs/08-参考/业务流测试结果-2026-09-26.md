## 二、用户反馈的问题：完全复现 ✅

**现象**：点「导入」选完文件后，**没有任何反应**。

**Playwright 实测证据**（修复前）：

| 场景 | 发出请求 | 消息条 | 弹窗 |
|---|---|---|---|
| 含 1 行错误班级的文件 | **0** | **无** | **无** |
| **全部正确的文件** | **0** | **无** | **无** |
| 同一文件再试第 2 次 | **0** | **无** | **无** |
| 同一文件再试第 3 次 | **0** | **无** | **无** |

→ 连**完全正确的文件**都毫无反应，与用户描述完全一致。

## 三、根因（P0）

**代码位置**：`src/views/attendance/students/index.vue` 的 `handleImport`

```ts
// ❌ 修复前
function handleImport(file: any) {
  ...
  reader.readAsArrayBuffer(file.raw);   // file.raw === undefined
  return false;
}
```

**为什么错**：`el-upload` 的 `before-upload` 钩子传入的是 **`UploadRawFile`**，
而 Element Plus 的类型定义是：

```ts
export interface UploadRawFile extends File { uid: number }   // ← 没有 raw 字段
beforeUpload: (rawFile: UploadRawFile) => ...
```

`raw` 字段**只存在于 `change` 事件的 `UploadFile`**（`UploadFile.raw?: UploadRawFile`）上。
所以 `file.raw` 是 `undefined`。

**为什么"没有任何反应"**（三个条件叠加，缺一不可）：

1. `FileReader.readAsArrayBuffer(undefined)` **同步抛 TypeError**
2. 而 `try/catch` **只包住了 `reader.onload` 回调的内部** —— 抛错发生在回调**之外**，无人接管
3. 该异常沿着 Element Plus 的事件处理向上抛，**没有任何 ElMessage**
   （全局响应拦截器只兜底 **HTTP 错误**，这里请求根本没发出去）

→ **无请求、无提示、无弹窗** = 用户看到的"点了没反应"。

**为什么之前"功能测试通过"却漏了**：
既有测试（如 `e2e-lifecycle.mjs`）直接 `POST /api/students/import` —— **接口本身是好的**，
但跳过了"用户选文件"这一步，而缺陷恰好就在这一步。
**这正是"功能可用 ≠ 使用时没问题"的典型样本。**

## 九、经验教训（写进记忆）

1. **`before-upload` 的参数是 `UploadRawFile`（无 `raw`）**；`raw` 只在 `change` 的 `UploadFile` 上。
   → 用 `any` 标注参数会**关掉类型检查**，正是这个 `file: any` 让错误逃过了编译期。
2. **`try/catch` 的位置很关键**：包住了异步回调内部 ≠ 包住了外层同步调用。
3. **"功能测试通过"可能只覆盖了 API 层**。凡是"用户要点/要选/要传"的环节，
   **必须走真实 UI 操作**才算测过（本次缺陷 100% 在 UI 步骤上）。
4. **判据口诀**：任何一次用户操作都必须有明确反馈（成功/失败/处理中）——**静默即缺陷**。
