# 参考系统插件源码分析（book-structuring-webext 0.0.30）

>分析对象：`book-structuring-webext-0.0.30(4)/`，**打包后的浏览器扩展产物**（非源码），553 文件 / 28 MB。
> 用途：作为《智能题库管理系统-完整设计》的补充输入。**不是源码，是压缩后的构建产物。**

---

## 0. 一句话结论

> **它不是题库系统本体，是「教辅录题浏览器扩展」** ——只负责把题目从网页/图片**采集**进来，
> 真正的题库服务在远端（`request-*.js` 里有大量 `/questionWebImport/*` 接口调用）。
> **所以：能借鉴的是「采集与渲染的工程做法」，不是数据模型与业务逻辑。**

`manifest.json` 自述：`"description": "教辅录题与智能取题浏览器扩展"`

## 1. 高价值可复用资产（★ 优先级最高）

### 1.1 HTML 题面 → Word（带公式）整条链路 ★★★

`chunks/html-to-docx-D7xcRdTJ.js`（474 KB）——**最大最有价值的一个文件**。

依赖链（已核实）：

| chunk | 作用 |
| --- | --- |
| `katex-*.js` | 公式渲染 |
| `mhchem-*.js` | **化学方程式支持**（LaTeX `\ce{}`）|
| `katex-display-mode-*.js` | 行内/行间公式模式 |
| `normalizeMathHtml-*.js` | **公式 HTML 归一化**（导出前的关键处理）|

→ **可以直接抄的思路**：我们二期要「导出 Word」，它已经踩完了
「题面 HTML → 公式正确 → Word 里公式不被转成乱码」这条链。

>⚠ **注意**：**不要**直接搬它打包后的代码（474 KB 压缩产物，含 license 与第三方 IP）。
> 正确做法是**照它的处理链路自研**：KaTeX 渲染 → `normalizeMathHtml` 归一化 → `html-docx-js` 生成 Word。

### 1.2 网页题库采集器（21世纪教育网 / 菁优网）★★

| 文件 | 体积 | 用途 |
| --- | --- | --- |
| `21cnjy-extract-*.js` | 9.8 KB | 21 教育网单题页解析 |
| `21cnjy-paper-extract-*.js` | 11 KB | **整张试卷页解析** |
| `jyw-extract-*.js` | 9.6 KB | 菁优网题目解析 |
| `content-scripts/zhixue-paper.js` | — | 智学网试卷页（manifest 里专门配了 `all_frames: true`）|

已核实的中文站URL 规则：

```
zujuan.21cnjy.com/question/detail/<id>     ← 单题
正则：/^\/question\/detail\/[^/?#]+$/
草稿键：localStorage["21cnjy-extract-draft:<id>"]
```

→ **价值**：它证明了「按站点写适配器」这条路可行。
→ **但我方决策**：**不做网页爬虫**。理由：① 站点 HTML 结构会变，适配器维护成本高
② 版权风险（21 教育网/菁优网都是商业题库，爬取入库有明显法律风险）
③ 我们已选定**AI 截图识别**为主路径，更稳定且不绑站点。

**保留参考**：站点适配的**分层思路**（`extract-*.js` 独立成 chunk，一站一文件）。

### 1.3 AI 识别状态机（★ 我设计里缺的一块）★★

从API 端点反推出的状态机设计：

| 端点 | 作用 | 出现次数 |
| --- | --- | --- |
| `...CreateFromRecognition` | 截图识别后入库（**超时 120 秒**）| — |
| `...RetryAiParse` | **识别失败重试** | 3 |
| `...AiFill` | **AI 补全字段**（超时 130 秒）| **47** |
| `...UpdateBatch` | 批量改 | — |

→ **`AiFill` 出现 47 次**说明「AI 补全」是高频动作：
不是一次识别就完事，而是**分阶段**——先识别骨架，再逐块补全。

→ 我原设计只有 `ocr_confidence` 一个字段，**缺「识别状态」字段**。需补：
`parse_status`（pending / recognized / filled / failed / confirmed）。

→ 也印证了我定的**「先返回用户确认，不自动入库」**是对的。

### 1.4 批量能力（一期就要）★★

从 API 清单看到完整的一组批量操作：

```
BatchCreate / BatchDelete / BatchMove / BatchUpdate
草稿自动保存：localStorage 存 imageDataUrl 之外的一切，换行split 逗号split 草稿
```

→ 印证截图里的「**批量删除**」「**选择当前页**」按钮确实存在。
→ **草稿机制值得抄**：题目编辑中未保存的内容存 localStorage，崩溃/关闭不丢（他们还处理了 `QuotaExceededError` → 清理后继续存）。

### 1.5 KaTeX（含字体与完整样式）★

`assets/KaTeX_*.woff2|woff|ttf` 全套字体 + `katex-display-mode-*.css` + `AutoRenderMathContainer-*.css`
→ **实证了数学题用 KaTeX 是对的选择**（与我的技术选型一致）。
→ 字体可作为**离线部署**备选（若担心 CDN 不可达，可自托管字体）。

## 2. 它的题目数据模型（★ 与我的设计有出入，值得吸收）

从 `chunks/question-*.js` 的 API 参数反推，**注意：这是它的远端接口约定，不是我们的库表**。

| 字段 | 类型 | 频次 | 对我的设计的启示 |
| --- | --- | --- | --- |
| `difficultyLevel` | number | 78 | 与我一致（1–5）|
| `year` | number | **103** | ★ **我漏了「年份」维度**（真题年份，机构题库刚需）|
| `customTagIds` | number[] | 37 | ★ 我只有 `source` 单字段，**它有自定义标签体系** |
| `questionTypeId` | number | 多处 | 它用**数字 ID 查表**；我用 TEXT 枚举（我的更可读，可不改）|
| `knowledgePointIds` | **number[]** | 多处 | ★ **数组 = 一题多知识点**，我设计的是单 `kp_id` → 应改 |
| `questionNos` | number[] | 13 | 题号（组卷用）|
| `folderId` / `paperFolderId` | number | — | ★ **文件夹二分**：题目文件夹 / 试卷文件夹分开 |
| `includeSubFolders` | boolean | — | ★ **筛选时含子文件夹**（树形筛选必需，我漏了）|
| `options` | string[] | — | 与我一致 |
| `knowledgePoints` | string[] | — | 表单里是逗号/顿号分隔的文本 ↔ 数组 |

### ★ 我要修正的 4 处设计

| # | 我的 v3 设计 | 应改为 | 理由 |
| --- | --- | --- | --- |
| 1 | `kp_id` 单值 | **`knowledge_point_ids` 多值**（关联表或 JSON） | 一题多知识点是实际需求（截图里 AI 会同时给多个知识点建议）|
| 2 | 无年份维度 | **加 `exam_year`**（真题年份 + `region` 地区）| 机构题库高频筛选维度，源系统 103 处引用 |
| 3 | 只有 `source` | **`source` + `custom_tags`（自定义标签）** | 标签是多维筛选的基础 |
| 4 | 筛选无树形支持 | **筛选支持「含子文件夹」** | 知识点/章节是树形，筛选父节点必须含子树 |

## 3. 明确不参考的部分

| 发现 | 不参考的理由 |
| --- | --- |
| `manifest` 含 `"key": "MIIBIjAN..."`（RSA 公钥）| 是它 Web Store 上架签名用，与我们无关 |
| `host_permissions: ["<all_urls>"]` + `webNavigation` | 我们是自建系统，**永不做浏览器插件**（越权 + 维护成本）|
| `sidepanel.html` / `popup.html` / `standalone.html` | 浏览器扩展 UI 形态 |
| `tree.json`（329 KB GeoGebra 几何画板索引）| ★ **不是知识点树**，是 `.ggb` 几何画板文件索引（数学工具素材），与我们无关 |
| `ggb-preview.html` + `assets/ggb-browser-*.css` | GeoGebra 预览器 |
| `membership-quota-*.js`（会员额度）| 单校区无商业化（ADR-012 不做 SaaS）|
| `use-oss-upload-*.js`（阿里云 OSS 上传）| 我们走自己的 `/assets` 链路（ADR-008）|
| Tiptap 富文本编辑器全家桶 | 一期不做富文本（题干纯文本 + LaTeX）|

## 4. 题型枚举（它的实际取值）

`简答题` 16 次 · `填空题` 8 · `单选题` 6 · `判断题` 6 · `多选题` 3 · `计算题` 1 · `解答题` 1

→ 我的 6 类（单选/多选/填空/判断/解答/简答）**覆盖了它的主力**，但它有**「计算题」**独立一类 → 我把计算题归入解答题，**可接受**（数学卷面里计算题就是解答题的一种）。
