## 一、总体结论

**架构与业务规模匹配，方向正确，不需要重构，需要的是一次「纪律收口」。**

- ✅ 单体 + node:sqlite 的务实选型在 200–500 学员量级远未到瓶颈；迁移机制、事务边界、脱敏三道闸、票据 SSO 均属同类自研 CRM 的上游水准。
- 🔴 唯一 Critical：**Dify API Key 由工作台浏览器直连持有（存 localStorage）**，直接违反已拍板的「Key 服务端代持」决策，必须最先修。
- 🟠 13 个 Required 集中在三处：AI 调用链未按决策收敛到服务端、安全收尾（refreshToken 存储 / 限速 / 备份纳管）、前端工程化欠账（压缩分包 / 色值纪律 / 组件迁移停滞）。
- 📌 唯一值得的**预先**架构投资：把「指标计算」抽成 `utils/metrics.js` 纯函数层（Phase 4 前完成），其余按现有节奏演进即可，不要提前抽象。

### 五轴评分（10 分制）

| 轴 | 得分 | 结论 |
| --- | --- | --- |
| 正确性 | 8.0 | 事务边界规范、异常统一回滚；缺口在批量录分无分数范围校验、连续缺勤口径 |
| 架构 | 8.0 | 模块边界清晰、迁移机制扎实；风险是 finance.js(791行)/attendance.js(692行) 文件体量 |

| 性能 | 7.0 | 运行时无忧（WAL + 索引覆盖）；欠账在生产构建产物（压缩关闭、无分包） |
| 可读性 | 7.5 | views 层约定执行到位（无 axios/$route 违规）；any 约 373 处集中 CRUD 页 |

## 二、现状架构画像

```
┌─ 浏览器 ─────────────────────────────────────────────┐
│  教务前端 :8080 (pure-admin)      AI 工作台 :8082     │
│  src/ (Vue3+TS+EP)                ai-workbench/       │
└──────────────┬───────────────────────┬──────────────┘
               │ /api/*                │ ①票据SSO(60s一次性)
               ▼                       │ ②/api/agent/*只读网关
┌─ nginx :8080 ──┐   ┌─ node :3000 ────▼──────────────┐
│ 静态资源+反代   │──▶│ Express 4 单体                 │
└────────────────┘   │  middleware: helmet/CORS/限速/  │
                     │   审计兜底/错误映射              │
                     │  routes: attendance/students/  │
                     │   exams/leads/finance/reports/ │
                     │   ai/agent/feedback/auth       │
                     │  utils: scope/validate/grade/  │
                     │   redact + llm(降级链)          │
                     └──────┬─────────────┬───────────┘
                            ▼             ▼
                   ┌─ SQLite (WAL) ─┐  ┌─ Dify :8081 ─┐
                   │ v16 · 迁移强校验│  │ 工作流底座     │
                   │ bind mount     │  │ (浏览器直连⚠️) │
                   └────────────────┘  └──────────────┘
```

**架构选型已验证的强项**（专家团一致认可，不要动）：
1. 事务边界规范：考勤扣减/线索转化等全部写联动在单事务内，prepared statement 复用，异常统一 ROLLBACK。
2. 迁移机制：`PRAGMA user_version` 连续性强校验，跳号终止启动，逐迁移事务，禁改历史。
3. 安全骨架：config fail-fast 先于触库、token_version 即时吊销、约束错误统一映射 400 不泄内部信息。
4. 票据 SSO + 只读网关最小权限：agent 凭证限定 `/api/(agent|ai)` 路径白名单，金额/电话不出网。
5. 备份机制：WAL checkpoint 后复制 + 原子恢复 + 20 份轮换。

## 四、目标架构与演进路线（对齐 ROADMAP Phase 0–5）

**总原则：架构不换血，只做三次收口 + 一次预先投资。**

| 阶段 | 架构动作 | 对应 ROADMAP |
| --- | --- | --- |
| **收口 A · AI 底座对齐决策**（建议 2 人日） | C1 + R1 + R2 + R3 打包：llm.js 加 Dify 适配器 → 场景路由改 scene→workflow 转发 → prompts 内容迁 Dify → 工作台删浏览器直连。降级链（Dify 失败→503→规则引擎）保持不变 | 支撑 D4/D5/D13；Phase 4 前置 |
| **收口 B · 安全收尾**（建议 2 人日） | R4 HttpOnly Cookie + R5 限速 + R6/R7 备份纳管与异地副本 + R8 5xx 文案 | Gate 3 销项（H3/H9 之外新增项并入） |
| **收口 C · 前端工程化**（建议 3 人日） | R13 压缩分包 + R15 色值收敛 + R16 样式顺序；R14 组件迁移按模块滚动推进（并入 Phase 5.2，但设「新页面禁用旧组件」即日生效） | Phase 5.2 提前启动 |
| **预先投资 · 指标层**（R12，建议 1.5 人日，Phase 4 开工前完成） | 抽 `utils/metrics.js` 纯函数层：出勤率/成绩趋势/知识点掌握度/离群检测全部从这里出；连续缺勤口径（R10）同步修正 | Phase 4.2/4.3/4.5 + F14 问数共用 |
| **数据模型演进** | F1–F3、F8–F9 的新表按现有「新表=新 vN」模式无损承载；F2 课评 `class_evaluations` 建表后同步扩展 `agent.js` capabilities；finance.js/attendance.js 超千行前拆分路由模块 | Phase 1–3 |

**明确不做**（防过度设计回潮，与 ADR-001 一致）：不拆微服务、不上 Redis/消息队列、不换 ORM、不为多校区预留、不引入 SSR。
