# 项目记忆系统设计方案 v1

> 目标：任意对话（新开/旧聊）都能接上当前进度；记录可读、可 diff、可追溯；随开发自生长；默认只加载必要层级。
> 性质：与业务无关的基础设施，可整体复制到其它项目。
> 版本：v1 ｜ 起草 2026-09-21 ｜ 状态：待批准

## 一、现状体检（为什么要重做，而不是加个文件了事）

| 现有资产 | 体积 | 问题 |
|---|---|---|
| `WORKBUDDY.md` | 23 KB | 明文要求「每次会话通读」→ 冷启动就吃掉约 7k token，且大部分内容与当次任务无关 |
| `../08-参考/PROGRESS.md` | 98 KB | 只增不减，无法回答「现在做到哪了」 |
| `../07-架构与决策/ROADMAP.md` | 35 KB | 与 PROGRESS 内容重叠，两处真相会漂移 |
| `.workbuddy/memory/` | 150 KB+ | 被 `.gitignore` 忽略 → 不可 diff、不可 blame、不可追溯；archive 已无人再读 |
| `../03-开发指南/` | 33 KB / 7 文件 | **唯一做对的部分**：分层 + 按需读 + git 追踪。本方案是把它的方法论推广到全局 |
| `README.md` | 55 KB | 给人看的文档，不是记忆。不该进上下文 |

**根因三条**：① 没有单一入口（谁都是入口 = 谁都不是入口）；② 没有分级（启动要读 32KB）；③ 没有淘汰机制（只增不减）。

## 二、设计原则（五条，违反即退化）

1. **单一入口**：任何会话只从 `memory/INDEX.md` 进入，不允许"顺手再读点别的"。
2. **三级渐进**：索引 → 摘要 → 详情。默认只读 L0，未命中绝不预读。
3. **一处真相**：同一事实只写在一处，其它地方只放指针（指针漂移比内容缺失更致命）。
4. **只增不删，但会降级**：详情文件永不清空，靠"压缩 / 归档 / 降级为指针"控制体积。
5. **纯文本 + git 追踪**：Markdown，可 diff、可 blame、可 grep。不引入数据库、不引入向量库。

## 三、目录结构（含体积上限与超限处理）

```
memory/                          ← git 追踪（注意：不能放 .workbuddy/ 下，它被 ignore）
├── INDEX.md                     L0 全局索引   ★每次必读    ≤ 4 KB / 80 行
├── CURSOR.md                    L0 当前进度   ★每次必读    ≤ 2 KB / 40 行
├── logs/
│   └── YYYY-MM-DD.md            L1 原始流水   读今天+昨天   ≤ 6 KB/天，append-only
├── knowledge/
│   ├── _index.md                L1 知识目录   命中才读      ≤ 6 KB，一行一条
│   ├── decisions/ADR-NNN-*.md   L2 决策详情   按需深读      单文件 ≤ 8 KB
│   ├── conventions/*.md         L2 约定·踩坑  按需深读      单文件 ≤ 8 KB
│   └── preferences.md           L2 用户偏好   按需深读      ≤ 4 KB
├── tasks/
│   ├── active.md                L1 进行中     常读          ≤ 20 条
│   ├── backlog.md               L1 待做       常读          ≤ 60 条
│   └── done/YYYY-MM.md          L2 已完成     几乎不读      按月滚动
└── archive/YYYY-MM.md           L3 过期日志   永不自动读    只做审计留痕
```

**超限即处理，不商量**：

| 层级 | 超限信号 | 处理动作 |
|---|---|---|
| INDEX / CURSOR | 超行数 | 把正文降级为指针，立刻裁剪 |
| logs | 超 6 KB | 高信号条目 Promote 出去，剩余原样保留（日志不清空） |
| knowledge/_index | 超 6 KB | 同主题合并；详情外移到 L2 |
| tasks/active | 超 20 条 | 完成的移 `done/`，阻塞超 7 天的降级到 backlog 并标注原因 |
| tasks/backlog | 超 60 条 | 90 天未动的删条目、留一行"已放弃 + 原因" |

## 四、字段规范（可追溯三要素：时间戳 + 来源 + 变更原因，缺一不可）

### 4.1 日志条目（`logs/YYYY-MM-DD.md`，append-only）

```markdown
## 14:20 | Decision | 待办待办双端共用一张表，按 owner_id 过滤

- 来源: 会话（用户重申「我确实要两端」）
- 影响: server/src/migrations/019*.js, src/views/todo/*
- 关联: ADR-待办双端 / T-012
- 原因: 曾误做成两套表，权限边界对不上，返工
```

### 4.2 类型枚举（决定条目最终落到哪个文件）

| 类型 | 含义 | 归宿 |
|---|---|---|
| `Decision` | 做了个选择，三个月后会被重新质疑 | `knowledge/decisions/` |
| `Convention` | 写代码/改配置时必须遵守的约定 | `knowledge/conventions/` |
| `Pitfall` | 踩过的坑、环境诡异 | `knowledge/conventions/` |
| `Preference` | 用户偏好（沟通方式、流程门禁） | `knowledge/preferences.md` |
| `Task` | 待办/进行中/已完成 | `tasks/` |
| `Fact` | 稳定的客观事实（版本号、端口、账号） | `INDEX.md` 或对应详情 |

### 4.3 知识目录条目（`knowledge/_index.md`，一行一条）

```
K-017 | Convention | 前端·工作台 | CSS 变量是 --c-*，写成 --brand 静默失效 | conventions/01-前端两端差异.md#工作台 | active | 2026-09-21 | 事故：整页无样式
```

字段顺序：`id | 类型 | 主题 | 一句话结论 | 详情文件#锚点 | 状态 | 更新于 | 来源`

### 4.4 任务条目（`tasks/*.md`）

```
T-012 | doing | 待办·自动（L3 归属矩阵） | 依赖 T-008 | 阻塞：等用户确认老师可见范围 | 2026-09-21
```

## 五、会话协议（★ 本方案的核心）

### 5.1 启动 · 最小加载流程（四步，按顺序）

| 步 | 动作 | 是否可跳过 |
|---|---|---|
| 1 | 读 `memory/INDEX.md` | ✗ 唯一硬必读 |
| 2 | 读 `memory/CURSOR.md` | ✗ 唯一硬必读 |
| 3 | 读 `logs/今天.md` + `logs/昨天.md`（存在才读） | 存在即读 |
| 4 | 依据本次任务，按 INDEX 的指针**按需**读 L1/L2 | 未命中就停在第 3 步 |

- **预算**：L0 ≤ 6 KB（约 1.5k token）；常规任务累计读取 ≤ 15 KB。
- **禁令**：启动阶段禁止读 `README.md`、`PROGRESS.md` 全文、`WORKBUDDY.md` 全文、任何源码目录。
- 判断"要不要读详情"的依据只有一条：**INDEX 里的一句话摘要是否够我动手**。够 → 不读。

### 5.2 结束 · 必写清单（缺一项即视为本次会话未归档）

| # | 动作 | 触发条件 |
|---|---|---|
| 1 | 追加 `logs/今天.md` | 每次（做了什么 / 决策 / 踩坑 / 下一步） |
| 2 | **覆写** `CURSOR.md`（不是追加，是整体刷新） | 每次 |
| 3 | 新增决策 / 约定 / 偏好 → 写详情 + `_index.md` 加一行 | 有则写 |
| 4 | 任务状态变化 → 改 `tasks/*.md` | 有则改 |
| 5 | 体检：任一文件超上限 → 当场裁剪 | 超限则做 |

### 5.3 谁可以写（单一写入者原则）

- **主会话 = 唯一写入者**。子 agent 只回报，不落盘（避免并发写坏文件）。
- `logs/` **只追加、不改昨天**。要修正就追加一条 `Correction:` 条目。
- `INDEX.md` / `CURSOR.md` **只覆写、不追加**。

## 七、自生长与瘦身机制（CAPTURE → PROMOTE → PRUNE → COMPRESS）

```
Capture  随时   日志 append-only，低门槛，宁滥勿缺
   ↓
Promote  会话末 从日志里挑 2–5 条高信号 → 提升进 knowledge/ 或 tasks/
   ↓
Prune    每周   去重 / 冲突消解 / 过期归档
   ↓
Compress 超限   超上限的文件当场压缩为指针
```

### 7.1 冲突消解（三条，按顺序裁决）

1. **时间戳新的胜出**（默认）。
2. **用户明确纠正过的胜出** —— 条目前加 ★，★ 条目**不可被自动覆盖**，只能由用户本人改。
3. **被代码事实推翻的立即标 `deprecated`** —— 不删除，保留原文 + 一行"已废弃，因为 XXX"。

### 7.2 去重规则

- `knowledge/_index.md` 同主题**只允许一行**；新条目进来先搜同主题，命中就合并（更新"更新于"，保留旧来源在详情里）。
- 详情文件内每节 ≤ 10 行，超出说明该拆文件。
- 日志里的操作流水（"跑了构建""改了个 typo"）**永不提升**，自然过期。

### 7.3 归档规则

- 日志满 30 天 → `archive/YYYY-MM.md`（原文不动，只移位置）。
- `tasks/active.md` 完成项 → `done/YYYY-MM.md`。
- **归档 ≠ 删除**：任何"为什么当初这么做"的追问都能在 archive 里 grep 到。

### 7.4 防癌变（针对"索引层慢慢变胖"这个必然趋势）

`INDEX.md` 只允许三种内容：**指针、状态、日期**。出现第四种（正文、解释、示例）当场移出去。

## 12.4 换模型还生效吗（三层保险）

1. **位置硬**：`AGENTS.md` 已是跨工具事实标准（Codex / Cursor / Copilot / WorkBuddy 等均识别根目录约定文件）；再补 `CLAUDE.md`、`.cursorrules` 覆盖各自生态。
2. **成本足够低**：启动只读 6 KB。指令再硬，若代价是 30KB，模型与工具都会想方设法跳过——低到 6 KB 才没人有动机绕开。
3. **平台注入层兜底**：WorkBuddy 会自动注入 `.workbuddy/memory/MEMORY.md`，该文件首行即指向 `memory/INDEX.md`；文件本身自解释（顶部写明"先读我"）。
4. **不依赖任何插件**：纯 Markdown，无脚本、无 MCP、无 hook 也能用。

> 唯一失效场景：某个工具既不读任何根目录约定文件、也不注入 MEMORY.md。此时无解——但前三条已覆盖现有主流工具。

## 12.5 会不会被部署上去（回答提问 2）

**不会，且有三道防线**：

| 防线 | 证据 |
|---|---|
| 前端镜像 | `Dockerfile` 只有 `COPY --from=build-stage /app/dist /usr/share/nginx/html` —— 只取构建产物 |
| 后端镜像 | `server/Dockerfile` 只 `COPY server/src ./src` —— **白名单式**，项目其它目录根本不在镜像里 |
| 构建上下文 | `.dockerignore` 新增 `memory` / `AGENTS.md` / `CLAUDE.md` / `.cursorrules` —— 连 docker build 的上下文都进不去 |

运行时产物只有 `dist/`（nginx 静态）与 `server/src`（Node 服务），二者都不含 `memory/`。
另：`ai-workbench/Dockerfile` 同样只取自身构建产物。
