# ADR-013 · 节次由「固定 1–8」改为「可配置」

- 状态：已采纳
- 日期：2026-10-01
- 关系：**部分修订** v21 设计中的「Q3：节次固定 1–8，不放宽」

## 背景

v21 引入课次实体时，把节次范围写死为 **1–8**，理由是"够用且约束清晰"（Q3）。
该约束在三个层面落地：数据库 `CHECK (period BETWEEN 1 AND 8)`、后端常量（4 处）、
前端按 8 行渲染。

2026-10-01 校区实际使用后反馈：

> 「因为我们是**机构**，不能像学校一样固定 8 节课，希望做成可以个性化创建节次数量和时间。」

机构与学校的作息差异明显：常见形态是一天 4–6 节、周末更多，**8 节是学校的形态**。
固定 8 节会导致：节次时间表里必须留着用不到的空节次、课表渲染出多余的空行。

## 决策

**节次数 = 「节次时间」表的行数**（`period_times`）。管理员在该页面**增删节次**即调整数量，
起止时间与显示名同样可自定义。

具体落地：

| 层 | 决策 |
|---|---|
| 数据库 | 迁移 **v24** 重建 `class_sessions` 与 `period_times`，CHECK 由 `BETWEEN 1 AND 8` 改为 **`>= 1`（只保底、不封顶）**；`UNIQUE(period)` 与 `UNIQUE(class_id, session_date, period)` 保留 |
| 后端 | 节次范围收口到 `utils/period.js`（原先散在 4 处：2 个迁移 + `period-times.js` + `session-engine.js`） |
| 接口 | `GET /api/period-times` 返回**实际配置**；新增 `POST`（加一节）与 `DELETE /:period`（删一节） |
| 前端 | 节次时间页改为**可增删的列表**；周课表与排课模板网格按**实际节次数**渲染 |

## 保留的约束（有意为之）

1. **排课/加课/挪课时，节次必须落在已配置范围内** —— 否则会产生"排了第 9 节但节次时间表里没有第 9 节"的**悬空课次**（课表渲染不出该行）。
   报错文案会指向解决路径：「请先到『排课与课表 → 节次时间』增加节次」。
2. **删除节次时，若该节次下有课次或排课模板则拒绝删除**，并说明在哪用了。
3. **删除后序号不前移** —— 避免把已有课次的节次语义整体改掉（如第 4 节变成第 3 节）。
4. **下限恒为 1**（`CHECK (period >= 1)`）—— 用户选择"上限不限"，但 0 / 负数显然非法，保留保底。

## 影响面

- **迁移**：v24（重建 2 张表）。SQLite 不支持改 CHECK，只能重建；沿 v22 已验证的
  `重建 + INSERT SELECT + disableForeignKeys` 模式，并在**库副本**上先行验证
  （87 条课次、8 行节次配置迁移前后一致、索引重建、外键检查通过）后才升级真库。
- **兼容性**：既有 8 节日次的配置与历史课次**全部保留**（INSERT SELECT 原样搬运）。
- **不做**：不支持"每天节次不同"（周一 5 节 / 周六 8 节）—— 会改动课次唯一性与多处校验，
  工作量数倍；本轮明确排除，若将来有需要另起一批。

## 附带决策：排课权限收窄

同批一并明确「排课与课表」的**视角归属**：它是**校区负责人的排课工作台**。

- 「排课模板」由"所有角色"收窄为**仅 admin**（与学期 / 节次 / 教室 / 任课关系一致）。
  此前同类配置两套权限，是定位不清的直接体现。
- **教师端菜单移除「排课模板」** —— 教师看课表走「周课表 → 教师视角」，不持有排课配置入口。
- 「补课管理」保持对所有角色开放（老师记补课是日常动作）。
