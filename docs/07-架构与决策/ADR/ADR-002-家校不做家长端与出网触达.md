# ADR-002：家校不做家长端，不做任何出网触达

- **状态**：已接受
- **日期**：2026-09-12
- **决策人**：校长（业务方）
- **相关**：[[ADR-001-单校区自用不做多校区架构]]、[[ROADMAP]]

## 背景

系统现有「家校管理 / 通知记录」模块：考勤标记缺勤、成绩录入、请假审批时会自动生成家长通知。但这些通知**只写入数据库，不会真的发给家长**——家长完全感知不到。

在需求访谈中，业务方提出的痛点包含「家长不知道临时调课」，但该痛点与「不做家校触达」直接冲突，业务方权衡后仍选择不做。

## 决策

**本期不做家长端，不做任何出网触达通道。**

具体排除：
- 家长端（小程序 / H5 / 公众号）
- 家长账号体系与家校绑定关系（数据库 v14 已删除，不回摆）
- 短信、微信模板消息、App 推送等任何出网通道
- 家长回执、家校互评、在线投诉

## 理由

1. **家长沟通已有替代渠道**：目前走微信群 + 电话，业务方认可现状。
2. **账号体系是分水岭**：一旦有家长登录，就要处理账号、绑定关系、家长侧权限、家长能看到什么不能看到什么——工作量与风险远大于功能本身。
3. **v14 刚把家长账号删掉**，加回来是架构回摆，会牵动通知、权限、学生档案多个模块。

## 影响（重要，务必知悉）

- **「家校管理 / 通知记录」模块降级为「内部留痕」**：价值是家长来质疑时能翻旧账，不产生任何家长侧感知。**不要再把它当卖点对外讲。**
- **「家长不知道临时调课」这个痛点本期在系统层面无解**，只能靠人工微信群通知。这是明确的、已接受的取舍，不是遗漏。
- 后续建议：把「通知记录」从一级菜单降级为学生档案的一个子页签，减少点击深度（已列入 ROADMAP Phase 5 低优先级）。

## 复审条件

出现以下任一情况时，本决策需重新评估：
- 家长投诉"收不到通知"成为高频问题
- 业务方明确要求家长自助查询（课表 / 考勤 / 成绩 / 课时余额）
- 出现需要家长确认或回执的业务（如调课确认、缴费确认）

## 例外

**AI 学情分析的数据出网不受本决策约束**，走独立的脱敏白名单机制，见 [[ADR-004-AI学情分析采用本地指标加大模型润色]]。
