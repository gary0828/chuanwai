# ADR-007：AI 能力采用「独立工作台 + 只读网关 + 最小权限凭证」

- **状态**：**已决定**（业务方 2026-09-14 拍板）
- **日期**：2026-09-14
- **决策人**：业务方（机构负责人）
- **相关**：[[ADR-004-AI学情分析采用本地指标加大模型润色]]、[[ADR-006-AI学情报告的数据模型与录入粒度]]、[[ADR-002-家校不做家长端与出网触达]]、`../../archive/AI教师助手调研分析报告-2026-09-14.md`

## 背景

下一版本拟开发面向教师的 AI 功能（课程设计、备课、授课流程、作业设计与检查、家长反馈、学情分析与报告）。事前完成调研（`../../archive/AI教师助手调研分析报告-2026-09-14.md`），核心待决问题是：

**AI 能力应融入现有系统，还是构建独立的 AI Agent 系统？若独立，如何读取本教务系统的数据？**

调研中发现三处与既有决策的冲突：D7（本期只做知识点最小集，明确不做题库与 RAG 知识库）、D5（出网白名单不含课时）、D2（不做任何出网触达）。

## 决策

### 1. 采用「逻辑独立、部署统一」，不做完全独立系统

把「融入 vs 独立」拆成四层分别决定，而不是整体二选一：

| 层 | 决策 |
| --- | --- |
| 数据层 | **融入**：教务业务数据留在原库，由原系统只读提供 |
| 能力层 | **内聚**：AI 能力是一个自包含模块，可替换底座、可单独测试 |
| 交互层 | **独立部署**：教师工作台是独立的 Web 应用（`ai-workbench/`），从教务系统免登进入 |
| 知识层 | **独立**：知识资产（教材 / 题目 / 知识点）与 AI 生成产物独立建表，不引业务外键，将来可整体迁出 |

### 2. 教务系统登录态统一，工作台免登进入

- 教务系统顶栏「AI 助手」按钮 → `POST /api/ai/sso/ticket` 签发**60 秒一次性票据**
- 浏览器跳转 `<工作台>/#/sso?ticket=...` → 工作台 `POST /api/ai/sso/verify` 换取会话
- 票据约束：置于 URL **hash 片段**（不随请求发送、不落访问日志）；带 `jti` 防重放；带 `tv` 随登出 / 改密 / 改角色即时失效；载荷不含姓名、电话、金额

### 3. 工作台取数走只读网关 + 最小权限凭证

- 新增 `/api/agent/*` 只读端点，复用既有 `utils/scope.js`（teacher 仅本班）
- `/api/ai/sso/verify` 增发 `agentToken`（`type=ai_agent`，12 小时），`middleware/auth.js` 按类型限制路径：**仅可访问 `/api/agent/*` 与 `/api/ai/*`**，其他一律 403
- 网关**不返回金额、家长姓名与电话**；`capabilities` 如实声明真实库里已有哪类数据，避免把「没有数据」渲染成「0 分」

### 4. AI 底座可插拔，原型阶段默认规则引擎

- 默认走**规则引擎**（零配置、零成本、任何环境可跑）：数字由本地指标引擎计算，文案由模板组织
- 配置 Dify 后可按场景切换为模型生成；调用失败**自动回退规则引擎并标注原因**
- 出网脱敏为硬编码白名单，在教务系统侧完成，不依赖模型自律

### 5. 家长反馈不含任何课时与金额

按机构要求，家长沟通文案**不出现剩余课时与金额**，只陈述学习事实。内部报告（教务版）仍含课时与续课建议，仅 admin 可生成。

## 理由

1. **独立系统的收益在本项目不成立**：单校区、5–15 员工、无专职运维；多一套系统 = 多一份运维与账号体系，且要重做一遍已有的四层权限（菜单 / 接口 / 字段 / 导出），极易漏。
2. **权限必须只有一个真相源**：AI 是最容易捅穿「财务对教师不可见」这条线的后门。把取数收口到只读网关 + 类型化凭证，权限判断仍由原系统做。
3. **开源套不进业务界面**：调研核实 CogniLoop（AGPL、且 v2 已废弃「老师出题→学生做题」管控模式，与培训机构场景相反）、OpenMAIC（AGPL、定位是学生上课体验）等，均无法匹配本机构的教学流程与报告口径；能用开源的是 AI 通用能力层（模型接入、RAG、工作流），不是业务层。
4. **规则引擎优先可零成本验证业务**：先确认「教师会不会用、用起来对不对」，再决定是否为模型质量付费。

## 明确不做

- **不做**多租户 / SaaS 化 / 跨校区（沿用 ADR-001）
- **不做**任何自动发送通道：家长文案只生成、可打印，**不代发**（沿用 ADR-002）
- **不做** text2sql：模型不得生成任何查询语句，只能消费本地算好的指标（沿用 ADR-004）
- **不做**逐题得分与错题原因分类（沿用 ADR-006）
- **不把**知识库做成本期阻塞项：真实库当前无课评 / 知识点 / 题库三类表，工作台对这三块标注「待建设」并继续展示演示内容

## 影响

- 新增目录 `ai-workbench/`（独立子项目，复用根 `node_modules`，独立镜像与端口）
- 新增目录 `dify/`（官方 docker 配置，端口 8081；工作台 8082）
- 数据库 v16（`feedbacks` 表）
- 新增路由：`server/src/routes/ai.js`、`agent.js`、`feedback.js`
- `middleware/auth.js` 增加 `ai_agent` 凭证的路径限制（**是否影响既有鉴权已由 e2e 80/80 回归覆盖**）
- 前端新增：顶栏「AI 助手」入口、首页「使用反馈」卡片

## 复审条件

出现以下任一情况时重新评估「是否拆成完全独立的服务」：

1. 多校区 / SaaS 化（推翻 ADR-001）
2. 知识库需要被其他系统复用
3. AI 批量任务影响教务系统响应（先用任务模式撑，撑不住再拆）
4. 需要本地私有化模型（GPU 部署）
5. 知识库规模从 10³ 涨到 10⁶ 级，`node:sqlite` 不再合适

搬迁成本可控：`ai/` 能力层与 `kb_*` 知识层已与业务解耦，届时按 HTTP 契约平移即可，业务代码无需改动。
