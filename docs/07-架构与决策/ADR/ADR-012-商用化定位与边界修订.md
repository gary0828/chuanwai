# ADR-012：商用化定位与边界修订（D1–D6）

- **状态**：**已决定**（业务方 2026-09-23 拍板）
- **日期**：2026-09-23
- **决策人**：业务方（机构负责人）
- **相关**：[[ADR-001-单校区自用不做多校区架构]]、[[ADR-002-家校不做家长端与出网触达]]、[[ADR-003-财务只做学员账户与剩余学费口径]]、[[ADR-008-数据资产化与AI产出层架构]]、[[ADR-009-课次实体与课消归属]]、[[ADR-010-学员生命周期状态机]]、[[ADR-011-数据修正留痕与对外可信数据]]
- **取代**：本 ADR **部分取代** `ROADMAP.md` §二 Non-goals 中的两条（**作业**、**优惠/赠课**），并**部分修订** `ADR-003`（财务边界）

## 背景

### 定位升级

2026-09-23，业务方明确目标：

> 「我希望是一个**可以商用的、专业的**教务管理平台。」

系统原定位为「**单校区自用**培训机构员工端 CRM」（ADR-001，规模 200–500 学员 / 5–15 员工）。定位升级后，先后完成了两份分析：

| 分析 | 产出 |
| --- | --- |
| 《教务功能补全分析》（本项目实际 schema v20 逐项核对） | 4 处结构性缺口 S1–S4；整体覆盖度 ≈55% |
| 《外部 PRD 对照与借鉴分析》（第三方独立撰写的《全学段教务管理平台 PRD v1.0》） | 采纳 8 / 改造 11 / 不采纳 7；**独立复现了 S1–S4 中的 4 项判断** |

### 「商用」的两种含义（业务方已选 B）

| 含义 | 内容 | 成本 | 结论 |
| --- | --- | --- | --- |
| A. 对外售卖（SaaS） | 多租户、租户隔离、计费订阅 | **架构级**（DB 层加租户维度） | ❌ **不做** |
| **B. 商用品质 + 独立部署交付** | 一套系统交付给**一个机构**独立部署；功能完整度、**配置化程度**、交付物、合规基线达商用标准 | **功能级**（现有「一机构一套 Docker」形态天然支持） | ✅ **采用** |

> ★ 走 B **不需要动架构** —— 现有单机 Docker + 单端口统一入口（18080）已经就是"一机构一套"。

## 决策

### D1 · 配置化是商用的真正门槛

**决策**：所有"机构相关"的东西必须**可配**，改机构**不改代码**。

| 必须可配 | 现状 |
| --- | --- |
| 机构名称 / Logo / 联系方式 | 部分已有（站点信息） |
| **学科**、年级 | ❌ 无主数据（`courses.grade` 是文本、无学科表） |
| **班型**（固定班 / 1对1 / 1对多 / 集训 / 专题） | ❌ 无字段 |
| **评价量表**（课评维度与档位） | ❌ 硬编码 |
| **考勤 × 课消规则矩阵** | ❌ 硬编码 |
| **打印模板**（收据 / 课表 / 成绩单 / 结课报告 / 学员卡） | ❌ 基本没有 |

### D2 · 用「对外交付物」替代「在线家长端」

**决策**：**仍不做家长端与任何出网触达**（ADR-002 维持）；改为把**交付物**做扎实：

| 交付物 | 形态 |
| --- | --- |
| 成绩单 / 成绩通知单 | **PDF + 打印**（含机构 Logo、签章位） |
| 结课报告 / 结业证书 | **PDF**（含成长曲线、作品、评价摘要） |
| 作业报告（班级版 / 个人版） | **PDF** |
| 学员卡 / 课表 | 打印模板 |

**理由**：家长会、面谈、续报说服——**这些真实场景要的是"能拿在手里的东西"**，而不是一个家长要额外学用的 App。用纸质/PDF 交付**拿到 90% 的实际价值，同时避开出网审批与账号体系这两块最贵的成本**。

### D3 · 角色维持「双角色」

**决策**：**只有「管理员级」与「教师级」**，**不新增财务、教务等岗位角色**；**不做自定义 RBAC**。

| 项 | 说明 |
| --- | --- |
| **代价（已知情并接受）** | 若把"前台/出纳"设为管理员级，该账号可见全校营收、退费金额、招生线索池、员工数据 —— **系统层无"只读财务"隔离** |
| **为何可接受** | 5–15 人机构中这些数字本就是校长与前台日常共知的；**角色带来的配置复杂度与人员流动维护成本，常高于它防住的风险** |
| **必须补的三个补偿** | ① **危险操作二次确认**（退费/删除/批量导入/改成绩）② **导出审计 + 按账号开关** ③ **修正留痕**（ADR-011） |
| **将来若需隔离** | **优先加「能力开关」**（按账号勾选模块可见性），**不要引入新角色** |

### D4 · 作业由 Non-goal 移出（定位：数据展示平台）

**决策**：**新增作业模块**，但**只做"数据面"**。

| 角色 | 职责 |
| --- | --- |
| **教务系统（本模块）** | 作业的**数据面**：布置了什么、谁交了、完成得怎么样、趋势如何 |
| **AI 工作台** | 作业的**创作面 + 批改面**：作业设计、批改、评价、家长反馈文案 |

**数据来源**（成败的唯一变量）：
1. **教师/班主任课后 30 秒快速登记**（主数据源）—— **批量矩阵 + 全班默认"已提交·合格"，只标异常**（沿用 ADR-005 课评哲学）
2. **AI 工作台未来单向回写**状态
3. ❌ 家长/学生端提交（不出网）

**呈现三层**：校级总览（校长）→ 班级看板（班主任，未交名单一键转待办）→ 个人视图 + PDF 报告。

> **交付判据**：校长打开看板，**3 秒内**能答出「本月全校提交率、哪个班最差、哪个老师最少批改」。

### D5 · 财务边界扩展（**部分修订 ADR-003**）

**决策**：**补**「优惠 / 赠课 / 课时有效期 / 冻结」；**仍不做**发票、线上支付、总账、会计凭证、提成绩效。

**理由**：商用的售卖方式离不开折扣与赠课，且它们**直接影响收入口径与退费计算**（ADR-003 的核心口径），绕不过去。

⚠️ **新增的定价维度必须同步进口径字典**（否则 ADR-003 的剩余学费口径会出现第二套解释）。

### D6 · 补「学科」与「年级」主数据

**决策**：新增学科、年级主数据（可先用字典表，不必立刻上树）。

**理由**：① 商用要覆盖不同学科机构（"数学/语文/英语"不能写死在代码里）；② 它是**报表与作业看板的必备维度**；③ 课程体系分层（学科→课程体系→课程→阶段→课次→知识点）的第一层。

## 理由

1. **配置化 > 功能数量**：我们已有 55% 功能覆盖，真正卡住"交付给另一家机构"的是硬编码。
2. **交付物是最低成本的商用化**：PDF + 打印不需要账号体系、不需要出网备案，却能覆盖家长会/面谈/续报全部真实场景。
3. **角色越少越稳**：小机构的真实约束是"一个人干三个岗位"，不是"权限要切得多细"。
4. **作业是教学质量的可见性**：校长必须能看见作业情况 —— 这与 AI 无关，且**作业数据是 AI 分析的事实依据**（ADR-008 唯一数据源原则）。
5. **边界修订必须显式留痕**：D4 解禁作业、D5 修订财务边界，均触碰既有 Non-goals 与 ADR —— 按 `feature-dev-flow` 门禁 9，**必须显式修订而非默默绕开**。

## 明确不做（本次重申，不因定位升级而放宽）

| # | 不做 | 依据 |
| --- | --- | --- |
| 1 | **SaaS 多租户** / 跨机构汇总 / 学员转校 | ADR-001 |
| 2 | **家长端 / 学生端 / 家长账号体系与家校绑定** | ADR-002 |
| 3 | **任何出网触达**（短信 / 微信模板 / App 推送）；**包括"为将来预留的适配层"** | ADR-002 |
| 4 | **自定义字段 / 自定义角色 RBAC** | D3 |
| 5 | **题库 / 组卷 / 在线作答 / 自动阅卷 / 错题本** | Non-goals；作业批改归 AI 工作台 |
| 6 | **作业的完整批改与 AI 评价** | D4（→ AI 工作台） |
| 7 | **家长或学生在线提交作业** | ADR-002 |
| 8 | **发票 / 电子发票 / 线上支付 / 日结总账 / 会计凭证** | D5 维持 |
| 9 | **员工提成 / 课时工资 / 绩效工资** | Non-goals（注：教师「课时数统计」是教学管理数据 → **做**） |
| 10 | **学历教育语义直接移植**：学分制 / 绩点 / 毕业审核规则引擎 / 选课轮次与志愿 / 学位授予 / 学籍上报 | 业务形态不符 |
| 11 | **考勤硬件 / 移动 App / 小程序 / 进销存 / 加盟商** | Non-goals |
| 12 | **数据分层 ETL / 数据仓库 / 数据血缘 / 自建向量库** | 过度设计（规模不符 + ADR-008 已定"系统是唯一仓库"） |
| 13 | **跨学段"全生命周期底座"**（三学段统一模型 + 升学关系迁移） | 培训机构无此业务 |

## 影响

**产品层面**
- 功能蓝图从 11 模块扩为 **12 模块**（新增作业）；整体目标覆盖度 **55% → 85%**
- 分期重排：**P0 地基七项 → P1 教务闭环补全 + 作业上线 → P2 作业深化 + 交付物 + 经营分析 → P3 商用打磨**

**数据层**
- 需新增：`assignments`、`assignment_submissions`（作业）；学科/年级主数据；配置项（班型/评价量表/规则矩阵/打印模板）
- 依赖 ADR-009（课次）、ADR-010（状态机）、ADR-011（留痕）**先行或并行**

**文档**
- `ROADMAP.md` §二 Non-goals 需标注本 ADR 的修订（作业、优惠赠课）
- `ROADMAP.md` §5 功能池需补入本 ADR 的派生项并打分
- `docs/00-导航.md` §七 Non-goals 速览需同步
- 需新增 `docs/03-开发指南/隐私与数据合规.md`（借鉴外部 PRD §13 + §23）

**交付层面（商用新增）**
- 需建立 **PDF 渲染方案**与**打印模板中心**（ADR-008 §7 已把 PDF 列为产出层第 2 步，本 ADR 将其**提前到 P2**，因为它同时承担 D2 的交付物职责）

## 复审条件

1. **业务方决定对外售卖（转为含义 A）** → 本 ADR 的 D1/D2/D3 全部需要重做（多租户、家长端、细角色）
2. **机构规模突破 50 人 / 1000 学员** → 需重新评估角色粒度与配置化边界
3. **家长端成为续报瓶颈**（纸质交付不够用）→ 需回到 ADR-002 显式修订
4. **作业登记实测耗时超过 1 分钟/班** → 需回到 D4 重新设计录入方式（**这是本 ADR 最可能失败的一点**）
5. **配置项数量失控**（>50 项配置）→ 需评估配置分组与默认值策略
