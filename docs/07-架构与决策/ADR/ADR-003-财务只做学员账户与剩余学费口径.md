# ADR-003：财务只做「学员账户」，剩余学费口径定义

- **状态**：已接受（**口径待校长最终确认**）
- **日期**：2026-09-12
- **决策人**：校长（业务方）
- **相关**：[[ROADMAP]] §6.1

## 背景

需求访谈中业务方指出痛点「财务对账 / 提成算不清」，但进一步明确：**"小公司没有那么正规的计算体系"**。真实需求被收敛为三个数字：

> 每个学生**交了多少学费**、**扣了多少课时**、**还剩多少学费**。

## 决策

**财务模块只做「学员账户」，不做正规财务体系。**

具体排除：
- 员工提成、业绩归属、课时工资、绩效工资
- 收据 / 发票打印、电子发票
- 优惠审批、优惠券、团报折扣、分期收款
- 线上支付（微信 / 支付宝 / 聚合支付）
- 日结对账单、会计凭证、总账

## 剩余学费口径（核心，不可随意改动）

以**实缴**为基准计算，避免欠费导致账面余额虚高：

```
实缴金额 paid           = SUM(payments.amount) − SUM(已审批通过的 refunds.amount)
已消耗金额 consumed_amt = paid × (consumed_hours ÷ total_hours)
剩余学费 balance        = paid − consumed_amt
                        = paid × (remaining_hours ÷ total_hours)
剩余课时 remaining_hours = total_hours − consumed_hours   （已有字段）
```

规则细节：

- **多订单**：每个订单独立计算，再在学员层面汇总；列表逐单展示，避免家长质疑时说不清
- **欠费部分**（应收 − 实缴）**不计入**剩余学费，单独在「欠费统计」体现
- **剩余学费总额 = 预收账款 = 负债**，不是收入

## 理由

1. **实缴基准更保守也更真实**：按应收算会把"家长还没交的钱"算成机构账面余额，导致现金流误判。
2. **口径自洽**：实缴 = 已消耗金额 + 剩余学费，两边对得上，不会出现负数或虚增。
3. **与现有实现一致**：`/api/finance/stats/consumption` 的 `revenue_recognized = amount × consumed ÷ total_hours` 已是同一口径，可直接复用，不需要重算。
4. **剩余学费总额是校长最易误判的数字**：把已收学费当收入，是培训机构暑期现金流断裂的典型原因。该数字必须上首页看板，且明确标注为「预收账款（负债）」。

## 影响

- 学生档案新增「账户」页签（实缴 / 已扣课时 / 剩余学费，逐单展示）
- 财务统计与首页看板新增「全校剩余学费总额」
- UI 上应展示计算式，让业务方能自行核对

## 复审条件

- 校长确认口径前不要上线该模块
- 若未来引入优惠折扣（实收 ≠ 标价），本口径需相应调整
