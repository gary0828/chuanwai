# ADR-014 · 智能题库系统（题目资产 → 组卷 → 作答 → 学情反哺）

- 状态：已采纳
- 日期：2026-10-07
- 关系：
  - **部分取代** `ROADMAP.md` 的 **D7**「本期只做知识点最小集，不做题库」—— 题库不但要做，且是四期建设的第一块地基
  - **部分修订** `ADR-012` 的 **§D4**「题库仍不做，批改归 AI 工作台」—— 题库自己做，且**批改不在本期范围**（见下「不做什么」）
  - 承接 `ADR-007`（AI 独立工作台 + 最小权限凭证）：题库沿用同一套免登机制，但**另立凭证类型**
  - 承接 `ADR-008`（数据资产化）：题目与配图遵循「DB 只存路径、文件落 `data/assets/`」

## 背景

系统此前**没有题库**：`v1`–`v25` 从未建立 `questions` 表，但 `routes/agent.js` 的
`capabilities()` 里已写 `questions: tableCount("questions") > 0` → **永久返回 false**。
AI 工作台的「知识库 → 题库」页签只能读 `mock/questions.ts` 的 21 道**演示题**。

2026-10-07 校区明确提出：

> 「还需要再加入一个学科，不能只有一个学科。」

这句话背后是三个诉求，逐层展开：

1. **题目得能沉淀** —— 老师反复录同一类题，是纯重复劳动；
2. **题目得能共享** —— 一位老师录的题，全校区老师都能用（这是题库的核心价值）；
3. **题目得能按学科分开** —— 数学题不该和物理题混在一个列表里。

同时参考系统调研（`docs/08-参考/参考系统插件源码分析-2026-10-07.md`）确认：
市面上的题库产品**全都**把「知识点树 + 章节树 + 解题方法」做成三套并行的浏览维度，
且都提供**两级查重**（精确 + 近似）。这不是锦上添花，是这类系统的骨架。

## 决策

### 一、题库作为**独立系统**，与教务端同源部署

题库是老师**高频独立作业**的场景（录题、查题、组卷），塞进教务端的左侧菜单会挤占排课/考勤的入口。

| 项 | 决策 |
|---|---|
| 前端 | **独立应用** `question-bank/`，挂统一入口的 `/qb/` 子路径，与 `ai-workbench/`（`/ai/`）同构 |
| 端口 | **同源同端口**（`WEB_PORT`，默认 18080），不单独开端口 |
| 产物 | 独立目录 `question-bank/dist` → 镜像内 `/usr/share/nginx/html-qb/qb` |
| 免登 | 沿用 ADR-007 的票据机制：教务端签 60 秒一次性票据 → 题库 `POST /api/ai/sso/verify` 换会话 |
| 凭证类型 | **`qb_agent`**（**写**权限，仅放行 `/api/qbank`）<br>★ **刻意与工作台的 `ai_agent`（只读）分开** —— 合并会让 `ai_agent` 的「只读网关」边界名存实亡 |

### 二、权限模型：校区共享 + 只能改自己的（**刻意不同于项目既有模型**）

题库是**校区资产**，不是班级资产 —— 一位老师录的题，全校区老师都能拿来用。
这与项目既有的「teacher 仅本班」**刻意不同**，理由：

- 题库域**不含任何学员数据、不含金额与家长信息**（出网白名单见 `utils/redact.js`，AI 录题只发题干文本）；
- 共享正是题库的价值所在，若按班级隔离，就退回成「个人题夹」。

| 角色 | 读 | 写（改/删） |
|---|---|---|
| admin | 全部 | 全部 |
| teacher | **全部**（共享） | **仅自己录入的**（`created_by` 过滤） |

### 三、查重：两级，且**限定同一学科内**

| 级 | 手段 | 说明 |
|---|---|---|
| L1 精确 | 题干归一化后哈希（`content_hash`，走索引） | 归一化会去掉空格与标点，所以「差一个空格」也算重复 |
| L2 近似 | 题干前段做 LIKE 粗筛 → 候选集算 Jaccard 相似度 ≥ 0.75 | 万题级不能全表算 Jaccard |
| L3 语义 | **本期不做** | 万题全量跑一次LLM 不经济；且 AI 判定更难向老师解释 |

★ **查重必须限定在同一学科内**：跨学科判重会误导 —— 物理题与数学题撞了相似度，
老师看到「题库里已有」点进去发现是另一科的题，反而要怀疑系统。
跨学科的「重复」本质是**归类问题**，不该在查重里提示。

### 四、学科：**复用教务的 `courses` 表**，不另建一套

`courses` 已被 **15 张表**引用（排课/考勤/财务/考试/知识点/测评/课消…）。
题库若另立一张学科表，必然出现「教务叫『初中数学』、题库叫『数学』」的分叉，
而分叉之后每一次统计都要join 两套口径 —— 这是典型的长期技术债。

★ 实测确认：教务端**界面几乎不用课程下拉**（只有 API 定义层），统计也不按课程分组，
所以「加 22 门课」对教务端影响极小（`analytics.js` 只按 month/source 分组）。

### 五、章节粒度：只预置到**课标主题**级，**不下沉到教材「节」**

预置章级板块（如初中物理的「声现象」「光现象」「物态变化」），因为这是
**课程标准里的主题**，公开且稳定。而教材的「节」因版本而异
（人教/北师大/苏科/沪教的章节名差异很大），**编不准就会污染整个教学体系** ——
老师会以为是对的，然后按错误的结构去组卷。

具体到「节」由老师用题库自带的「知识点与章节」页按自己教材补。

★ `knowledge_points`（学情分析用，与 689 条学生测评联动）**刻意不预置** ——
凭空造知识点等于给学情统计埋一堆空节点。老师按实际教学进度自建。

### 六、四期路线（题库 → 组卷 → 作答 → 学情反哺）

| 期 | 范围 | 状态 |
|---|---|---|
| **一期（2026-10-07）** | 题目资产（录入/检索/三视角浏览/两级查重）+ Excel 导入导出 + AI 截图识别 + AI 出题 | ✅ 已交付 |
| 二期 | 组卷（`papers` + 题目快照）、按知识点/章节铺题 | 未开始 |
| 三期 | 学员作答（`attempts`）、客观题自动判分 | 未开始 |
| 四期 | 学情反哺（`question_kp_stats`）、正确率回填 `correct_rate`、学情报告引用真实题目 | 未开始 |

一期**预留但不实现**的字段：`use_count`（被组卷引用次数）、`correct_rate`/`wrong_rate`
（实测正确率）、`quality_score`（录入完整度）。预留而不实现，是为了避免半迁移。

## 不做什么（Non-goals）

- **不做**学员端/家长端做题（ADR-002 已定：家校不做家长端）；
- **不做**题目付费/版权分发（`source` 字段只做**记录**，不做分发）；
- **不做**跨校区题库共享（ADR-001 已定：单校区自用）；
- **本期不做**主观题自动批改 —— 属三期，且需谨慎设计评分口径；
- **本期不做** L3 语义查重（理由见上）。

## 后果

**正面**：
- 老师的录题成果可沉淀、可共享（题库的核心价值）；
- 题目成为二~四期组卷与学情反哺的**数据地基**（否则三期无题可考、四期无据可分析）；
- 三视角浏览 + 两级查重对齐了同类产品的成熟骨架。

**代价 / 风险**：
- **21 处查询必须带 `deleted_at IS NULL`**（回收站引入）—— 漏一处就是数据泄漏。已用脚本横向核查，规则写进 `database.md` v27 行；
- **21 处查询/端点必须带 `course_id`**（多学科引入）—— 同样漏一处就是跨学科数据泄漏。已抽 `courseFilter()` 共享函数收敛；
- 章节预置到「主题」级意味着**新学科开箱可用但不够细**，老师需花一次时间补「节」；
- 题库是**校区资产**，误删代价高 —— 故引入回收站（软删）。

**后续需要警惕的**（已记入项目记忆 K-069~K-079）：
- 同一逻辑若存在**两份实现**（如查重在 `qbank.js` 与 `qbank-ocr.js` 各一份），改一处必漏另一处 —— 已用横向扫描脚本核查；
- 新增筛选维度时，**列表与导出必须共用同一份条件构造函数**，否则会出现「筛了却导出全部」的静默错误。
