# 需求确认 · 独立题库系统（第二版）

> ⚠️ **本文件取代第一版**。第一版把重心放在「CRUD + Excel 批量导入」，
> 用户提供参考系统截图后**方向修正**：核心是 **AI 录题**（截图/照片 → 结构化题目）。
> 决策人：业务方（机构负责人）｜日期：2026-10-07｜流程门禁：K-018

## 0. 第一版为什么作废

参考系统（@独立老师的题库）的立命之本是**录入效率**，视频标题即「**一天录入 10111 道题**」。

|维度 | 第一版方案 | 参考系统（用户认可） |
| --- | --- | --- |
| 录入方式 | Excel 模板逐行填写（手工） | **截图/拍照 → AI 识别 → 可编辑题卡** |
| 公式 | 纯文本，无公式 | **题干带 LaTeX**（`\vec{a}`、`\frac{\pi}{4}`、`f'(x)`） |
| 查重 | 无 | **每题带「查重」+ 置信度分数** |
| 视角 | 按知识点 | **三种**：按知识点 / 按章节 / **按解题方法** |
| 配图 | 无 | **题干、配图、答案分别切取** |

→ 第一版的推荐「题干纯文本、暂不做公式」**被参考系统否掉**，改为**必做 KaTeX**。

### 明确不照搬的部分

参考系统含「租户库 / 会员与额度 / 语文 / 图库 / 系统配置」——**均不适用**：
本项目是单校区自用、5–15 员工、**纯员工端 CRM**（ADR-001/002），**没有商业化场景**（ADR-012 明确「不做 SaaS」）。
**抄它的录入流水线，不抄它的多租户与计费。**

### `questions` 表设计要点（相对第一版修订）

- `stem` / `options`(JSON) / `answer` / `analysis` —— **全部允许 LaTeX**
- `kp_id` REFERENCES `knowledge_points(id)` ON DELETE SET NULL，**允许 NULL**（通用题）
- `created_by` REFERENCES `users(id)` —— **权限过滤依据，不能省**
- `source` TEXT NOT NULL CHECK IN ('自编','AI 原创','教材','授权题库') —— **必填受限枚举**
- `difficulty` INTEGER CHECK BETWEEN 1 AND 5（与 `knowledge_points.difficulty` 同口径）
- `ocr_confidence` REAL —— ★ **新增**，存 AI 识别置信度（对应截图里的 0.89/0.58/0.36）
- `ocr_raw` TEXT —— ★ **新增**，存模型原始输出，便于识别错了后对照排查
- `content_hash` TEXT —— ★ **新增**，题干归一化后的哈希，**查重的第一道过滤**（纯 SQL，零成本）

## 4. 待确认（本版新增的真问题）

### 4.1 ★ 查重怎么做（截图里每题都有「查重」按钮）

三层递进，**成本与效果递增**：

| 层 | 手段 | 成本 | 效果 |
| --- | --- | --- | --- |
| L1 | `content_hash` 精确去重（题干归一化后哈希） | 零，纯 SQL | 挡住完全重复 |
| L2 | 归一化后**编辑距离**/分词 Jaccard | 低，纯 JS | 挡住改几个字的重复 |
| L3 | **AI 语义判重**（调模型问「这两题是否等价」） | 每次查重 1 次模型调用 | 挡住改数字/改措辞的重复 |

>推荐 **L1 + L2 落地，L3 留接口**。理由：截图里显示「相似题关联 20」——万题量级下 L2 足够；L3 每题一次调用，10111 题全量跑一遍成本与时间都不可接受，应只在**入库时对新题**判重。

### 4.2 ★ 配图要不要进本期（我上版问过，你当时选的是「纯文本」，但参考系统有配图）

参考系统方法③明确写「**题干、配图、答案分别切取**」。数学几何题、应用题离不开图。
但配图涉及：`/assets` 上传链路 + **K-049 的 `before-upload` 坑**（本项目3 处上传功能都踩过）+ 图片存储与缩略图。

### 4.3 AI 识别的输出格式控制

模型必须返回**结构化 JSON**（题干/选项/答案/解析/题型/难度/知识点建议）。
风险：LaTeX 里的反斜杠 `\` 与 JSON 转义冲突，是这类场景的经典坑 → 需设计容错解析（先剥 ```json 围栏、再修转义、失败要明确报错而非静默空白）。

### AI 调用链路（复用 ADR-007 铁律）

```
浏览器传图(base64)
  → POST /api/qbank/ocr/recognize  （auth + qb_agent 校验）
  → 服务端校验：体积上限 / MIME 白名单 / 非空
  → llm.chat() 用 deepseek-v4-flash-vision-exp，prompt 要求返回 JSON
  → **容错解析**：剥围栏 → 修转义 → 失败则明确报错
  → 算 content_hash 做 L1 查重
  → 返回题卡 + confidence（**不回写库，等用户确认后再存**）
```

- Key 全程在服务端，**不下发前端**
- 图片**只转发不落盘**（除非将来做配图功能）
- 识别结果**先返回给用户确认，不自动入库** —— 避免污染题库
