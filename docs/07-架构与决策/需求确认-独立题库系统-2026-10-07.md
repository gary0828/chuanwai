# 需求确认 · 独立题库系统

> 按`feature-dev-flow` 门禁 1 产出。**用户确认前不动一行代码。**
> 决策人：业务方（机构负责人）｜日期：2026-10-07 ｜流程门禁：K-018

---

## 1. 要解决的业务问题

校区要有一份**可沉淀、可检索、可复用**的题目资产。现在题目散在老师个人手里（Word / 口头），出了好题就丢了，换个老师还要重出。

「校区测试已启动」这个背景下，本需求**不阻塞校区测试**，是并行的下一件事。

## 2. 形态：独立前端 + 共用后端

采纳 **ADR-007 给AI 工作台定下的同构分层** ——「逻辑独立、部署统一」：

| 层 | 决策 |
| --- | --- |
| 数据层 | **融入**：题目数据进教务系统同一个SQLite，权限仍由原系统判定 |
| 能力层 | **内聚**：`question-bank/` 是自包含模块，可整体迁出 |
| 交互层 | **独立**：独立 Web 应用（`/qb/`），从教务系统免登进入 |
| 凭证层 | **新发 `qb_agent` 类型**（不污染`ai_agent` 的只读定位） |

- 不做「前后端都独立」：单校区 5–15 员工、无专职运维，多一套账号体系收益不成立，ADR-007 已明确否决。
- **凭证必须新类型而非给 `ai_agent` 加口子**：题库要写（老师录题），`ai_agent` 的定位是只读网关；塞进去会让那8 条边界注释名存实亡。

## 4. 验收标准

| # | 判据 | 怎么算过|
| --- | --- | --- |
| 1 | 免登可达 | 教务系统点入口 → 直接进 `/qb/`，**不出现登录页** |
| 2 | 题目 CRUD | 新增/编辑/删除题目，刷新后数据仍在；每步都有明确反馈（**静默即缺陷**，K-050） |
| 3 | 筛选 | 按知识点 + 难度 + 题型 + 来源四类筛选能正确收敛结果集 |
| 4 | Excel 导入 | 下载模板 → 填题 → 上传 → 成功入库；**报错要指出第几行哪个字段错** |
| 5 | Excel 导出 | 导出后能用Excel 正常打开，中文不乱码 |
| 6 | 知识点关联 | 可选挂知识点，也可留空；按知识点筛选能筛出 |
| 7 | 权限双角色 | admin 全量可改；**teacher 只能改/删自己录入的**（`created_by` 过滤），改别人的返回明确拒绝 |
| 8 | 版权来源 | `source` 必填，选项：自编 / AI 原创 / 教材 / 授权题库 |
| 9 | 数据不丢 | 建表走**迁移 026**（版本号连续，执行器 `if (m.version !== current+1) throw` 会拒绝跳号启动） |
| 10 | 既有功能零回归 | 教务系统 + AI 工作台全部既有页面正常；类型错误零新增（基线 21） |
| 11 | 白屏检查 | 三个前端任一刷新均无空白页（nginx 正则 location 抢资源的老坑） |
| 12 | 用户实测 | **由用户实测通过才算完成**，自测不算（K-019 / 门禁 3） |

### `questions` 表设计要点

- `kp_id` REFERENCES `knowledge_points(id)` **ON DELETE SET NULL**，允许 NULL（通用题）
- `created_by` REFERENCES `users(id)` —— **权限过滤的依据，不能省**
- `source` TEXT NOT NULL CHECK IN ('自编','AI 原创','教材','授权题库')—— **必填且受限枚举**
- `difficulty` INTEGER CHECK BETWEEN 1 AND 5（与 `knowledge_points.difficulty` 同口径）
- `type` 支持：选择题 / 填空题 / 解答题（与现有 mock 一致；选择题 `options` 存 JSON）
- `stem` / `answer` / `analysis` TEXT
- `status` TEXT：草稿 / 待审 / 已启用
