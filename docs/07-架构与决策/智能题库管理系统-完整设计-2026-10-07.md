# 智能题库管理系统 · 完整设计

> ⚠️ **本文件取代 v1 / v2**。前两版把「录题效率」当核心，是**手段当目的**。
> 本版按业务链重建：**六子系统 + 一个贯穿的能力层 + 一个闭环**。
> 决策人：业务方（机构负责人）｜日期：2026-10-07｜流程门禁：K-018 / K-019

---

## 0. 为什么前两版错了

| 版 | 我说的核心 | 问题 |
| --- | --- | --- |
| v1 | CRUD + Excel 批量导入 | 那是手工活，参考系统的价值恰恰是**不用手工** |
| v2 | **录题效率** | 把参考系统里的「智能录题」当成了整个系统 |
| **v3** | **一套完善的智能题库管理系统** |✅ 本文件 |

参考系统的菜单（截图读出）实际是一条完整业务链，不是录题工具：

```
录题 → 题库管理 → 组卷 → 试卷 → 作答 → 阅卷 → 错题 → 学情 → 沉淀回题库
```

**「智能」不是一个功能，是贯穿全链的能力。**

## 1. 系统边界

### 六个子系统（全部要做）

| # | 子系统 | 内容 |
| --- | --- | --- |
| ① | **题目资产** | 题目库（题型/难度/知识点/来源/配图）· 知识点树 · 专题文件夹 · 查重去重 · 四种录入方式 |
| ② | **检索与浏览** | 三视角（知识点 / 章节 / **解题方法**）· 全文搜索 · 多维筛选 · 批量操作 |
| ③ | **智能组卷** | 按知识点+ 难度 + 题型抽题 · 手工组卷 · 智能组卷 · 卷面增删改 · 导出 Word/PDF |
| ④ | **试卷与作答** | 试卷实体 · 布置到班级 · 学生作答（**身份方案待定，见 §6**）|
| ⑤ | **阅卷与诊断** | 自动判分 · 错题归集 · 错因分类 · 知识点掌握度 · 学情画像 |
| ⑥ | **题库智能**（能力层） | AI 录题 · AI 出题 · 查重判重 · 知识点推荐 · 难度标定 · **学情反哺** |

### 闭环 —— 这才是「智能」的真正落点

```
③组卷 → ④作答 → ⑤阅卷诊断 → 真实数据回流 → ①题库更准
```

- 错题**自动入库**并标记「常错知识点」
- 题目难度与**实际正确率校准**（标称的难 ≠ 实测的难）
- 知识点掌握度报表驱动下一步教学与组卷

### 明确不做

| 不做 | 理由 |
| --- | --- |
| 租户库 / 会员与额度 | ADR-001 单校区自用 · ADR-012 不做 SaaS |
| 语文专项（诗词/文言） | 校区是数学学科（截图全为数学题） |
| 图库 / 系统配置后台 | 无对应场景，配置并入现有 `ai-admin` |
| 多校区 / 分校| ADR-001 明文排除 |

### 技术路线：全部自建

不外接试卷切题 OCR，**不依赖 Dify**。多模态识别走DeepSeek Vision，精度靠 prompt 工程调优。
（ADR-008：Dify 是加工厂不是仓库；本期能力轻，不值得引入额外链路）

设计原则：**每张表都能独立回答一个业务问题**，不搞宽表。

> ★ **字段级修订（2026-10-07，据参考系统插件 API 分析）**
> 依据：`docs/08-参考/参考系统插件源码分析-2026-10-07.md`
>
> | # | 修订 | 理由 |
> |---|---|---|
> | 1 | `kp_id` 单值 → **`kp_ids` JSON 多值** | 一题常挂多个知识点（参考系统用 `knowledgePointIds: number[]`，AI 识别也会同时给多个建议）。**保持 JSON 不建关联表**：题库 <1 万条，「按知识点反查」走 `json_each()` 足够，省一张表 |
> | 2 | 新增 `parse_status` | 参考系统有 `RetryAiParse` + `AiFill`（**47 处引用**）→ 识别是**分阶段**的：pending → recognized → filled → confirmed / failed |
> | 3 | 新增 `custom_tags` + `exam_year` + `region` | 参考系统 `customTagIds`（37 处）、`.year`（**103 处**）。真题年份是机构题库刚需维度 |
> | 4 | 筛选支持「**含子文件夹**」 | 知识点/章节是树形，筛父节点必须含子树（参考系统 `includeSubFolders`）|
> | 5 | **草稿自动保存**（localStorage + `QuotaExceededError` 兜底）| 编辑中未保存内容不能丢，参考系统有明确处理 |
> | 6 | 题目文件夹与试卷文件夹**分开**（二期）| 参考系统用 `folderId` / `paperFolderId` 两个独立 ID |

## 3. 六子系统实现要点

### ① 题目资产

- **四种录入方式**：手工填写 / Excel 批量导入 / **AI 截图识别** / AI 出题
- **KaTeX 渲染**（新增依赖 `katex@0.19.0`，仅 1 个传递依赖）：题干、选项、答案、解析全支持 `$...$` 与 `$$...$$`
- **配图**：走既有 `/assets` 链路（DB 存路径 + 文件落 `server/data/assets/questions/`）
  ⚠ 前端上传前**必读 K-049**（本项目 3 处 `before-upload` 都踩过）
- **知识点关联**：允许为空；录题时AI 建议知识点，用户确认

### ② 检索与浏览

- **三视角**：`按知识点`（挂树）· `按章节`（挂课程大纲树）· `按解题方法`（枚举 + 维护入口）
- **全文检索**：SQLite FTS5（`questions_fts`虚拟表，`content` 索引同步触发器）
  > 不引向量库（K-030 护栏：<1 万条文件/SQL 方案更准且零基础设施）
- **查重三层**：
  | 层 | 手段 | 成本 |
  |---|---|---|
  | L1 | `content_hash` 精确 | 纯 SQL |
  | L2 | 归一化后编辑距离 / 分词 Jaccard | 纯 JS |
  | L3 | AI 语义判重 | 1 次模型调用 |
  → **L1+L2 落地，L3 只在入库时对新题跑**（万题全量跑不经济）

### ③ 智能组卷

- **手工组卷**：按条件筛选 → 加入卷面 → 调分值调顺序
- **智能组卷**：给条件（知识点范围/难度分布/题型分布/总分）→ 按权重随机抽题，**避免同知识点连续出现**
- **导出**：Word（`docx` 库）/ PDF（浏览器打印或服务端渲染）
- **卷快照**：`paper_questions.seq_snapshot` 存题干快照 → 题目后续被改，历史卷不受影响

### ④ 试卷与作答

- 试卷状态机：`草稿 → 已发布 → 已考完 → 已归档`
- 「组目录策略」对应：**题目乱序 + 选项乱序**，减少抄袭（参考系统有此菜单，我们只做规则开关）

### ⑤ 阅卷与诊断

- **自动判分**：客观题（选择/判断/填空）规则判分；主观题（解答/简答）给**建议分数 + AI 批改意见**，**最终由老师确认**
  ⚠ ADR-006 已定：**不做逐题错因自动分类**由模型推断，只记录客观对错与错因标签（老师选）
- **错题本**：从 `attempt_answers` 聚合，按学生/知识点/时间三个维度看
- **学情画像**：复用 `engine.ts` 现成 10 个函数（`kpMasteryRanking` / `errorRanking` / `scoreOutliers` / `studentInsight` / `classDiagnosis`）

### ⑥ 题库智能（能力层）

| 能力 | 实现 | 底座 |
| --- | --- | --- |
| AI 录题识别 | 图片 → 结构化 JSON 题卡 | `deepseek-v4-flash-vision-exp` |
| AI 出题 | 按知识点+难度+题型批量出 | 现有 `llm.chat` |
| 查重判重 | L3 语义判重（仅入库时） | 同上 |
| 知识点推荐 | 读题干 → 推荐知识点 | 同上 |
| 难度标定 | AI 预估 + 实测校准 | 同上 + `question_kp_stats` |
| 质量诊断 | 扫描解析缺失/知识点未挂/配图缺失 | **纯规则，零模型成本** |

**底座约束（ADR-007 铁律）**：Key 存`settings` 表 · 服务端调用 · **永不下发前端** · 图片**只转发不落盘**（配图除外）· 识别结果**先返回用户确认，不自动入库**（避免污染题库）

## 6. 唯一的真阻断项：学员作答身份

三期要做「学生在线作答」，而项目铁律是**学员与家长无账号不登录**（ADR-002，ROADMAP D7 明文）。

**你上一轮初定「一次性作答码」**，方向可行，但三期开工前需单独确认。本设计按此预留：

```
老师布置试卷 → 系统生成作答链接（含一次性 token）
     → 投屏/发班级群，学生无需登录直接作答
     → 提交后记录挂 student_id（老师分配或学生自选姓名）
```

⚠ **待确认**：学生如何对应到 `student_id`？（① 老师提前排座位号对应名单 ② 学生首次输入姓名匹配 ③ 扫码绑定）。此项影响 `attempts` 表设计，**二期结束前必须定**。

## 7. 验收标准（全局）

| # | 判据 |
| --- | --- |
| 1 | 免登可达：教务端点入口 → 直接进 `/qb/`，无登录页 |
| 2 | 公式渲染：含 LaTeX 的题目在列表与详情**都渲染为公式**，不显示裸 `$...$` |
| 3 | AI 录题：传图 → 返回可编辑题卡（题干/选项/答案/解析/题型/难度/知识点建议）|
| 4 | **置信度如实展示**：低置信**页面明确标示**，不把低置信结果当正确答案呈现（K-050 静默即缺陷）|
| 5 | **识别失败有反馈**：超时/非法 JSON → 页面明确报错，**不静默空白** |
| 6 | 查重可用：重复题能提示且**指出与哪题重复** |
| 7 | 三视角：按知识点 / 按章节 / 按解题方法 均能正确收敛结果集 |
| 8 | 权限双角色：admin 全量；teacher **只能改/删自己录入的**（`created_by`），改别人的明确拒绝 |
| 9 | 迁移连续：026 → 030 版本号连续，跳号会导致后端拒绝启动 |
| 10 | 既有功能零回归：教务端 + 工作台既有页面全正常；类型错误零新增（基线 21）|
| 11 | 三端无白屏：`/` · `/ai/` · `/qb/` 任一刷新均正常（nginx 正则 location 抢资源的老坑）|
| 12 | **用户实测**：每期由你实测通过才算完成（K-019 / 门禁 3），自测不算 |
