## 2. 现状判断

**强项（护城河，不要动）**：课时包联动扣减与回补、缺勤→通知→撤销的幂等链路、课消收入确认分摊、调课审批自动同步课表、线索一键转化（建档+报班事务）、成长档案全生命周期时间线。这套**业务联动完整度**超过多数收费 SaaS。

**整体覆盖度约 53%**：强在「教务执行闭环」，弱在「触达 / 经营 / 移动化」。

**最大结构性缺口**：系统在库里**没有「学员日常表现」数据**。现有可分析数据只有考勤状态、考试成绩、课时消耗、缴费记录——AI 学情分析若无课评数据，只能基于三次考试做线性回归，产出正确的废话。**因此「课堂评价」被 AI 需求倒逼为前置模块。**

## 4. 优先级方法

采用 **RICE = Reach × Impact × Confidence ÷ Effort**

- **Reach**：月均关键动作次数（系统自动执行或人工操作的次数，估算值，需业务校准）
- **Impact**：3 = 巨大（影响收入或流失）/ 2 = 高 / 1 = 中 / 0.5 = 低
- **Confidence**：对 Reach 与 Impact 估计的把握（0.5 / 0.8 / 0.9）
- **Effort**：人日（含实现 + 联调 + 浏览器验证 + 文档）

**排序例外**：标注为「前置依赖」的项不参与 RICE 排序，按依赖顺序强制前置（RICE 会系统性低估地基类功能）。

### 关于「校长自然语言问数」的风险提示

D6 选择了「校长经营洞察」，但**通用 text2sql 会让大模型写错 SQL 或理解错口径**，产出一个看起来专业、实际错误的数字——校长拿它做决策会出事。因此本期**降级为「预置指标语义问答」**：把用户输入映射到 `/api/analytics/metrics` 已定义的 12 个指标（语义匹配 + 槽位填充），**不允许生成任意 SQL**，命中不了就明确回答「这个问题我答不了」并列出可问清单。

## 8. 关键设计决策（落地前需确认口径）

### 6.1 学员账户口径（建议值，上线前请校长确认一次）

以**实缴**为基准计算，避免欠费导致账面余额虚高：

```
实缴金额 paid          = SUM(payments.amount) - SUM(已审批通过的 refunds.amount)
已消耗金额 consumed_amt = paid × (consumed_hours / total_hours)
剩余学费 balance        = paid - consumed_amt   (= paid × remaining_hours / total_hours)
剩余课时 remaining_hours = total_hours - consumed_hours   （已有字段）
```

- **多订单**：每个订单独立计算，再在学员层面汇总；列表逐单展示，避免家长质疑时说不清
- **欠费部分**（应收 − 实缴）**不计入**剩余学费，单独在「欠费统计」体现
- **全校剩余学费总额 = 预收账款（负债）**，建议放到首页看板显眼位置——这是校长最容易误判的数字
- 现有 `/api/finance/stats/consumption` 的 `revenue_recognized = amount × consumed ÷ total_hours` 与上述口径一致，可复用

### 6.2 课堂评价维度（建议）

- **交互设计**：课次维度批量评价，全班默认「良好」，老师**只标异常学员**，大幅降低录入负担（否则必然烂尾）
- **结构化维度**（1–5 分，可选填）：专注度、参与度、作业完成、知识点掌握
- **自由文字**：一句话点评（可选，供 AI 生成报告时引用）
- **数据落点**：新建 `class_evaluations` 表（课次 + 学员 + 教师 + 维度分 + 文字 + 时间）

### 6.3 知识点体系最小集

- 表结构：`knowledge_points(id, subject, parent_id, name, sort)` 树形；`exam_scores` 关联知识点（成绩录入时按题目/题型打标签，或整卷打 1–3 个知识点）
- **只建树和标签**，不做题库、不做组卷、不做在线答题
- 历史成绩提供「补录标签」入口，否则 Phase 4 只能用新数据

### 6.4 AI 脱敏与降级

- **出网白名单**：只允许 `学号（内部 ID）+ 年级 + 结构化指标数值 + 知识点名称` 出网；**姓名、家长姓名、家长电话、金额一律不出网**
- **降级**：未配置 `LLM_API_KEY` 或调用失败 → 自动使用规则引擎模板版报告，页面明确标识「规则生成（未启用 AI）」
- **审计**：记录生成人、时间、模型名、输入指标快照，可复现
