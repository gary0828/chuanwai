# 安装与启动

两种方式：**Docker 部署**（生产与演示）与**本地开发**（改代码时）。前端页面在两种方式的端口不同，别混用。

---

## 1. 环境要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 22.13 | 后端依赖内置 `node:sqlite`，低版本没有该模块 |
| pnpm | 随 `package.json` 的 `packageManager` 字段 | 前端依赖 |
| Docker | Desktop 或 Engine + Compose v2 | 仅部署方式需要 |
| Python | 3.14（系统自带） | 仅浏览器验证脚本需要 |

---

## 2. Docker 部署

### 2.1 启动

```bash
# 生成签名密钥（后端必需，缺失时会拒绝启动而不是回退默认值）
export JWT_SECRET=$(openssl rand -hex 32)
# Windows PowerShell：
# $env:JWT_SECRET = [Convert]::ToHexString((1..32|%{Get-Random -Max 256})) -replace '-',''

docker compose up -d --build
```

`JWT_SECRET` 需注入容器的 `server.environment`，`docker-compose.yml` 中已用 `${JWT_SECRET:?...}` 强制校验：

```yaml
server:
  environment:
    - PORT=3000
    - JWT_SECRET=${JWT_SECRET:?JWT_SECRET 未设置，拒绝启动}
```

### 2.2 服务地址

统一入口形态：**一个端口同时提供教务系统、AI 工作台与后端 API**（2026-09-23 起为唯一形态）。

| 服务 | 地址 |
| --- | --- |
| 教务系统（唯一入口） | http://localhost:18080 |
| AI 工作台（子路径 `/ai/`） | http://localhost:18080/ai/ |
| 后端 API（经 nginx 反代） | http://localhost:18080/api |
| 健康检查 | http://localhost:18080/api/health |

- 对外端口由 `.env` 的 `WEB_PORT` 决定（缺省 `80`；无域名请用 `18080` —— 大陆 80/443 对外服务需 ICP 备案）。
- SQLite 数据落在 `server/data/attendance.db`（已挂数据卷，首次启动自动建表并写入种子数据）。
- `unified`（nginx）会等 `server` 健康后才启动。

### 2.3 部署后验证

```bash
bash server/scripts/docker-verify.sh   # 容器 / 健康检查 / 前端托管 / 反代 / 数据持久化，共 9 项
BASE=http://127.0.0.1:3000 node server/scripts/e2e-lifecycle.mjs   # e2e 80 项
```

### 2.4 排障：中文目录导致 `docker compose up` 失败

报错形如 `failed to dial gRPC ... non-printable ASCII characters`。这是 Docker Desktop / Buildx 的已知缺陷：compose 走 Bake 构建时会把**当前工作目录**写进 gRPC 会话头，而 gRPC 要求头字段为可打印 ASCII，中文目录名直接让构建在起始阶段失败（`COMPOSE_BAKE=false` 也绕不开）。

两种解法任选其一：

```bash
# 方案 A（推荐）：把项目放到纯 ASCII 路径，如 D:\attendance-system\
docker compose up -d --build

# 方案 B：留在中文目录，手工打镜像再启动（compose 未指定 image 时，默认镜像名即 <项目名>-<服务名>）
docker build -t attendance-system-server  -f server/Dockerfile .
docker build -t attendance-system-unified -f deploy/Dockerfile.unified .
docker compose up -d --no-build
```

### 2.5 国内网络拉取镜像慢

Docker Desktop → Settings → Docker Engine，配置 `registry-mirrors`，例如 `https://docker.m.daocloud.io`。

## 3. 本地开发

```bash
# 1. 后端（端口 3000）
cd server
npm install
npm run dev          # 缺 JWT_SECRET 会拒绝启动，见 ../05-配置/环境变量.md

# 2. 前端（端口 8848，vite 已代理 /api 到 localhost:3000）
pnpm install
pnpm dev
```

常用变体：

```bash
node ./node_modules/vite/bin/vite.js --port 8848          # 直接起 vite（不经 pnpm 脚本）
node ./node_modules/vite/bin/vite.js build                # 生产构建
node _verify_test/serve-dist.mjs                          # 托管 dist/（:8848，含 /api 反代）
```

> 浏览器验证请用**生产构建产物**，不要用 vite dev server。

## 4. 首次登录后必做

1. **改掉默认口令** `admin/admin123456`、`teacher/teacher123456`（公开信息，且登录失败限速默认 10 次 / 15 分钟 / IP）。
2. 建员工账号、绑定班主任。
3. 在 `../06-部署/校区部署与升级.md` 走一遍备份配置。
