## 〇、先做「一键保险」（最重要，3 分钟，强烈建议做）

因为服务器是 **PVE 里的虚拟机**，最省心的回滚方式不是命令行，而是**虚拟机快照**：
不管后面搞成什么样，点一下就能**整个回到现在这个状态**，连数据一起回。

在 PVE 网页里：

1. 左侧选中这台虚拟机
2. 点上方 `快照` → `现在拍摄快照`
3. 名称填 `升级前-20260924`，描述随意 → `拍摄`

✅ 快照列表里出现这条 → **保险到位了，后面怎么折腾都能回来。**

> ★ 如果你**没有 PVE 或者不会拍快照**：跳过这步，但**第二步的备份必须做**，且做完要确认备份文件真的存在。

## 四、先构建新镜像（**这一步老师完全无感，服务照常运行**）

> ★ 这是本手册跟"常规做法"最大的不同：**先偷偷把新版本准备好，最后再一次性切换**，
> 这样系统打不开的时间从 3–8 分钟压缩到 10–30 秒。老师在点名时也敢升级。

```bash
cd /opt/jx-system
docker compose build
```

✅ 最后出现类似 `✔ Service server Built`、`✔ Service unified Built`，回到命令行提示符。
⏳ 首次构建慢，**3–8 分钟属正常**，耐心等，别 Ctrl+C。
❌ 报 `gRPC` / `non-ASCII` → 项目在中文目录（与前提不符，先告诉我）。
❌ 报 `no space left on device` → 磁盘满了，先 `docker image prune -f` 再重跑。

```bash
# 确认新镜像建好了
docker images --format "{{.Repository}} {{.ID}} {{.CreatedSince}}" | grep attendance-system
```

✅ 两条镜像的 `CreatedSince` 都是刚刚（几秒/几分钟前）。

## 五、切换（**真正的停机窗口：10–30 秒**）

> ⏰ 建议挑**课间或放学后**。老师正在点名的瞬间别切。

```bash
cd /opt/jx-system

# ① 清掉可能残留的老容器（数据在 server/data，删容器不丢数据）
docker rm -f attendance-server attendance-unified attendance-web attendance-ai-workbench 2>/dev/null || true

# ② 起新容器（--no-build 因为上一步已经建好；--force-recreate 必须加，否则可能继续跑旧镜像）
docker compose up -d --no-build --force-recreate

# ③ 等它起来，看状态
sleep 20
docker compose ps
```

✅ 两个容器都是 `Up`（`attendance-server` 带 `healthy`）。
❌ 一直 `Restarting` → 立刻看日志：`docker compose logs --tail=100 server`，把报错发我。

> ⚠️ `--force-recreate` **不能省**。少了它 Docker 可能让旧容器继续跑旧镜像，
> 表面上"升级完成"，实际上代码根本没换（这个坑 2026-09-23 实测踩过）。

## 八、出问题怎么回滚（两条路，从简单到复杂）

### 路线 1 · PVE 快照回滚（**最简单，推荐小白**）

PVE 网页 → 选中虚拟机 → `快照` → 选中 `升级前-20260924` → `回滚`。

✅ 等几十秒 → 开机 → 系统和数据**完全回到升级前那一刻**。
⚠️ 回滚会丢掉升级之后产生的新数据（比如这期间新录的学员），所以**只在真的出问题时用**。

### 路线 2 · 命令行回滚（没有快照时）

```bash
cd /opt/jx-system

# ① 停服务
docker compose stop

# ② 还原升级前的数据库
bash server/scripts/restore-db.sh server/data/attendance-20260924-xxxx.db attendance-server -y
#    ↑ 换成第二节生成的那个文件名

# ③ 把代码退回旧版本（★ 必须做：v21 的库配旧代码会启动失败）
git checkout <升级前那个 commit 号>

# ④ 重新起来
docker compose up -d --build --force-recreate
```

> ⚠️ **数据库迁移是单向的**：只回程序不回数据 = 起不来；只回数据不回程序 = 也起不来。
> **两个必须一起回。** 这就是为什么第一步的备份/快照那么重要。

### 备选 · 服务器连不上 gitee 时的「离线升级」

如果 `git pull` 死活拉不动（网络/权限），可以**只换程序、不动代码目录**：

1. 我这边在本机把两个新镜像导出成一个压缩包给你
2. 你把它传到 `/opt/jx-system/`，然后：
   ```bash
   docker load -i jx-images.tar.gz
   docker compose up -d --no-build --force-recreate
   ```
需要走这条路时跟我说，我来准备包。

## 九、常见报错对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `git pull` 报要密码 / `Permission denied` | 服务器没配仓库凭据 | 改用 `git pull https://gitee.com/gary0828/chuanwai.git main` |
| 拉完 `git log` 还是旧 commit | **pull 的是 github 旧仓库** | 按第三节 B 方案重拉（最常见的坑） |
| `docker compose build` 报 gRPC / 非 ASCII | 项目在中文目录 | 换到 `/opt/jx-system` 英文路径 |
| 容器一直 `Restarting` | 常见是 `.env` 丢了导致 `missing JWT_SECRET` | `cp .env.bak-20260924 .env` 后 `docker compose up -d` |
| 后端日志 `missing JWT_SECRET` | 同上 | 同上 |
| 打开首页白屏 | 浏览器旧缓存 | `Ctrl + F5` 强制刷新 |
| 页面能开但数据是空的 | 在**新目录** clone 了代码 → 灌了种子演示数据 | 别慌：真实数据还在旧目录 `server/data/`，告诉我我来救 |
| 升级后学员数变少了 | 同上 | 同上，**不要**继续录入新数据 |
| 老师反映"AI 助手"进不去 | 没从教务系统顶栏进 | 必须点教务系统顶栏的「AI 助手」按钮，不要手输地址 |
