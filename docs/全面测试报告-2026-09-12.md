## 二、发现的缺陷与修复（全部已修复 + 复验通过）

### 🔴 F1 阻断：学生批量导入 100% 失败
- **位置**：`server/src/routes/students.js` import 路由
- **现象**：`INSERT` 语句 11 个占位符只传 9 个参数（漏 `source_channel`、`enroll_date`），每行都抛错被吞成笼统的「写入失败」。**200 行导入成功 0 行**。e2e 80 项断言未覆盖导入，属测试盲区。
- **修复**：补全参数并对齐 v9 新增列；失败原因精确化（UNIQUE → 「学号已存在」）。
- **复验**：200 行导入 64ms，成功 200 / 失败 0。

### 🟠 F2 高：考勤接口接受非法日期且照常扣课时
- **位置**：`POST /api/attendance/batch`
- **现象**：`date="2026-99-99"` / `"xxxx-xx-xx"` 均返回 200 并**真实扣减课时**，落库不可排序的垃圾日期。
- **修复**：新增共享校验模块 `server/src/utils/validate.js`（parseDate 严格校验「格式 + 真实存在 + 年份范围」），考勤批量接口强制校验，非法日期一律 400 且课时不动（6 种异常形态逐一复验）。

### 🟠 F3 高：数据库约束错误统一返回 500
- **位置**：`server/src/index.js` 全局错误中间件
- **现象**：外键不存在（如给不存在的学生建订单）→ `FOREIGN KEY constraint failed` → 500。语义错误（客户端问题）被报成服务器故障，干扰监控与排障。
- **修复**：错误中间件识别约束类错误 → 400 + 可读中文提示（不泄露表名列名）。

### 🟡 F4 中：销假回补在课时耗尽时失败（原 H10，上轮延后项）
- **位置**：`server/src/routes/leaves.js` 审批联动
- **现象**：回补查询带 `remain_hours > 0`，学员最后一课时被扣至 0 后销假 → 查不到订单 → 考勤已改「请假」但课时永久丢失。
- **修复**：去掉 `remain_hours > 0` 条件（与考勤扣课时侧口径一致）。
- **复验**：remain 1 → 考勤扣至 0 → 审批通过回补至 1 ✅。

### 🟡 F5 中：12 处服务端输入校验缺失
- 考试 `exam_date` 任意字符串、`full_score` 可负数；班级/课程名称、公告标题无长度上限（可写 400 字符）；订单 `enroll_date`、缴费 `pay_time` 无格式校验。
- **修复**：统一走 `validate.js` 收口（exams/classes/courses/notices/finance 共 5 个路由 9 个端点）。
- **复验**：校验缺口扫描 **12 → 0**。

### 🔧 D1 部署缺陷：后端容器非 root 运行导致启动失败
- **现象**：上一轮加固加的 `USER node`（uid 1000）无法写入 Windows bind mount 的 `./server/data`（属主 root）→ `attempt to write a readonly database`，容器 unhealthy。**若未测部署直接上线即事故**。
- **修复**：回退 `USER node`（Windows Docker Desktop bind mount 下不可行），保留其他加固。已记录为部署约束。

## 六、已知低优先级项（不阻断上线，建议 go-live 后处理）

1. **越权访问渲染 404 页而非 403 页**（前端路由守卫）：功能 fail-closed 正确、无数据泄露，仅 UI 一致性瑕疵。
2. **考勤改状态不回补课时**：upsert 把「正常」改为「缺勤」时，已扣课时不自动回补。业务上属「老师改考勤」的边界口径，建议产品确认后决策。
3. 前端主包体积可按 pure-admin 指南做路由级分包（优化项）。
4. H9（明文默认口令散布文档/脚本）、H14（`xlsx` CVE）、H12（前端 397 处 any）等原 Gate 3 延后项维持原计划。
