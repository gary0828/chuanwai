# 前端视觉规范（2026-09-18）

> 本文是**全站视觉的唯一人类可读规范**。代码层面的唯一权威源是 `src/style/tokens.scss`。
> 新增或修改任何页面前请先读本文；设计意图（为什么这么设计）见根目录 `.impeccable.md`。

---

## 一、设计方向

**「教务台」**——参考纸质成绩单与教务档案的秩序感：结构清晰、边界精确、数字成列对齐、没有一处多余装饰。

- 定位：培训机构员工端 CRM（admin / teacher），**台式机为主、平板并重**
- 主色：深靛蓝 `#1F5C99`（替换 Element 出厂 `#409EFF`：前者是机构信赖感，后者是通用科技产品）
- 差异化记忆点：**让「看数字」本身成为视觉特征**——表格只有横线无竖线、人数与金额右对齐且逐位对齐

### 反参考（明确不要）

- ❌ 通用 Element 出厂皮肤（默认蓝、糖果色标签、圆角 + 通用阴影的卡片）
- ❌ AI 模板特征：青紫渐变、发光边框、毛玻璃堆叠、等宽字体硬凑「技术感」
- ❌ 大数据屏式深色霓虹、英雄指标大数字铺满首屏
- ❌ 大圆角（12px+）+ 卡片套卡片
- ❌ 空状态只写「暂无数据」

## 二、三层样式架构（改样式前必读）

| 文件 | 职责 | 加载位置 |
| --- | --- | --- |
| `src/style/tokens.scss` | **唯一变量源**：色阶 / 字号 / 间距 / 圆角 / 阴影 / 动效 / 字体栈；含深色模式全套取值 | `index.scss` 首条 `@use`（最先） |
| `src/style/page.scss` | 页面级视觉语法工具类 `.app-page` / `.page-card` / `.stat-card` / `.num` 等 | `index.scss` |
| `src/style/element-plus-override.scss` | **Element Plus 组件视觉重定义** | `main.ts`，**必须晚于 `element-plus/dist/index.css`** |

### ⚠️ 三条硬性约束

1. **`element-plus-override.scss` 的引入位置不能挪**。Element 官方规则与本文件大多同特异性，本文件靠「后加载」取胜；一旦挪到官方样式之前，规则会被覆盖，只能靠堆 `!important` 补救。
2. **变量覆盖用 `html:root` 而非 `:root`**。Element 在 `:root` 定义变量，`html:root`（特异性 0,1,1 > 0,1,0）可稳定覆盖且不受加载顺序影响；深色覆盖用 `html.dark:root`。
3. **页面内禁止硬编码色值 / 阴影 / 圆角 / 动效时长**。一律引用 `tokens.scss` 的变量。出现 `#xxxxxx` 即为缺陷。

## 三、Token 规格

### 品牌色阶（深靛蓝）

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--brand-600` | `#1f5c99` | 基准色 = `--el-color-primary`（由 `platform-config.json` 的 `EpThemeColor` 注入） |
| `--brand-500` | `#2a6eae` | hover |
| `--brand-700` | `#17456f` | active / 选中文字 |
| `--brand-100` | `#e8f0f8` | 浅底（选中行、Tag 背景） |
| `--brand-50` | `#f2f7fb` | 极浅底（行 hover、说明条） |

### 中性色阶（冷灰，向品牌色微偏）

`--ink-900` 主标题 → `--ink-50` 页面底 / 行 hover。**语义是「前景色阶」**：900 = 与背景对比最强。深色模式下整体反转，`--ink-900` 变成最亮的文字色。

### 语义状态色（去糖果化）

| 变量 | 浅色 | 含义 |
| --- | --- | --- |
| `--status-success` | `#2e7d5b` | 正常 / 已通过 / 在读 |
| `--status-warning` | `#b7791f` | 迟到 / 早退 / 待处理 |
| `--status-danger` | `#b3453c` | 缺勤 / 驳回 / 异常 |
| `--status-info` | `#64798a` | 请假 / 中性态 |
| `--finance-up` / `--finance-down` | 红 / 绿 | **中国约定：涨为红、跌为绿** |

### 排版

- 中文系统字体栈，**不引入 Web 字体**（中文子集动辄数 MB，不划算）
- **`font-variant-numeric: tabular-nums` 已在 `html` 上全局开启** —— 数字天然逐位对齐，无需逐元素声明
- 字号阶梯：`--text-xs` 12 / `--text-sm` 13 / `--text-base` 14（正文基准）/ `--text-md` 16 / `--text-lg` 20（页面标题）/ `--text-xl` 26（关键指标）/ `--text-2xl` 32

### 间距 / 圆角 / 阴影 / 动效

- 间距：4px 基数，`--space-1`(4) ~ `--space-12`(48)
- 圆角：`--radius-xs`(3) / `--radius-sm`(5) / `--radius-md`(7) / `--radius-lg`(10) / `--radius-pill`
- 阴影：`--shadow-xs` ~ `--shadow-lg`。**克制使用**：卡片默认无阴影，边界靠 1px 边框与留白；阴影只用于真正浮起的层级（弹窗、下拉）
- 动效：`--duration-fast`(120ms) / `--duration-base`(180ms)；缓动 `--ease-out` / `--ease-out-expo`。**只动 `opacity` / `transform` / 颜色**，不动布局属性

## 四、页面骨架（新增页面的标准写法）

```vue
<template>
  <div class="app-page">
    <AppPageHeader title="班级管理" description="班级、班主任与在读人数">
      <!-- 主操作放页头右侧 -->
      <el-button type="primary" :icon="PlusIcon" @click="openAdd">新增班级</el-button>
    </AppPageHeader>

    <!-- 表格/列表用 flush（内边距归零，表格与卡片边界贴合） -->
    <div class="page-card page-card--flush">
      <div class="page-toolbar">
        <el-input v-model="keyword" placeholder="搜索" class="!w-56" />
        <el-button type="primary" @click="search">搜索</el-button>
      </div>

      <el-table :data="list" border stripe>
        <!-- 数字列右对齐并加 .num -->
        <el-table-column label="在读人数" width="110" align="right">
          <template #default="{ row }">
            <span class="num">{{ row.student_count }}</span>
          </template>
        </el-table-column>

        <template #empty>
          <AppEmpty title="还没有班级" description="新增班级后，学生、课表与考勤都会挂在班级下" />
        </template>
      </el-table>

      <div class="page-card__footer">
        <el-pagination ... />
      </div>
    </div>

    <!-- 弹窗宽度必须能容纳窄屏 -->
    <el-dialog v-model="visible" title="新增班级" width="min(480px, calc(100vw - 32px))" />
  </div>
</template>
```

### 可用工具类

| 类名 | 用途 |
| --- | --- |
| `.app-page` | 页面根容器（统一内边距 + 响应式收缩） |
| `.page-card` / `.page-card--flush` | 内容卡片（细边框、无阴影、圆角 7px） |
| `.page-toolbar` / `.page-toolbar__spacer` | 筛选与操作条（`__spacer` 用于把主操作推到右侧） |
| `.page-card__footer` | 卡片底部（分页 / 汇总行，右对齐 + 顶部分隔线） |
| `.card-head` | 卡片内区块标题 |
| `.stat-grid` / `.stat-card(--brand/--success/--warning/--danger)` | 自适应指标卡（左侧语义色条） |
| `.metric-value` / `.metric-label` / `.num` | 数据排版（关键指标 / 标签 / 等宽数字） |
| `.chart-grid` / `.chart-box` | 图表布局（窄屏自动堆叠） |
| `.page-hint` | 辅助说明小字 |

### 页面级组件

- **`AppPageHeader`**（`@/components/AppPageHeader`）：`title` + `description` + 默认 slot（主操作）+ `meta` slot（徽标）
- **`AppEmpty`**（`@/components/AppEmpty`）：`title` + `description` + `icon`（传 `~icons/ep/xxx`）+ 默认 slot（操作）
  - 文案要求：`title` 说清「为什么空」，`description` 说清「下一步做什么」

> 两个组件遵循项目既有约定：`withInstall` 包装、**页面显式 import**（与 `ReImageVerify` / `ReText` 一致）。
> 若要全局注册，还需在 `types/global-components.d.ts` 的 `GlobalComponents` 声明，否则 Volar 无类型提示。

## 五、响应式策略

| 断点 | 场景 | 主要行为 |
| --- | --- | --- |
| > 1200px | 桌面 | 侧边栏展开（210px） |
| 761 ~ 1200px | 平板横屏 / 小笔记本 | **侧边栏自动折叠（54px）**，横向空间优先让给内容 |
| 641 ~ 760px | 平板竖屏 / 大手机 | 侧边栏隐藏（抽屉式） |
| ≤ 640px | 手机 | 页面内边距收窄；弹窗宽度强制 ≤ `100vw - 24px` |

平板是一等公民的具体落实：
- 表格行高 44px、按钮小尺寸 ≥ 28px（触控热区）
- `.stat-grid` / `.chart-grid` 用 `auto-fit + minmax`，容器多宽就铺几列，无需逐尺寸写断点
- 侧边栏折叠阈值在 `src/layout/index.vue` 的 `useResizeObserver` 内（**不要单独改某一处的数字**）

## 七、登录页背景：教务格栅（2026-09-18 晚新增）

登录页是全站唯一**没有数据**的页面，所以它的背景要替系统说话。

**方案**：全屏对称的两级坐标格栅。

- 主格 128px（`color-mix(in srgb, var(--brand-600) 13%, transparent)`）
- 次格 32px（同色 6%）
- 径向遮罩让中心 38% 完全透明 —— 卡片与品牌文字周围不留任何线条干扰
- 深色模式改用 `--brand-400` 并提高透明度（底色暗，线色需提亮才可见）

**为什么它能与全站协调**：系统其余 34 个页面的共同视觉语言是「浅灰底 + 白卡 + 只有横线的表格」，本质是**规则线条**。格栅正是把这一语言抽象到背景层 —— 主格对应页面分区层级，次格对应表格行线。同时底色直接取 `--surface-page`，卡片规格直接对齐 `.page-card`（1px 边框 / 10px 圆角 / 无重阴影 / 白底），因此登录页与内页用的是同一套物料。

**对称性**：品牌 → 卡片 → 页脚 三者同轴居中，实测 5 个视口（1680/1440/1280/1024/768）偏差均为 **0.0px**。
此前是「左品牌深色块 + 右表单」的左右分栏 —— 深色块占左侧 42%，是全站唯一的深色区域，既导致不对称（视觉重心偏左，而卡片在右侧居中），也是"不统一"的根源，已移除。

**实现位置**：`src/style/login.css`（背景与骨架）+ `src/views/login/index.vue`（结构）。
**验证脚本**：`_verify_test/ui-login-shots.py`（20 项：居中 / 同轴 / 格栅层数与遮罩 / 卡片规格）。
