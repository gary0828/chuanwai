# 项目约定（Conventions）

> 这是本项目的**长期记忆**：所有"踩过坑才懂"的硬规则都在这里。
>
> ★ 与 `docs/` 下其它文档的区别：
> - 这里的每**一条**都对应一次真实事故或一次用户纠正，不是泛泛的设计说明
> - 这些文件 **git 追踪**（`.workbuddy/memory/` 是 gitignore 的，不留存）
> - 需要时**按需读取**，不占用每次会话的注入额度

---

## 什么时候读哪个

| 我要做… | 读 |
|---|---|
| **新增/改动前端页面** | `01-前端两端差异.md`（**必读**，最容易踩） |
| 改后端 / 新建表 / 动数据库 | `02-后端与数据.md` |
| 改 nginx / docker / 部署 | `03-部署与nginx.md` |
| 任何"谁能看到什么"的改动 | `04-权限模型.md` |
| 写验证脚本 / 加断言 | `05-测试与验证.md` |
| 跑命令 / 推代码 / 环境诡异 | `06-环境坑与工具.md` |
| 判断"该不该做 / 该放哪" | `07-产品边界与AI.md` |
| 走一个功能的完整流程 | skill `feature-dev-flow`（调用才加载） |

## ★ 维护纪律（防止重新变胖）

1. **`.workbuddy/memory/MEMORY.md` 只放**：项目定位 + 流程门禁 + **指向本文档的索引**。
   新知识点一律写进这里，**不要**往 MEMORY.md 里堆细节。
2. **日志只记结论**：每条 ≤ 10 行（做了什么 / 决策 / 为什么 / 踩坑），过程细节不进日志。
3. **日志 30 天蒸馏**：有价值的蒸馏进本文档后**删除**原日志文件。
4. 发现本目录里某条**过时了**（如代码已改），**立刻改**，别留过期信息。

## 与既有文档的关系

本目录**不重复**已有文档，只沉淀硬规则，并互相引用：

- `docs/PROGRESS.md` —— 已完成（不记待做）
