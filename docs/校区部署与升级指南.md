## 〇、先回答最关键的四个判断题

| 问题 | 结论 |
| --- | --- |
| **装在 PVE 的哪种环境里？** | **Ubuntu 24.04 虚拟机（VM）**。详见 §九 —— 这是本指南的推荐形态 |

| **升级会不会丢学员数据？** | **不会**，前提是**升级前先备份**。数据库迁移只做「加表 / 加列」，不做删除 |

## 一、合规与安全边界（**上线前必读**）

这一节解决「有独立公网 IP、没有域名，怎么做才不算违规」的问题。
系统里存着**学员姓名、手机号、考勤、成绩、财务**数据，其中大量属于**未成年人个人信息**，
受《个人信息保护法》《数据安全法》《未成年人保护法》约束，**不能当成一个普通网页挂到公网上去**。

### 1.1 端口：**别用 80 / 443**

| 事实 | 说明 |
| --- | --- |
| 80 / 443 需要 **ICP 备案** | 而备案的**前提是有域名**。你没有域名 → 这条路走不通 |
| 运营商 / 云商会**主动封禁**未备案的 80/443 | 典型症状：**内网能打开，外网打不开**，且不报错，极难排查 |
| 未备案对外提供 Web 服务属**违规** | 被查到要整改 |

> ✅ **正确做法**：对外映射一个**非标准高位端口**，推荐 **`18080`**（或 8443）。
> 端口号只是个数字，老师访问 `http://公网IP:18080` 体验上没有任何区别。
> **这是无域名场景下的标准解法。**
>
> 本项目的一键脚本已按这个口径默认使用 `18080`，你什么都不用改。

### 1.2 传输加密：三选一

学员信息走公网明文传输不合适。有域名时可以自动申请免费证书，纯 IP 下 Let's Encrypt **不给签**，所以有三个选择：

| 方案 | 成本 | 做法 | 适合谁 |
| --- | --- | --- | --- |
| **A · 内网为主 + VPN 拨入**（最稳） | 0 | 服务只在内网暴露，外网访问走 WireGuard / OpenVPN | 老师基本在固定几个地点办公 |
| B · 自签证书 | 0 | 自建 CA 并导入客户端信任 | 有 IT 能力、能逐台配客户端 |
| **C · 买个便宜域名**（最省事） | 几十元/年 | 有域名 → 免费证书 + 正常备案 → **合规一步到位** | 需要随时随地开网页 |

> **建议**：先按 **A** 用起来，投入最小、风险最低；如果确实需要随时随地访问，**C 是最省心的终局方案**，几十元换掉全部合规顾虑。
> 上 HTTPS 的详细步骤见 §十一。

### 1.3 安全底线清单（逐条确认）

| 项 | 要求 | 本项目的状态 |
| --- | --- | --- |
| 默认口令 | **上线后立即修改** `admin / admin123456`、`teacher / teacher123456` | 需你手动做（§九 第 8 步） |
| 登录图形验证码 | 生产环境保持开启 | ✅ 默认开启（`VITE_LOGIN_CAPTCHA=true`） |
| 登录失败限速 | 防暴力破解 | ✅ 已内置（`/api/auth/login` 独立限速） |
| 后端端口不对外 | **3000 绝不能暴露到公网** | ✅ 统一入口下后端只在 Docker 内网，`ufw` 也不放行 |
| 只放行必要端口 | 只开 SSH + 业务端口，其余全关 | ✅ 脚本自动配置 |
| 每日自动备份 | 数据库每日备份、保留 14 天 | ✅ 脚本自动配置（凌晨 3:00） |
| 数据不出网 | 调模型时只送**脱敏后的字段**（姓名/电话/金额不出网） | ✅ 后端白名单控制 |
| 密钥不进前端 | Key 只由服务端代持 | ✅ 严格遵守，前端无任何密钥入口 |
| 审计日志 | 关键操作留痕 | ✅ 已内置审计中间件 |

> **等保 2.0 提示**：如果机构后续要接政府 / 学校的合作项目，可能被要求做等保定级备案。
> 上面这套措施（最小化暴露面、加密传输、审计日志、定期备份、强口令）是等保的**基础项**，先做到位就不慌。

## 二、全新部署（目标机没有数据）

> 这一节是**通用流程**。如果你的目标是「PVE + Ubuntu 虚拟机」，可以直接跳到 **§九** —— 那里有完整的分步操作，并且第 4 步会调用本节提到的一键脚本。

### 最快的方式：一条命令（Linux 服务器）

如果你用的是 **Debian / Ubuntu 服务器**（含 PVE 里的虚拟机），项目已备好一键脚本：

```bash
sudo bash deploy/linux-server-setup.sh --llm-key sk-你的Key
```

它会自动完成：

1. 安装 Docker CE + Compose 插件
2. 配置国内镜像加速器
3. 生成 `.env`（**随机 JWT 密钥**，权限 600，不进仓库）
4. 启动「统一入口」编排（**对外只开一个端口**，默认 `18080`）
5. 等待服务就绪并自检
6. 配置 `ufw` 防火墙（**只放行 SSH 与业务端口**）
7. 配置**每日凌晨 3 点自动备份**（保留 14 天）

跑完后访问 `http://本机IP:18080` 即可。

**脚本参数：**

| 参数 | 作用 |
| --- | --- |
| `--llm-key sk-xxx` | 顺便写入 DeepSeek Key（也可以部署完在页面上填，见 §二 步骤 5） |
| `--web-port 18080` | 指定对外端口（默认已是 `18080`） |
| `--skip-mirror` | 跳过镜像加速器配置（网络本身畅通时用） |
| `-h` / `--help` | 查看用法 |

> 脚本是**幂等**的：重复执行安全，不会破坏已有数据。

### 如果用 Windows 机器（本机试跑 / 演示）

```bash
bash deploy.sh
```

它会：检查 Docker → 生成 `.env` → 优先用离线镜像包 → 启动（**三端口形态**）→ 等待就绪 → 打印访问地址。

> ⚠️ `deploy.sh` 用的是默认的 `docker-compose.yml`（**三端口**：8080 / 8082 / 3000），
> 适合本机演示；**正式对外部署请用 `docker-compose.unified.yml`（统一入口，只开一个端口）**。
> 原因见 §十。

### 路线选择（网络不通时的关键）

| 路线 | 要不要网络 | 什么时候用 |
| --- | --- | --- |
| **A · 离线镜像包** | ❌ **完全不需要** | **校区网络不确定时的首选** |
| B · 在线构建 | ✅ 要访问代码仓库 + npm 源 + Docker Hub | 网络畅通时最省事 |

#### 路线 A · 离线镜像包

**在已经跑起来的机器上导出一次：**

```bash
docker compose -f docker-compose.unified.yml build
docker save attendance-unified-unified attendance-server | gzip > attendance-offline.tar.gz
```

**目标机上**（U 盘拷过去）：

```bash
docker load -i attendance-offline.tar.gz     # 载入镜像
# 然后照常跑一键脚本（脚本检测到镜像已存在会直接用）
sudo bash deploy/linux-server-setup.sh
```

> `--no-build` 是关键：它不会联网下载任何东西。这条路线连 npm 源都不需要。

### 步骤 1 · 拷贝项目

**放到纯 ASCII 路径**（如 `/opt/jx-system`），**不要放中文目录**：

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/gary0828/chuanwai.git jx-system
cd jx-system
```

> 已有 `docs/` 里的代码仓库地址以实际为准（gitee 亦可）。

### 步骤 2 · 生成密钥（**必做**）

一键脚本会自动生成。**若要手工做**：

```bash
cd /opt/jx-system
echo "JWT_SECRET=$(openssl rand -hex 32)" > .env
echo "WEB_PORT=18080" >> .env
echo "AI_WORKBENCH_URL=http://localhost" >> .env
echo "AI_WORKBENCH_BASE_PATH=/ai" >> .env
chmod 600 .env
```

> 不设 `JWT_SECRET` 后端会**拒绝启动**（这是刻意的安全设计，且要求至少 16 位）。
> `.env` 已被 git 忽略，不会进仓库。

### 步骤 3 · 构建并启动

```bash
docker compose -f docker-compose.unified.yml up -d --build
```

> 若路径含中文导致构建报 gRPC 非 ASCII 错误，先手工构建三条镜像再 `up -d --no-build`。
> **最省事的办法就是别用中文路径。**

### 步骤 4 · 验证

```bash
docker compose -f docker-compose.unified.yml ps
curl -s http://127.0.0.1:18080/api/health              # {"success":true,"data":{"status":"ok"}}
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18080/      # 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18080/ai/   # 200
```

浏览器打开：

| 地址 | 用途 |
| --- | --- |
| `http://服务器IP:18080` | **教务系统**（老师日常用这个） |
| `http://服务器IP:18080/ai/` | AI 教学工作台（**从教务系统顶栏「AI 助手」进，不要手输地址**） |
| `http://服务器IP:18080/#/ai-admin` | AI 配置中心（填 Key 的地方） |

### 步骤 5 · 填大模型 Key（在页面上填，**不用改 .env**）

浏览器打开 **AI 配置中心**：`http://服务器IP:18080/#/ai-admin`

用 `admin` 登录后，在「大模型 API Key」一栏填入 Key，点保存 —— **立即生效，不用重启容器**。

> - 这个页面**不在任何菜单里**，只能凭地址进入；教师账号访问会被拒绝（403）。
> - 配置优先级：**页面填的值 > `.env` 里的 `LLM_API_KEY`**。
>   所以 `.env` 里的 Key 只是「页面上还没填」时的兜底，日常改 Key 一律在页面上改。
>   某一栏留空保存 = 清除该栏，回退到 `.env`。
> - 页面上有「账户可用余额」「本月用量」两张卡，Key 配对了就会显示真实数字。
>   **余额空白 = Key 没配对，或服务器出不了网。**
> - 内置镜像的 `.env` 由脚本生成，`LLM_MODEL` 默认 `deepseek-flash`。
>   **不要手改成 `deepseek-chat` —— 该模型已于 2026-07-24 停用**，当前可用的是 `deepseek-flash` / `deepseek-v4-pro`。

### 步骤 6 · 首次登录后必做

用 `admin / admin123456` 登录 → **立即改密码** → 全体教师账号也改 → 导入真实班级 / 学员 / 课程 / 课表。

## 三、带数据迁移（把现有学籍数据搬过去）

> 适用于「在别的机器已录入一部分真实数据，想原样搬到服务器」。

### ⚠️ 绝对不要直接 `cp attendance.db`

SQLite 运行在 **WAL 模式**下，除了 `attendance.db` 还有 `attendance.db-wal`（未合并的事务页）。
**只拷 db 文件 → 拷出来是损坏的**，症状是启动即崩：

```
Error: malformed database schema (92) / database disk image is malformed
```

### 正确做法 · 用内置脚本

**① 源机器上导出（不停机）**

```bash
bash server/scripts/backup-db.sh
# → server/data/attendance-20260921-2000.db （自包含单文件快照）
```

**② 把这一个文件拷到目标机**

放到目标机的 `server/data/` 目录下。

**③ 目标机上恢复**

```bash
bash server/scripts/restore-db.sh server/data/attendance-20260921-2000.db attendance-server -y
```

> 注意容器名：**统一入口形态**下后端容器名是 `attendance-server`；
> 三端口形态下是 `attendance-system-server`。用 `docker ps` 确认一下。

脚本会自动：停容器 → **隔离旧的 `-wal` / `-shm`** → 覆盖 db → 启容器 → 打印学员数与库版本。

**④ 复核**

```bash
curl http://127.0.0.1:18080/api/health
# 登录系统后核对：学员数、班级数、最近考勤是否与源机一致
```

> ⚠️ **Windows 服务器上的 SQLite bind mount 有缓存**，恢复完数据后建议重启一次容器：
> ```bash
> docker restart attendance-server
> ```

> 备份/恢复脚本已在本机**真机演练通过**：备份 → 恢复 → `PRAGMA integrity_check = ok` → e2e 80/80。

## 四、后续升级（换新版本）

### 原理：为什么不会丢数据

```
┌─ 镜像（每次升级被替换）──┐   ┌─ 数据卷（永远不动）────────┐
│ 后端代码 / 前端页面       │   │ server/data/attendance.db  │
│ 重建会丢，但没关系        │   │ 学员 / 考勤 / 财务 / 反馈  │
└──────────────────────────┘   └────────────────────────────┘
```

compose 文件里 `- ./server/data:/app/data` 这行就是数据保命符。

### 升级五步法（停机约 10–20 秒）

```bash
# ① 备份（最重要，永远第一步）
bash server/scripts/backup-db.sh

# ② 拉新代码
git pull

# ③ 重建并起新容器（会自动执行数据库迁移，旧数据原地保留）
docker compose -f docker-compose.unified.yml up -d --build --force-recreate

# ④ 验证
curl http://127.0.0.1:18080/api/health
BASE=http://127.0.0.1:18080 node server/scripts/e2e-lifecycle.mjs   # 应 PASS 80 / FAIL 0

# ⑤ 确认无误后清理旧镜像
docker image prune -f
```

> 容器启动时 **`PRAGMA user_version` 会自动比对并逐级跑迁移**。
> 迁移**只做「加表 / 加列」，不会删数据**。**迁移版本号跳号会导致启动终止**，所以升级时不要手改迁移文件。

### 开窗建议

选**课间或放学后**执行，全程 < 1 分钟。老师正在点名时不要升级。

## 五、回滚方案

数据库迁移是**单向**的（新版本代码可能依赖新列），降级必须同时还原程序与数据：

```bash
# ① 停服务
docker compose -f docker-compose.unified.yml stop server

# ② 还原数据（用升级前那份备份）
bash server/scripts/restore-db.sh server/data/attendance-<升级前时间戳>.db attendance-server -y

# ③ 回滚程序
git checkout <旧版本 commit>
docker compose -f docker-compose.unified.yml up -d --build
```

> 因此**升级前的备份文件请保留到确认新版本稳定运行之后**再删。

### 交付给客户前：恢复出厂状态

```bash
node server/scripts/reset-production-data.mjs            # 先预览会清什么
node server/scripts/reset-production-data.mjs --confirm  # 确认后执行
```

- 清空**全部**业务数据（学员、班级、课程、考勤、成绩、财务、线索、通知、审计日志…），**只保留 admin 一个账号**
- 保留 `terms`（当前学期）与 `settings`（系统配置）—— 签到等功能依赖当前学期，清掉会导致系统不可用
- 执行前**自动备份**，且默认只预览不执行，必须显式 `--confirm`
- 自增 ID 归零，新数据从 1 开始

> 教师账号让客户自己建。默认密码 `admin123456` 也要提醒客户**首次登录后立即修改**。

### Linux 服务器上的备份位置

一键脚本已配置好：**每天凌晨 3:00** 备份到 `/var/backups/jx-system`，**自动删除 14 天前**的备份。

```bash
# 手动立刻备份一次
/usr/local/bin/jx-backup.sh

# 查看备份清单
ls -lh /var/backups/jx-system

# 从备份恢复
tar -xzf /var/backups/jx-system/data-2026-09-21-0300.tar.gz -C /opt/jx-system
```

> ★ **备份范围是整个 `server/data/` 目录**，不只 `attendance.db`。
> 未来启用 AI 产出层后，生成的 PDF / PPT / 试卷等文件会存在 `server/data/assets/` 下（见 [[ADR-008-数据资产化与AI产出层架构]]），**只备份 db 会把文件全丢掉**。当前脚本已按整目录打包，无需改动。

## 七、上线后常见故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端起不来，日志写 `missing JWT_SECRET` | `.env` 没配密钥 | 重跑一键脚本，或手工生成（§二 步骤 2） |
| 启动即崩，`malformed database schema` | 直接 cp 了 db 没处理 WAL | 隔离 `-wal`/`-shm` 后用脚本恢复（§三） |
| **内网能开、外网打不开** | ① 路由器/安全组没做端口映射 ② **用了 80/443 被运营商封** | ① 检查映射规则（§九 第 7 步）② **改用 18080 高位端口** |
| 构建报 gRPC 非 ASCII 错误 | 项目在中文目录 | 移到 `/opt/jx-system` 这类 ASCII 路径 |
| 打开首页白屏 | 前端未重建 | `docker compose -f docker-compose.unified.yml up -d --build` |
| 工作台显示「演示身份」 | 没从教务系统入口进 | 必须走教务系统顶栏「AI 助手」按钮 |
| 工作台显示「未配置模型」 | Key 没填 / 填错 / 服务器出不了网 | 到 `/#/ai-admin` 检查，看「余额」卡是否有数字 |
| AI 生成内容空白 | 关了 `LLM_REASONING_EFFORT=none` 或额度太小 | 保持 `LLM_REASONING_EFFORT=none` |
| AI 报模型不存在 | 模型名写成已停用的 `deepseek-chat` | 改成 `deepseek-flash` 或 `deepseek-v4-pro` |
| 页面上改了 Key 不生效 | —— | **改完立即生效，无需重启**；若不生效，确认是不是填到了 `.env` 而页面覆盖了它 |
| 数据恢复后读到的还是旧数据 | Windows bind mount 缓存 | `docker restart attendance-server` |

## 九、PVE 服务器 + 独立公网 IP + Ubuntu 虚拟机（**推荐形态**）

> 编写日期：2026-09-21 ｜ 适用：**已装 PVE、有独立公网 IP、暂不申请域名、希望用 Ubuntu**
> 这是**当前推荐的正式部署形态**，一次配好，外网与局域网都能用。

### 9.1 先做决策：装在 PVE 里的哪种环境？

| 方案 | 说明 | 推荐度 |
| --- | --- | --- |
| **A · Ubuntu 虚拟机（VM）** | PVE 里建 **Ubuntu 24.04 LTS** 虚拟机，虚拟机内装 Docker | ⭐⭐⭐⭐⭐ **本指南采用** |
| B · Debian LXC 容器 | 开销更小，但**必须开 `nesting=1`**，且容器里不是真正的 Ubuntu | ⭐⭐⭐ |
| C · PVE 宿主机直接装 | 不推荐：PVE 宿主机是" appliances "，装 Docker 会与 iptables / cgroup 管理冲突 | ⭐ |

**为什么选虚拟机而不是 LXC（4 条理由）：**

1. **你需要的 Ubuntu 生态** —— LXC 容器里跑的不是真正 Ubuntu 内核，想用的东西未必装得上。
2. **Docker 原生运行** —— LXC 里 Docker 必须开 `nesting=1`，还常撞 AppArmor / cgroup 权限问题；虚拟机里零特殊配置。
3. **快照 / 备份更成熟** —— PVE 对 VM 的快照支持远好于 LXC，出问题**几秒钟回滚**。
4. **数据更安全** —— SQLite 的 WAL 锁对文件系统敏感，虚拟机原生 ext4/xfs 比 LXC 的 overlay 层更稳。

> 代价只是资源开销略大（LXC 2 核 / 2 GB vs VM 4 核 / 4 GB），
> 对「5–15 员工、200–500 学员」的负载来说**完全无感**。这个代价换来的是稳定性与省心，值。

### 9.2 虚拟机规格建议

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 系统 | **Ubuntu Server 24.04 LTS**（或 22.04 LTS） | 选 **Server 版**，不需要桌面 |
| CPU | **2–4 vCPU**，类型 **`host`** | 构建镜像时吃 CPU，构建完就闲了 |
| 内存 | **4 GB**（最低 2 GB） | 3 个容器 + 构建峰值；**给 2 GB 构建时可能 OOM** |
| 磁盘 | **32 GB**，总线 **`virtio-scsi`** | 镜像 + 日志 + 备份留余量 |
| 网卡 | **`virtio`**，桥接 `vmbr0`，**静态内网 IP** | 例 `192.168.1.50/24`，网关 `192.168.1.1` |
| 磁盘缓存 | `Write back` | PVE 默认值即可 |
| 引导 | `SeaBIOS`（默认） | 无需 UEFI |

### 9.3 完整步骤（从零到外网可访问）

#### 第 1 步 · 在 PVE 里创建 Ubuntu 虚拟机

**① 准备 ISO**

PVE 界面 → `local` → `ISO 镜像` → `从 URL 下载`，填 Ubuntu Server 24.04 LTS 的 ISO 地址；
或本地下载后点 `上传`。

**② 创建虚拟机**

PVE 界面右上角 → `创建 VM`，按下表填写：

| 页签 | 设置 |
| --- | --- |
| 常规 | 名称 `jx-ubuntu`，VM ID 用默认（如 `100`） |
| 操作系统 | 存储选 `local`，ISO 选刚下载的 Ubuntu Server ISO，类型 `Linux`，版本 `6.x - 2.6 Kernel` |
| 系统 | 默认（`SeaBIOS` + `virtio-scsi`） |
| 磁盘 | 总线 `SCSI`，存储 `local-lvm`，大小 **32 GB** |
| CPU | 类型 **`host`**，核心 **4** |
| 内存 | **4096 MB** |
| 网络 | 桥接 `vmbr0`，模型 **`VirtIO (半虚拟化)`** |

> 创建后先**别急着启动**，若磁盘缓存需要调整：选中 VM → `硬件` → `硬盘` → `编辑` → 缓存 `Write back`。

**③ 安装 Ubuntu**

启动 VM → 控制台进入安装程序：

- 语言选 English（中文可能显示为方块，装完再改）
- 网络：**选静态 IP**（Manual），填：
  - IP：`192.168.1.50/24`
  - 网关：`192.168.1.1`
  - DNS：`223.5.5.5`（阿里公共 DNS，比默认稳）
- 存储：选 `Use an entire disk`，**勾选 LVM**（方便以后扩盘）
- **务必勾选 `Install OpenSSH server`**（不然后面没法远程连）
- 用户名任意（如 `admin`），密码记牢

> 安装约 10–20 分钟，视磁盘性能而定。

**④ 首次登录并更新系统**

```bash
ssh admin@192.168.1.50

# 换国内源加速（可选，24.04 是 noble）
sudo sed -i 's|//archive.ubuntu.com|//mirrors.aliyun.com|g; s|//security.ubuntu.com|//mirrors.aliyun.com|g' /etc/apt/sources.list.d/ubuntu.sources 2>/dev/null || true
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git openssl ufw
```

**⑤ 安装 QEMU Guest Agent（PVE 常驻必做）**

```bash
sudo apt install -y qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent
```

> 装完后在 PVE 界面选中 VM → `选项` → 开启 `QEMU Guest Agent`。
> 这样 PVE 才能读到虚拟机的真实 IP、并在关机时正确通知系统。

#### 第 2 步 · 设置 PVE 开机自启

选中 VM → `选项` → `开机自启动` → 设为 **`是`**，启动顺序 `order=1`，延迟 `10`。

> 这样 PVE 宿主机重启（比如机房断电恢复）后，系统会**自动跟着起来**，不用人工干预。

#### 第 3 步 · 创建虚拟机快照（装机后立刻做一次）

选中 VM → `快照` → `现在拍摄快照`，名称填 `初始干净系统`。

> 这是**兜底保险**：后面不管怎么折腾坏了，都能一键回滚到这个干净状态。

#### 第 4 步 · 放代码 + 一键部署

```bash
# 放到纯 ASCII 路径（中文目录会让 Docker 构建失败）
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/gary0828/chuanwai.git jx-system
sudo chown -R $USER:$USER /opt/jx-system

cd /opt/jx-system
sudo bash deploy/linux-server-setup.sh --llm-key sk-你的DeepSeekKey
```

> **没有 Key 也没关系**：Key 可以后面在「AI 配置中心」页面上填（§二 步骤 5）。
> 不带 Key 时工作台会走**规则引擎降级模式**，功能可用、零出网。

这条脚本会自动完成装 Docker、配镜像加速、生成密钥、构建启动、开防火墙、配每日备份。
**首次构建约 3–8 分钟**，取决于网络。

#### 第 5 步 · 本机验证

```bash
cd /opt/jx-system
docker compose -f docker-compose.unified.yml ps
curl -s http://127.0.0.1:18080/api/health
```

看到 `{"success":true,"data":{"status":"ok"}}` 即成功。

#### 第 6 步 · PVE 防火墙放行

① PVE 宿主机：`数据中心` → `防火墙` → `添加` → 方向 `in`，动作 `ACCEPT`，协议 `tcp`，端口 **`18080`**
② 确认 VM 所在的网桥 `vmbr0` 未被整体拦截

> **如果你没启用 PVE 的防火墙，可以跳过这一步**（默认是关闭的）。

#### 第 7 步 · 路由器 / 安全组做端口映射（**外网访问的关键**）

在**路由器**里添加端口转发规则：

| 项 | 值 |
| --- | --- |
| 外部端口 | **18080** |
| 内部地址 | `192.168.1.50` |
| 内部端口 | **18080** |
| 协议 | TCP |

> ⚠️ **不要映射 80 / 443** —— 那是需要 ICP 备案的端口，无域名用不了（原因见 §一）。
> 如果你用的是云服务器而非家宽，则改在**云控制台的「安全组」**里放行 `18080/tcp`。

#### 第 8 步 · 外网验证

用**手机 4G/5G 流量**（不要连 WiFi，才是真正的外网）访问：

```
http://<你的公网IP>:18080
```

能打开登录页 → **外网打通**。再让手机连内网 WiFi 访问同一地址，也能开 → **内外网都通**。

#### 第 9 步 · 上线收尾（**必做**）

1. `admin / admin123456` 登录 → **立刻改密码**
2. 让全体教师登录并改掉 `teacher123456`
3. 到 `http://公网IP:18080/#/ai-admin` 确认 AI 已生效（余额卡有数字）
4. 确认每日备份已在跑：`ls -lh /var/backups/jx-system`

### 9.4 补充：LXC 方案（备选，如果你想省资源）

如果你最终决定用 LXC 而不是虚拟机：

- 模板选 `debian-12-standard`，磁盘 32 GB、内存 2048 MB、核心 2
- 网络桥接 `vmbr0`，静态 IP
- **✅ 必须勾选 `嵌套`（nesting）** —— 否则 Docker 起不来

```bash
# 或命令行开启嵌套
pct set <CTID> -features nesting=1
# 改完重启容器
pct reboot <CTID>
```

后面第 4–9 步与虚拟机完全一致（同样是 `sudo bash deploy/linux-server-setup.sh`）。

> ⚠️ **LXC 的已知麻烦**：AppArmor / cgroup 权限问题偶发；
> 若仍起不来 Docker，可临时勾 `unprivileged=0`（安全性略降，内网可接受）。
> **这也是本指南推荐虚拟机的原因。**

### 9.5 PVE 环境特别注意

| 事项 | 说明 |
| --- | --- |
| **磁盘别用 NFS / CIFS** | SQLite 在 NFS 上锁行为异常，会导致 `database is locked`。请用本地存储（`local-lvm`） |
| **定时快照** | PVE → VM → `快照` → 建每周定时快照（比只靠 Docker 备份更省心） |
| **别把 Docker 装在 PVE 宿主机** | 会与 PVE 的 iptables / cgroup 管理冲突 |
| **磁盘空间监控** | 快照会持续占用空间；PVE → VM → `快照` 定期清理旧的 |
| **公网 IP 变化** | 家宽的公网 IP **可能是动态的**。若 IP 变了，映射规则通常不用改，但老师收藏的地址会失效 —— 解决办法是买域名（§一 方案 C） |
| **电费与散热** | 长期运行的服务器建议放在通风处，并接 UPS（断电会让 SQLite 有极小概率损坏） |

## 十、为什么必须用「统一入口」而不是三个端口

老师报过的「**AI 工作台点击无法进入**」，根因就在"多端口"形态：

| 形态 | 老师的访问地址 | 「AI 助手」跳转 | 结果 |
| --- | --- | --- | --- |
| 三端口 | `http://公网IP:18080` | 跳到 `http://公网IP:8082` | 要额外放行 8082；若配成 `localhost:8082` 则**必挂** |
| 三端口 + HTTPS | `https://域名` | 跳到 `http://域名:8082` | **协议降级 + 错端口，必挂** |
| ✅ **统一入口** | `http://公网IP:18080` | 跳到 `http://公网IP:18080/ai/` | **天然正确** |

**原理**：统一入口下，「AI 助手」的跳转地址 = **访问者当前正在访问的 origin**（协议 + 主机 + 端口全部跟随），所以：

- 内网老师用 `http://192.168.1.50:18080` 访问 → 跳到 `http://192.168.1.50:18080/ai/` ✅
- 外网老师用 `http://公网IP:18080` 访问 → 跳到 `http://公网IP:18080/ai/` ✅
- 以后上了域名 + HTTPS → 跳到 `https://域名/ai/` ✅ **不用改任何配置**

> 代码层已经做到：当 `AI_WORKBENCH_URL` 配成**回环地址**（`localhost` / `127.0.0.1` / `::1` / `0.0.0.0`）时，
> 后端自动替换为访问者 origin，并补上 `/ai` 子路径（`AI_WORKBENCH_BASE_PATH`）。
> 因此 `docker-compose.unified.yml` 里故意把 `AI_WORKBENCH_URL` 配成 `http://localhost`。
>
> **判据**：`AI_WORKBENCH_BASE_PATH` 非空 = 同源部署（跟随完整 origin）；
> 为空 = 独立端口部署（只跟随 hostname，保留配置的端口）。

## 十一、后期加 HTTPS（有了域名之后）

教务系统里有**学员姓名、手机号、考勤、财务**数据，走公网最好加密。
**前提：你需要一个域名**（纯 IP 拿不到免费证书）。

### 步骤 1 · 域名解析

在域名服务商处添加 A 记录：`jx.你的域名.com` → `你的公网IP`。

### 步骤 2 · 把统一入口端口改回内网端口

编辑 `.env`，把对外端口改成 `8080`（由 Caddy 对外提供 80/443）：

```bash
cd /opt/jx-system
sed -i 's/^WEB_PORT=.*/WEB_PORT=8080/' .env
docker compose -f docker-compose.unified.yml up -d
```

### 步骤 3 · 装 Caddy 并配置

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

编辑 `/etc/caddy/Caddyfile`：

```
jx.你的域名.com {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy
```

Caddy 会自动申请并续期 Let's Encrypt 证书，**且原样透传 `Host` 头**，
所以「AI 助手」跳转会正确变成 `https://jx.你的域名.com/ai/`，**无需改任何应用配置**。

### 步骤 4 · 放行端口

- 路由器 / 安全组放行 **80 与 443**（有了域名并完成备案后才可用）
- 把原来的 `18080` 映射**关掉**（减少暴露面）

> ⚠️ **备案提示**：用域名 + 80/443 对外提供服务，**必须先完成 ICP 备案**。
> 这是上了域名之后必须走的一步（通常 7–20 个工作日）。
