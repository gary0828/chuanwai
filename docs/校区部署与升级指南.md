## 〇、先回答最关键的三个判断题

| 问题 | 结论 |
| --- | --- |
| **Dify 必须部署吗？** | **现在不需要。** 当前 AI 能力全部走「工作台 → 教务后端 → DeepSeek」，不经过 Dify。Dify 只在你要做**知识库问答 / 多步 Agent / 工作流编排**时才需要。先不装可省 15 个容器、约 2.2 GB 内存 |
| **能热更新吗？** | **不能热打补丁，但换新版本不丢数据。** 数据与镜像是解耦的（数据在 `server/data/`，代码在镜像里），换镜像只影响程序，不动数据 |
| **升级会不会丢学员数据？** | **不会**，前提是**升级前先备份**。数据库迁移只做「加表 / 加列」，不做删除；实测 v15→v16 升级后 29 名学员、86 条考勤一条不丢 |

## 二、全新部署（目标机没有数据）

### 最快的方式：一条命令

项目根目录已经准备好了 `deploy.sh`。**装好 Docker Desktop 之后，只要跑这一条**：

```bash
bash deploy.sh
```

它会自动完成：检查 Docker → 生成 `.env`（JWT 密钥随机生成，不用手工填）→ 准备镜像（**优先用离线包，不联网**）→ 启动 → 等待就绪 → 打印访问地址。

最后会输出类似这样的信息，直接告诉老师们用哪个地址：

```
  本机访问：        http://localhost:8080
  同局域网其他电脑：http://192.168.1.20:8080
  AI 配置中心：    http://localhost:8080/#/ai-admin
```

> ⚠️ **务必让老师用 IP 地址访问**，不要用 `localhost`。
> 「AI 助手」按钮会自动跟随访问者所用的主机，跳到同一台机器上的工作台，不会再出现打不开的情况。

### 路线选择（先看这个，选错会卡在网络上）

| 路线 | 要不要网络 | 什么时候用 |
| --- | --- | --- |
| **A · 离线镜像包** | ❌ **完全不需要** | **校区网络不确定时的首选** |
| B · 在线克隆构建 | ✅ 要访问 Gitee/GitHub + npm 源 + Docker Hub | 网络畅通时最省事 |

#### 路线 A · 离线镜像包（推荐）

**在已经跑起来的机器上导出一次**（本项目已导出：`attendance-offline-images-20260914.tar.gz`，约 **84 MB**）：

```bash
docker save attendance-system-server attendance-system-web attendance-system-ai-workbench | gzip > attendance-offline-images.tar.gz
```

**目标机上**（U 盘拷过去即可，三个文件：项目目录 + 镜像包 + 备份的数据库）：

```bash
docker load -i attendance-offline-images.tar.gz     # 载入镜像，10 秒左右
cp .env.example .env                                 # 编辑写 JWT_SECRET（见步骤 2）
docker compose up -d --no-build                      # 直接用已载入的镜像，不构建
```

> `--no-build` 是关键：它不会联网去下载任何东西。
> 这条路线连 npm 源都不需要，**只要 Docker Desktop 装上了就能跑**。

#### 路线 B · 在线克隆构建

按下面步骤 1–4 走，构建过程会联网拉取依赖（Dockerfile 已配 npmmirror 国内源）。

### 步骤 1 · 拷贝项目

把整个项目目录拷到目标机（**不要拷 `server/data/` 的数据库文件**，让它自动初始化）：

```bash
# 在本机执行：导出代码（不含数据与密钥）
git clone https://github.com/gary0828/chuanwai.git D:/jx-system
# 或用 U 盘拷贝后删除 server\data\*.db*
```

### 步骤 2 · 生成密钥（**必做**）

进入项目根目录，创建 `.env`：

```bash
cd D:/jx-system
cp .env.example .env
```

然后编辑 `.env`，至少写一行：

```bash
JWT_SECRET=用下面命令生成的一串64位十六进制
# LLM_API_KEY 不用写在这里！部署完到「AI 配置中心」页面上填，见步骤 5。
```

生成 `JWT_SECRET`：

- Git Bash：`openssl rand -hex 32`
- Windows PowerShell：`[Convert]::ToHexString((1..32|%{Get-Random -Max 256}))`

> 不设 `JWT_SECRET` 后端会**拒绝启动**（这是刻意的安全设计）。该文件已被 git 忽略，不会进仓库。

### 步骤 3 · 构建并启动

**路径是 ASCII** → 用标准命令：

```bash
docker compose up -d --build
```

**路径含中文（踩坑规避法）** → 手工构建再启动：

```bash
docker build -t attendance-system-server      -f server/Dockerfile .
docker build -t attendance-system-web         -f Dockerfile .
docker build -t attendance-system-ai-workbench -f ai-workbench/Dockerfile .
docker compose up -d --no-build
```

### 步骤 4 · 验证

```bash
curl http://127.0.0.1:3000/api/health     # 应返回 {"success":true,"data":{"status":"ok"}}
bash server/scripts/docker-verify.sh      # 9/9 通过
```

浏览器打开：

| 地址 | 用途 |
| --- | --- |
| `http://localhost:8080` | **教务系统**（老师日常用这个） |
| `http://localhost:8082` | AI 教学工作台（**从教务系统顶栏「AI 助手」进，不要直接输入地址**） |

### 步骤 5 · 填大模型 Key（在页面上填，**不用改 .env**）

服务起来之后，浏览器打开 **AI 配置中心**：

| 部署形态 | 地址 |
| --- | --- |
| 独立端口（8080 教务 / 8082 工作台） | `http://你的服务器地址:8080/#/ai-admin` |
| 统一入口（推荐，只开一个端口） | `http://你的服务器地址/#/ai-admin` |

用 `admin` 登录后，在「大模型 API Key」一栏填入 Key，点保存 —— **立即生效，不用重启容器**。

> - 这个页面**不在任何菜单里**，只能凭地址进入；教师账号访问会被拒绝。
> - 配置优先级：**页面填的值 > `.env` 里的 `LLM_API_KEY`**。
>   所以 `.env` 里的 Key 只是「页面上还没填」时的兜底，日常改 Key 一律在页面上改。
>   某一栏留空保存 = 清除该栏，回退到 `.env`。
> - 页面上还有「账户可用余额」「本月用量」两张卡，Key 配对了就会显示真实数字，
>   可用来确认 Key 是否生效、以及大概花了多少钱。**余额空白 = Key 没配对或服务器出不了网。**

### 步骤 6 · 首次登录后必做

用 `admin / admin123456` 登录 → **立即改密码**（全体员工一同换）→ 导入真实班级 / 学员 / 课程 / 课表。

## 三、带数据迁移（把现有学籍数据搬过去）

> 适用于「在本机已录入一部分真实数据，想原样搬到校区机器」。

### ⚠️ 绝对不要直接 `cp attendance.db`

SQLite 运行在 **WAL 模式**下，除了 `attendance.db` 还有 `attendance.db-wal`（未合并的事务页）。**只拷 db 文件 → 拷出来是损坏的**，2026-09-14 在恢复脚本里实测踩过，症状是启动即崩：

```
Error: malformed database schema (92) / database disk image is malformed
```

### 正确做法 · 用内置脚本

**① 源机器上导出（不停机）**

```bash
bash server/scripts/backup-db.sh
# → server/data/attendance-20260914-2000.db （自包含单文件快照）
```

**② 把这一个文件拷到目标机**（U 盘 / 微信 / 网盘都行）

放到目标机的 `server/data/` 目录下。

**③ 目标机上恢复**

```bash
bash server/scripts/restore-db.sh server/data/attendance-20260914-2000.db attendance-server -y
```

脚本会自动：停容器 → **隔离旧的 `-wal` / `-shm`** → 覆盖 db → 启容器 → 打印学员数与库版本。

**④ 复核**

```bash
curl http://127.0.0.1:3000/api/health
# 登录系统后核对：学员数、班级数、最近考勤是否与源机一致
```

> 备份/恢复脚本已在本机**真机演练通过**：备份 → 恢复 → `PRAGMA integrity_check = ok` → e2e 80/80。

## 四、后续升级（换新版本）

### 原理：为什么不会丢数据

```
┌─ 镜像（每次升级被替换）──┐   ┌─ 数据卷（永远不动）────────┐
│ 后端代码 / 前端页面       │   │ server/data/attendance.db  │
│ 重建会丢，但没关系        │   │ 学员 / 考勤 / 财务 / 反馈  │
└──────────────────────────┘   └────────────────────────────┘
```

`docker-compose.yml` 里 `- ./server/data:/app/data` 这行就是数据保命符。

### 升级五步法（停机约 10–20 秒）

```bash
# ① 备份（最重要，永远第一步）
bash server/scripts/backup-db.sh

# ② 拉新代码
git pull origin main

# ③ 重建镜像（三条都建，或只建改动的那条）
docker build -t attendance-system-server       -f server/Dockerfile .
docker build -t attendance-system-web          -f Dockerfile .
docker build -t attendance-system-ai-workbench -f ai-workbench/Dockerfile .

# ④ 起新容器（会自动执行数据库迁移，旧数据原地保留）
docker compose up -d --no-build --force-recreate

# ⑤ 验证
curl http://127.0.0.1:3000/api/health
BASE=http://127.0.0.1:3000 node server/scripts/e2e-lifecycle.mjs   # 应 PASS 80 / FAIL 0
```

> 容器启动时 **`PRAGMA user_version` 会自动比对并逐级跑迁移**（如 v15→v16 加 `feedbacks` 表）。
> 迁移只做「加表 / 加列」，**不会删数据**。

### 开窗建议

选**课间或放学后**执行，全程 < 1 分钟。老师正在点名时不要升级。

## 五、回滚方案

数据库迁移是**单向**的（新版本的代码可能依赖新列），降级必须同时还原程序与数据：

```bash
# ① 停服务
docker compose stop server

# ② 还原数据（用升级前那份备份）
bash server/scripts/restore-db.sh server/data/attendance-<升级前的时间戳>.db attendance-server -y

# ③ 回滚程序
git checkout <旧版本 commit>
docker build -t attendance-system-server -f server/Dockerfile .
docker compose up -d --no-build
```

> 因此**升级前的备份文件请保留到确认新版本稳定运行之后**再删。

## 七、上线后常见故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端起不来，日志写 `missing JWT_SECRET` | `.env` 没配密钥 | 按 §二 步骤 2 生成并注入 |
| 启动即崩，`malformed database schema` | 直接 cp 了 db 没处理 WAL | 隔离 `-wal`/`-shm` 后用脚本恢复（见 §三） |

| 工作台显示「演示身份」 | 没从教务系统入口进 | 必须走教务系统顶栏「AI 助手」按钮 |
| 工作台显示「未配置模型」 | Key 没生效或容器没重建 | 改 `.env` 后必须重建 server 镜像 |
| AI 生成内容空白 | 关掉了 `reasoning_effort=none` 或额度太小 | 保持 `LLM_REASONING_EFFORT=none` |

## 九、PVE 服务器 + 公网 IP 部署（推荐形态）

> 编写日期：2026-09-20 ｜ 适用：**独立服务器、已装 PVE、有公网 IP**
> 这是**当前推荐的正式部署形态**，一次配好，外网与局域网都能用。

### 9.1 先做决策：装在 PVE 里的哪种环境？

| 方案 | 说明 | 推荐度 |
| --- | --- | --- |
| **A · LXC 容器**（推荐） | PVE 里直接建一个 Debian 12 LXC，容器内装 Docker | ⭐⭐⭐⭐⭐ |
| B · 虚拟机 | PVE 里建 Debian 12 VM，VM 内装 Docker | ⭐⭐⭐⭐ |
| C · PVE 宿主机直接装 | 不推荐：PVE 宿主机是" appliances "，装 Docker 有污染风险 | ⭐ |

**为什么推荐 LXC**：开销小（512 MB～1 GB 内存足够）、启动快、快照备份方便，且可以直接在 PVE 界面里做定时快照（比 Docker 卷备份更省心）。

> ⚠️ **LXC 必须开启嵌套容器支持**，否则 Docker 起不来：
> PVE 界面 → 选中该 LXC → `选项` → `特性` → 勾选 **`nesting=1`**；
> 或在宿主机执行：`pct set <CTID> -features nesting=1`。改完重启 LXC。

### 9.2 完整步骤（从零到外网可访问）

**第 1 步 · 创建 LXC**
- PVE 界面 → `创建 CT`
- 模板：`debian-12-standard`
- 磁盘：**32 GB** ｜ 内存：**2048 MB** ｜ 核心：**2**
- 网络：桥接 `vmbr0`，**静态 IP**（例 `192.168.1.50/24`，网关 `192.168.1.1`）
- ✅ 勾选 `嵌套`（nesting）
- 启动后设置 root 密码

**第 2 步 · LXC 内装 Docker**

```bash
apt update && apt install -y curl
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker version          # 能输出版本号即成功
```

**第 3 步 · 放代码 + 配置密钥**

```bash
mkdir -p /opt/jx && cd /opt/jx
# 上传项目（git clone 或 U 盘拷贝，**注意目录名用 ASCII**，不要用中文目录）
export JWT_SECRET=$(openssl rand -hex 32)
echo "JWT_SECRET=$JWT_SECRET" > .env
```

> ⚠️ **强烈建议把项目放在纯 ASCII 路径**（如 `/opt/jx/`）。Docker Compose 的 Bake 会把工作目录编码进 gRPC 会话头，**中文目录会导致 `docker compose up --build` 必然失败**。

**第 4 步 · 用「统一入口」方式启动（关键）**

本项目提供 **一个 nginx 同时托管两个前端 + 反代后端** 的形态，对外只开 **1 个端口**：

```bash
cd /opt/jx
docker compose -f docker-compose.unified.yml up -d --build
```

启动后检查：

```bash
docker compose -f docker-compose.unified.yml ps
curl -s http://127.0.0.1/api/health        # {"status":"ok",...}
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/          # 200
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/ai/       # 200
```

**第 5 步 · 放行端口（两处都要做，缺一不可）**

① **PVE 防火墙**（宿主机）：`数据中心` → `防火墙` → 确认未拦 80
② **云服务器安全组 / 路由器端口映射**：把公网 `80` 映射到 LXC 的 `192.168.1.50:80`

```bash
# 在 LXC 内确认 nginx 在监听
ss -lntp | grep :80
```

**第 6 步 · 外网验证**

用**手机 4G/5G 流量**（不要连 WiFi，才代表真正的外网）访问：

```
http://<你的公网IP>/
```

能打开登录页 → 外网打通。然后手机连内网 WiFi 访问同一地址，也能开 → 内外网都通。

### 9.3 为什么必须用「统一入口」而不是三个端口

老师报过的「**AI 工具台点击无法进入**」，根因就在"多端口"形态：

| 形态 | 老师的访问地址 | 「AI 助手」跳转 | 结果 |
| --- | --- | --- | --- |
| 三端口 | `http://公网IP:8080` | 跳到 `http://公网IP:8082` | 要额外放行 8082；若配成 `localhost:8082` 则**必挂** |
| 三端口 + HTTPS | `https://域名` | 跳到 `http://域名:8082` | **协议降级 + 错端口，必挂** |
| ✅ **统一入口** | `http://公网IP` | 跳到 `http://公网IP/ai/` | **天然正确** |

**原理**：统一入口下，「AI 助手」的跳转地址 = **访问者当前正在访问的 origin**（协议 + 主机 + 端口全部跟随），所以：
- 内网老师用 `http://192.168.1.50` 访问 → 跳到 `http://192.168.1.50/ai/` ✅
- 外网老师用 `http://公网IP` 访问 → 跳到 `http://公网IP/ai/` ✅
- 以后上了域名 + HTTPS → 跳到 `https://域名/ai/` ✅ **不用改任何配置**

> 代码层已经做到：当 `AI_WORKBENCH_URL` 配成**回环地址**（`localhost`/`127.0.0.1`）时，
> 后端自动替换为访问者 origin，并补上 `/ai` 子路径（`AI_WORKBENCH_BASE_PATH`）。
> 因此 `docker-compose.unified.yml` 里故意把 `AI_WORKBENCH_URL` 配成 `http://localhost`。

### 9.4 建议加上 HTTPS（有域名时强烈推荐）

教务系统里有**学员姓名、手机号、考勤、财务**数据，走公网不上加密不合适。

**做法（在 LXC 内用 caddy 反代，自动申请证书）**：

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
```

把统一入口的对外端口从 80 改成 80 之外的（如 `8080`），然后在 Caddyfile 里：

```
jx.你的域名.com {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
systemctl reload caddy
```

Caddy 会自动申请并续期 Let's Encrypt 证书，**且原样透传 `Host` 头**，所以「AI 助手」跳转会正确变成 `https://jx.你的域名.com/ai/`，无需改任何应用配置。

> ⚠️ 前置条件：域名已解析到该公网 IP，且云安全组放行 **443**。

### 9.5 端口规划（统一入口版）

| 端口 | 用途 | 是否对外 |
| --- | --- | --- |
| **80** | 统一入口（教务 + `/ai/` 工作台 + `/api` 后端） | ✅ **唯一需要对外开放** |
| 443 | （可选）HTTPS | 上 HTTPS 时开放 |
| 3000 | 后端 API | ❌ 仅在 Docker 内网，**不暴露** |
| 8082 | 工作台 | ❌ 统一入口下**不再需要** |

### 9.6 PVE 环境特别注意

| 事项 | 说明 |
| --- | --- |
| **必须开 nesting** | 不开则 Docker 无法启动（现象：容器内 `pct start` 后 Docker 服务起不来） |
| **磁盘别用 NFS/CIFS** | SQLite 在 NFS 上锁行为异常，会导致 `database is locked`。请用 LXC 本地存储 |
| **定时快照** | PVE → 该 CT → `快照` → 建每周定时快照（比 Docker 卷备份更省心） |
| **别把 Docker 装在 PVE 宿主机** | 会与 PVE 的 iptables / cgroup 管理冲突 |
| **LXC 特权模式** | Docker 需 `nesting=1`；若仍有权限问题，可临时勾 `unprivileged=0`（安全性略降，内网可接受） |
