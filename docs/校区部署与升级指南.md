# 校区部署与升级指南

> 编写日期：2026-09-14 ｜ 适用版本：HEAD `458e92f`（数据库 v16）
> 目标读者：把本系统**换一台电脑部署**，或后续**升级版本**的人

---

## 〇、先回答最关键的三个判断题

| 问题 | 结论 |
| --- | --- |
| **Dify 必须部署吗？** | **现在不需要。** 当前 AI 能力全部走「工作台 → 教务后端 → DeepSeek」，不经过 Dify。Dify 只在你要做**知识库问答 / 多步 Agent / 工作流编排**时才需要。先不装可省 15 个容器、约 2.2 GB 内存 |
| **能热更新吗？** | **不能热打补丁，但换新版本不丢数据。** 数据与镜像是解耦的（数据在 `server/data/`，代码在镜像里），换镜像只影响程序，不动数据 |
| **升级会不会丢学员数据？** | **不会**，前提是**升级前先备份**。数据库迁移只做「加表 / 加列」，不做删除；实测 v15→v16 升级后 29 名学员、86 条考勤一条不丢 |

## 一、目标机器准备

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11（macOS / Linux 亦可，命令基本一致） |
| Docker | **Docker Desktop 29+**（含 Compose v2） |
| 内存 | 不装 Dify：**4 GB 可用**即可；装 Dify：**≥ 8 GB，推荐 16 GB** |
| 磁盘 | 10 GB 以上 |
| 网络 | **必须能访问公网**（调用 DeepSeek）；校区内网互通即可 |

> ⚠️ **强烈建议把项目放在纯 ASCII 路径**（如 `D:\jx-system\`）。
> Docker Compose 的 Bake 会把工作目录编码进 gRPC 会话头，**中文目录会导致 `docker compose up --build` 必然失败**（Docker Desktop/Buildx 的已知缺陷，非本项目问题，见 `README.md` 排障小节）。放在 ASCII 路径下可直接使用标准命令。

## 二、全新部署（目标机没有数据）

### 步骤 1 · 拷贝项目

把整个项目目录拷到目标机（**不要拷 `server/data/` 的数据库文件**，让它自动初始化）：

```bash
# 在本机执行：导出代码（不含数据与密钥）
git clone https://github.com/gary0828/chuanwai.git D:/jx-system
# 或用 U 盘拷贝后删除 server\data\*.db*
```

### 步骤 2 · 生成密钥（**必做**）

进入项目根目录，创建 `.env`：

```bash
cd D:/jx-system
cp .env.example .env
```

然后编辑 `.env`，至少写两行：

```bash
JWT_SECRET=用下面命令生成的一串64位十六进制
LLM_API_KEY=sk-你的DeepSeek密钥      # 可选，不填则 AI 走规则引擎
```

生成 `JWT_SECRET`：

- Git Bash：`openssl rand -hex 32`
- Windows PowerShell：`[Convert]::ToHexString((1..32|%{Get-Random -Max 256}))`

> 不设 `JWT_SECRET` 后端会**拒绝启动**（这是刻意的安全设计）。该文件已被 git 忽略，不会进仓库。

### 步骤 3 · 构建并启动

**路径是 ASCII** → 用标准命令：

```bash
docker compose up -d --build
```

**路径含中文（踩坑规避法）** → 手工构建再启动：

```bash
docker build -t attendance-system-server      -f server/Dockerfile .
docker build -t attendance-system-web         -f Dockerfile .
docker build -t attendance-system-ai-workbench -f ai-workbench/Dockerfile .
docker compose up -d --no-build
```

### 步骤 4 · 验证

```bash
curl http://127.0.0.1:3000/api/health     # 应返回 {"success":true,"data":{"status":"ok"}}
bash server/scripts/docker-verify.sh      # 9/9 通过
```

浏览器打开：

| 地址 | 用途 |
| --- | --- |
| `http://localhost:8080` | **教务系统**（老师日常用这个） |
| `http://localhost:8082` | AI 教学工作台（**从教务系统顶栏「AI 助手」进，不要直接输入地址**） |

### 步骤 5 · 首次登录后必做

用 `admin / admin123456` 登录 → **立即改密码**（全体员工一同换）→ 导入真实班级 / 学员 / 课程 / 课表。

## 三、带数据迁移（把现有学籍数据搬过去）

> 适用于「在本机已录入一部分真实数据，想原样搬到校区机器」。

### ⚠️ 绝对不要直接 `cp attendance.db`

SQLite 运行在 **WAL 模式**下，除了 `attendance.db` 还有 `attendance.db-wal`（未合并的事务页）。**只拷 db 文件 → 拷出来是损坏的**，2026-09-14 在恢复脚本里实测踩过，症状是启动即崩：

```
Error: malformed database schema (92) / database disk image is malformed
```

### 正确做法 · 用内置脚本

**① 源机器上导出（不停机）**

```bash
bash server/scripts/backup-db.sh
# → server/data/attendance-20260914-2000.db （自包含单文件快照）
```

**② 把这一个文件拷到目标机**（U 盘 / 微信 / 网盘都行）

放到目标机的 `server/data/` 目录下。

**③ 目标机上恢复**

```bash
bash server/scripts/restore-db.sh server/data/attendance-20260914-2000.db attendance-server -y
```

脚本会自动：停容器 → **隔离旧的 `-wal` / `-shm`** → 覆盖 db → 启容器 → 打印学员数与库版本。

**④ 复核**

```bash
curl http://127.0.0.1:3000/api/health
# 登录系统后核对：学员数、班级数、最近考勤是否与源机一致
```

> 备份/恢复脚本已在本机**真机演练通过**：备份 → 恢复 → `PRAGMA integrity_check = ok` → e2e 80/80。

## 四、后续升级（换新版本）

### 原理：为什么不会丢数据

```
┌─ 镜像（每次升级被替换）──┐   ┌─ 数据卷（永远不动）────────┐
│ 后端代码 / 前端页面       │   │ server/data/attendance.db  │
│ 重建会丢，但没关系        │   │ 学员 / 考勤 / 财务 / 反馈  │
└──────────────────────────┘   └────────────────────────────┘
```

`docker-compose.yml` 里 `- ./server/data:/app/data` 这行就是数据保命符。

### 升级五步法（停机约 10–20 秒）

```bash
# ① 备份（最重要，永远第一步）
bash server/scripts/backup-db.sh

# ② 拉新代码
git pull origin main

# ③ 重建镜像（三条都建，或只建改动的那条）
docker build -t attendance-system-server       -f server/Dockerfile .
docker build -t attendance-system-web          -f Dockerfile .
docker build -t attendance-system-ai-workbench -f ai-workbench/Dockerfile .

# ④ 起新容器（会自动执行数据库迁移，旧数据原地保留）
docker compose up -d --no-build --force-recreate

# ⑤ 验证
curl http://127.0.0.1:3000/api/health
BASE=http://127.0.0.1:3000 node server/scripts/e2e-lifecycle.mjs   # 应 PASS 80 / FAIL 0
```

> 容器启动时 **`PRAGMA user_version` 会自动比对并逐级跑迁移**（如 v15→v16 加 `feedbacks` 表）。
> 迁移只做「加表 / 加列」，**不会删数据**。

### 开窗建议

选**课间或放学后**执行，全程 < 1 分钟。老师正在点名时不要升级。

## 五、回滚方案

数据库迁移是**单向**的（新版本的代码可能依赖新列），降级必须同时还原程序与数据：

```bash
# ① 停服务
docker compose stop server

# ② 还原数据（用升级前那份备份）
bash server/scripts/restore-db.sh server/data/attendance-<升级前的时间戳>.db attendance-server -y

# ③ 回滚程序
git checkout <旧版本 commit>
docker build -t attendance-system-server -f server/Dockerfile .
docker compose up -d --no-build
```

> 因此**升级前的备份文件请保留到确认新版本稳定运行之后**再删。

| 频率 | 动作 | 命令 |
| --- | --- | --- |

## 七、上线后常见故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端起不来，日志写 `missing JWT_SECRET` | `.env` 没配密钥 | 按 §二 步骤 2 生成并注入 |
| 启动即崩，`malformed database schema` | 直接 cp 了 db 没处理 WAL | 隔离 `-wal`/`-shm` 后用脚本恢复（见 §三） |
| `docker compose up --build` 报 gRPC 非 ASCII 错误 | 项目在中文目录 | 改用 §二 步骤 3 的手工构建，或移到 ASCII 路径 |
| 打开 8080 白屏 | 前端未重建 | `docker build -t attendance-system-web -f Dockerfile .` |
| 工作台显示「演示身份」 | 没从教务系统入口进 | 必须走教务系统顶栏「AI 助手」按钮 |
| 工作台显示「未配置模型」 | Key 没生效或容器没重建 | 改 `.env` 后必须重建 server 镜像 |
| AI 生成内容空白 | 关掉了 `reasoning_effort=none` 或额度太小 | 保持 `LLM_REASONING_EFFORT=none` |
