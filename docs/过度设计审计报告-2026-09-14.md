1. **`auth` / `perms` 指令保留**（初版列为第 3 项的一部分）。理由：后端 `rolePermissions()` 真实下发 `permissions` 数组、前端 store 也真实消费（`SET_PERMS`），这两个指令是该链路唯一的展示层消费端。删掉会让整条权限数据流失去用途。仅删除 `copy` / `longpress` / `optimize` 三个纯通用工具（164 行）。

### 执行中顺带修掉的两个问题

1. **`server/scripts/ui-p0-verify.py` 改为「接口登录 + 注入 token」**。原脚本走 UI 表单登录，无法识别登录页的 canvas 验证码，必须靠 `VITE_LOGIN_CAPTCHA=false` 重新构建才能跑（PROGRESS.md 早有记录并建议改造）。现已彻底移除对登录页的依赖：任何构建产物都能直接验证。
   - 关键坑：token 要写进 localStorage 的 **`user-info`** 键（`@pureadmin/utils` 的 `storageLocal()` 不加命名空间前缀）；写成 `responsive-user-info` 是错的（那是 `responsive-storage` 包的命名空间）。且注入后必须**整页重载**——store 在应用启动时就读了 localStorage，只改哈希不会重新初始化。
