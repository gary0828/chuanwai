# ADR-006：AI 学情报告的数据模型与录入粒度

- **状态**：**提案（待业务方确认）**
- **日期**：2026-09-12
- **决策人**：待校长确认（产品经理提出）
- **相关**：[[ADR-004-AI学情分析采用本地指标加大模型润色]]、[[ADR-005-课堂评价采用全班默认良好只标异常]]、[[ROADMAP]]

## 背景

业务方提供了一份样例学情报告：`杨倚翔-41.0-252212.pdf`（火光课堂 / 错题星出品，28 页，数学测评诊断报告），希望本系统能生成同类报告，由老师下载后手动发给家长。

已完整拆解该报告的 12 个板块（详见下文「报告结构拆解」），并逐项对照现有数据库 schema（v14）评估可得性。

## 报告结构拆解与数据可得性

| # | 报告板块 | 现有数据能否算出 | 缺失什么 |
| --- | --- | --- | --- |
| 1 | 学生姓名、班级、考试名称 | ✅ 已有 | — |
| 2 | 总考生 / 总分 / 班级平均 / 最高 / 最低 | ✅ 可算 | — |
| 3 | 诊断用时、班级平均用时 | ❌ | 考试没有"用时"字段 |
| 4 | 知识点掌握数 / 掌握率 | ❌ | 无知识点体系、无掌握度 |
| 5 | 逐题答题情况（26 题正确/错误） | ❌ | **无逐题得分** |
| 6 | 排名分析（排名 / 标准差 / 分数段分布） | ✅ 可算 | — |
| 7 | 试卷知识点分析表（主/子知识点、重要性、难度、分值、得分比、掌握程度） | ❌ | **无题目表 + 无知识点标签** |
| 8 | 历史成绩趋势 | ✅ 可算（多次考试） | — |
| 9 | 历史知识点掌握个数与正确率趋势 | ❌ | 依赖 #7 |
| 10 | 知识点掌握预警（累计测试次数、失分总和） | ❌ | 依赖 #7 |
| 11 | 错题列表（题目、我的作答、订正、错题原因 6 选 1） | ❌ | **无题目、无作答记录、无错因分类** |
| 12 | 举一反三（相似题推荐） | ❌ | **需要题库** |

**结论：28 页报告里，现有数据只能支撑第 1、2、6、8 项，约占报告信息量的 15%。**

## 关键判断

### 1. 这份报告本质是「阅卷系统」的产物，不是「教务系统」的产物

样例报告背后有：题库 + 题目知识点标注 + 逐题阅卷 + 错因分类 + 相似题推荐。**它卖的是"测评"，不是"管理"。** 本系统是教务 CRM，要 1:1 复刻，等于再造一个阅卷产品——这与 [[ADR-001-单校区自用不做多校区架构]] 确立的"只做单校区自用"和 [[ROADMAP]] §二 Non-goals（不做完整题库）直接冲突。

### 2. 逐题录分在小机构不成立

按样例的粒度，老师录入工作量的变化是：

```
现在：  1 个学生 × 1 个总分 = 1 个数字
逐题：  1 个学生 × 26 个题分 = 26 个数字（×26 倍）
```

一个班 8 人、一次月考 = 208 个数字。**必然烂尾**，与 [[ADR-005-课堂评价采用全班默认良好只标异常]] 面临的困境相同。

### 3. 但本系统有样例报告给不了的东西

样例是纯"考试诊断"。本系统额外掌握：
- **出勤数据**（出勤率、迟到/缺勤次数）
- **课堂表现**（ADR-005 的课评：专注度、参与度、作业完成）
- **课时进度**（已消耗 / 剩余课时）
- **缴费与在读状态**

**"成绩 + 出勤 + 课堂表现 + 课时"四维合并的学情报告，是纯阅卷产品做不出来的。** 这才是本系统的差异化价值，不该去硬抄一份只能靠逐题数据堆出来的报告。

## 决策（提案）

### 采用「知识点分组得分」，不采用「逐题得分」

- 建 `knowledge_points` 知识点树（学科 → 主知识点 → 子知识点）
- 考试时把整卷按**知识点组**拆成 6–10 组（不拆到单题），老师录**每组得分**
- 由此可算：知识点掌握度、班级对比、历史趋势、连续失分预警

**工作量对比**：

| 方案 | 录多少个数字/生/次 | 能产出报告的哪些板块 |
| --- | --- | --- |
| 现状（只录总分） | 1 | #1 #2 #6 #8（约 15%） |
| **知识点分组（推荐）** | **6–10** | #1 #2 #4 #6 #7(简化) #8 #9 #10（约 60%） |
| 逐题（样例同款） | 26 | #1–#11 全部（约 95%，但需题库才能出 #12） |

### 需要新增的表（3 张）

1. `knowledge_points` — `id, subject, parent_id, name, sort_order`
2. `exam_paper_groups` — `id, exam_id, knowledge_point_id, group_name, full_score, difficulty`
3. `exam_group_scores` — `id, exam_id, group_id, student_id, score`

### 明确不做（即使样例里有）

- 逐题得分与逐题错题列表
- 错题原因 6 分类（概念模糊 / 思路错误 / 审题错误 / 运算错误 / 题目过难 / 粗心大意）
- 举一反三相似题推荐（依赖题库，见 ROADMAP Non-goals）

### DeepSeek 的职责边界

沿用 [[ADR-004-AI学情分析采用本地指标加大模型润色]]：
- **本地算**：排名、平均分、标准差、分数段、知识点掌握率、历史趋势、预警
- **模型写**：开场白、知识点点评、学习建议、给家长的话
- **出网字段**：学号 + 年级 + 结构化指标 + 知识点名称（姓名/家长电话/金额不出网）

## 报告结构（本系统可产出版本）

1. 学生信息与班级
2. 本次考试：得分、排名、班级平均/最高/最低、分数段位置
3. **知识点掌握度**（按组）：已掌握 / 未掌握清单 + 得分比
4. 历史成绩趋势（多次考试折线）
5. **知识点预警**：连续多次失分的知识点 + 累计失分
6. **出勤概况**：出勤率、迟到 / 缺勤次数 ← 样例没有
7. **课堂表现**：专注度 / 参与度趋势 ← 样例没有
8. **课时进度**：已消耗 / 剩余课时 ← 样例没有
9. AI 生成的综合评语与学习建议

## 交付形式

老师在系统内一键生成 → 页面展示 → **下载 PDF，手动发给家长**（本期不做自动发送，符合 [[ADR-002-家校不做家长端与出网触达]]）。

PDF 方案建议：**优先优化 `@media print` 打印样式 + 浏览器「另存为 PDF」**，零新增依赖；若体验不达标再考虑后端生成（会在 server 侧引入新依赖，需单独评估）。

## 影响

- Phase 1 的「知识点体系最小集」范围扩大：不只是打标签，还要建"知识点组"的录分入口
- Phase 4 学情报告的产出结构按上述 9 个板块设计
- 老师的成绩录入流程会变：从录 1 个总分 → 录 6–10 个分组分

## 复审条件

- 若业务方坚持要"逐题"粒度的报告，需明确接受：老师每次考试录入量 ×6–10 倍，且需评估是否引入扫码阅卷
- 若后续引入题库，本决策可升级为逐题方案
