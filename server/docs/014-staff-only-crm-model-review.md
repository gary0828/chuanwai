# v14 员工端 CRM 定调（学生/家长无账号，家长信息并入学生档案）数据模型评审

- 日期：2026-08-14
- 变更类型：改约束 / 加字段 / 删表 / 删除逻辑 / 跨模块联动
- 结论：通过

## 背景与必要性

系统定位调整为**纯员工端 CRM**：学生不登录、家长不登录、无账号，只有机构员工（admin/teacher）可登录。v13 为"学生登录/家长端"预埋的账号体系（student 账号、parent 账号、parent_children 绑定表、notifications.target_user_id 指向家长账号）为过度设计，需整体收敛：

- users 只保留员工账号（role 收紧为 admin/teacher）
- 家长信息并入学生档案（students.parent_name / parent_phone，v9 已有字段）
- 通知从"推给家长账号"简化为"给学生档案留通知记录（含家长姓名快照）"

## 1. 数据模型变更单

| 表              | 变更                                                                           | 说明                                                                        |
| --------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| users           | role CHECK 收紧为 `('admin','teacher')`，重建表                                | 删除历史 student/parent 账号数据（含 s2023001 演示账号）                    |
| students        | 删除 `user_id` 列及唯一索引                                                    | v13 引入的账号↔档案一对一关联废弃；家长字段（v9 已有）成为唯一家长信息来源 |
| parent_children | 整表删除                                                                       | 家长绑定关系并入 students.parent_name / parent_phone                        |
| notifications   | `target_user_id` 列删除，新增 `parent_name` 快照列（TEXT NOT NULL DEFAULT ''） | 通知目标从"家长账号"变为"家长姓名快照"（家长无账号，通知仅内部留痕）        |

无新增表；无新增外键。

## 2. 数据源归属表

| 字段                                | 唯一写入口                                  | 消费方（只读）                                       | 是否冗余   | 冗余同步时机                                       |
| ----------------------------------- | ------------------------------------------- | ---------------------------------------------------- | ---------- | -------------------------------------------------- |
| students.parent_name / parent_phone | students 接口（新增/编辑/导入）+ leads 转化 | notifications 生成（考勤缺勤/成绩发布/请假审批通过） | 否         | -                                                  |
| users（admin/teacher）              | 用户管理（员工账号页）                      | 登录 / 权限 / 审计                                   | 否         | -                                                  |
| notifications.parent_name           | 各通知生成点（从 students 快照）            | 通知记录页展示                                       | 是（快照） | 生成通知时写入；档案修改不回写历史通知（留痕语义） |

## 3. 跨模块联动清单

| 触发方               | 目标方                                                 | 方向 | 反向补偿                             | 幂等性                           | 事务边界 |
| -------------------- | ------------------------------------------------------ | ---- | ------------------------------------ | -------------------------------- | -------- |
| 考勤登记标记「缺勤」 | notifications 生成缺勤通知（parent_name 从学生档案取） | 正向 | 改回非缺勤 → 删除当日缺勤通知        | 已有当日同学生缺勤通知不重复生成 | 同事务   |
| 考试录入成绩（新增） | notifications 生成成绩发布通知                         | 正向 | 修改已有成绩不重复通知               | 已存在成绩仅更新不通知           | 同事务   |
| 请假审批「通过」     | notifications 生成审批通过通知                         | 正向 | 考勤改回其他状态 → 撤销该通知        | 重复审批拒绝                     | 同事务   |
| 线索转化             | students 建档案（含家长姓名/手机号）+ orders 建单      | 正向 | 删除学生级联清理；已转化线索禁止删除 | 手机号已存在则拒绝重复转化       | 同事务   |
| 学生删除             | 级联清理考勤/请假/通知/成绩/课时流水等                 | 正向 | 有订单 → 400 保护                    | -                                | 同事务   |

> v14 相比 v13 的联动变化：不再生成/绑定家长账号与 parent_children；通知目标从"家长账号 ID"变为"家长姓名快照"；线索转化不再建 student/parent 账号。
