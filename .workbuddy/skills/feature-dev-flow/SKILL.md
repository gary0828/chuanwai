# 项目功能开发流程（强制门禁）

## 何时用

- 用户提出任何新需求 / 要开发新功能
- 要改现有功能的行为、配置、权限
- 修 bug（走 ①②③④，⑤ 可省）

**不走本流程（快速通道）**：错别字、注释、纯样式微调（走 `tokens.scss`）、已拍板事项的重复执行、纯文档修正。

> ⚠️ 快速通道**仅限「无行为变化」**的改动。**只要代码行为变了，就走全流程。**

---

## 为什么有这套流程

三条真实事故，根因都是「只解决被指出的那一处」：

| 事故 | 根因 |
|---|---|
| **413 上传失败** | 三份 nginx 配置只改了一份（统一入口），另两份（8080 / 8082）没改，7 天后用户实测才炸 |
| **头像无法修改** | 做「站点 Logo 上传」时只当成"一个配置项"，没想到"系统里还有哪些东西本该可编辑" |
| **通知铃铛是演示数据** | 09-14 就发现了，却写进 `PROGRESS.md`（**已完成**文档）→ 从此 7 天无人再见过 |

**共同点**：解决了被点名的「那一个点」，没解决「那一类问题」；且把待决策事项记进了错误的文档。

---

## ① 需求澄清 —— 调 `grill-me`

**目的**：搞清楚**要解决什么问题**，而不是**要做什么功能**。

**动作**：加载 `grill-me` skill 追问（每问先给出我的建议答案；能用代码查证的不问用户）。

> ★ **实践变体（2026-09-26 / 10-01）**：`grill-me` 原文要求「逐个分支追问」，但实测
> **用 `AskUserQuestion` 一次问 3–4 个决策点更省用户时间**（用户两轮就把 7 个决策全拍完了）。
> 前提：每题都给**推荐选项 + 理由**，且只问「真正需要用户决策」的（能查证的自己查）。

**必答 4 问**：

1. **谁用？**（教务端 = 校区负责人 / AI 工作台 = 一线老师）
   > 本项目有「人群分离」铁律。放错端的返工成本极高 —— 真踩过：把「课后随手记」做在教务端签到页，整块要迁到工作台。
2. **解决什么问题？现在怎么凑合的？**
3. **验收标准是什么？**（怎么算做完了）
4. **明确不做什么？**（边界）

**产出**：《需求确认》= 要解决的业务问题 + 验收标准 + 边界。

### ⛔ 门禁 1：用户未确认《需求确认》前，一行代码都不许写。

---

## ② 扫描 + 横向同类扫描 + 开发计划

### 2.1 现状扫描
这个需求会碰到哪些代码 / 配置 / 接口 / 数据 / 文档。

### 2.2 ★★ 横向同类扫描（强制五问，不许跳）

| 扫什么 | 触发条件 | 真实事故 |
|---|---|---|
| **多份同步配置** | 要改三份 nginx / 两种 docker-compose / 双端共用逻辑 | 413（只改一份） |
| **同类可编辑内容** | 要加"用户可编辑的东西" | 头像（做 Logo 时没想到） |
| **同类 bug** | 修任何一个 bug | 只修被点名那一处 |
| **同类演示数据** | 发现写死 / 假数据 | 铃铛演示数据 |
| **★ 同类页面/组件的写法** | **要新增任何页面、组件或表单** | `ai-workbench/views/Todos.vue`（2026-09-21）—— 全工作台只用它用了原生 `<input>/<select>`，其它页一律 `el-input/el-select`，结果整页像"没样式的白板" |

> ★ **新增页面/组件前，必须先打开 2–3 个同类页面，看它们用什么组件、什么写法，照抄。**
> 判断口诀：**"我要写的这个控件，项目里已经有别的地方在用吗？用的哪个组件？"**
> 反面教材：自己发明一套原生控件 + 自写 CSS，即使功能对，观感也与全站割裂。
>
> ★★ **本项目的关键差异（极易踩）**：两端组件库**不是同一套** ——
> | 端 | 路径 | 样式来源 |
> |---|---|---|
> | 教务端 | `src/` | **pure-admin + Element Plus**（`el-*` 齐全，样式受 `element-plus-override.scss` 管辖） |
> | AI 工作台 | `ai-workbench/src/` | **也是 Element Plus**（`el-button/el-select/el-input/el-radio-group/el-tabs/el-checkbox` 都在用），但**没有 pure-admin 的壳与全局覆盖**，靠各页 scoped CSS + `styles.css` 的 `.card/.tag/.btn` |
> 所以**两端都用 `el-*`**，但工作台的排版要抄工作台自己的页面（如 `Settings.vue`），别照搬教务端的骨架类。

**本项目的具体扫描清单**（照做，别凭记忆）：

| 类别 | 具体文件 |
|---|---|
| **唯一的 nginx** | `deploy/nginx-unified.conf` —— ★ 2026-09-23 起**只剩这一份**（`ai-workbench/nginx.conf`、`ai-workbench/Dockerfile` 已随「工作台单独部署」形态一并删除，见 K-027） |
| 部署形态 | **只有一份编排** `docker-compose.yml`（统一入口单端口；原三端口 / `docker-compose.unified.yml` 已于 2026-09-23 删除） |
| 双端 | 教务端 `src/` · 工作台 `ai-workbench/` |
| **文档四件套** | `docs/04-API/API.md` · `docs/04-API/openapi.yaml` · `server/database.md` · `docs/08-参考/PROGRESS.md` |

> ✅ **路径已于 2026-09-23 核对修正**（原写 `docs/api.md` / `docs/openapi.yaml` / `docs/PROGRESS.md`，均为旧路径）。

**扫描命令示例**（改配置类必跑）：
```bash
node _verify_test/preflight.mjs        # ★ 首选：node 自己扫，含「过时表述 / 迁移连续性 / SQL 注入 / 调试残留」
rg -n "client_max_body_size" deploy/nginx-unified.conf   # 只有一份 nginx，改完即全覆盖
git diff --stat                        # 检查是否漏改了同类的其它文件
```

> ★★ **不要用 shell 的 `grep -r` / `grep -n` 扫代码** —— 本环境的 shell grep 会**静默漏返回**。
> 2026-10-01 实测：扫文档时漏掉 **7 处**待改内容，还导致 ADR 里的出处写错，事后再扫才发现。
> 请用 **ripgrep（`rg`）** 或 **`node _verify_test/preflight.mjs`**（内部用 node 读文件，不依赖任何外部工具）。

### 2.3 产出《开发计划》
改动清单 + **同类项清单** + 风险 + 需用户拍板的决策点。

### ⛔ 门禁 2：用户逐项决定做哪些。未获批的项 → 写进 `ROADMAP.md`，**不进本次开发**。

> 开发时加载哪些 skill，见 **③ · 3.1**（路由表已按宿主环节重排过一次）。

## ③ 开发 + 开环境给用户测（不重构生产）

### 3.1 加载开发用 skill（按类型挑，别硬写）

| 类型 | 开发 skill |
|---|---|
| 工作台新功能 / 权限放行 | `workbench-feature-with-permission` |
| 视觉改版 / 设计 token | `element-plus-token-revamp` |
| 死代码清理 | `safe-dead-code-cleanup` |
| 过度设计审查 | `ponytail-audit` |

> ★ 这张表原本挂在 **②（计划阶段）**，已按宿主环节**重排到此处** —— 它们是**开发时**才加载的
> （`workbench-feature-with-permission` 自带「执行清单 7 步」）。
> ② 阶段只需知道"本次将由哪套规范约束"，不必在此加载。

### 3.2 按计划开发
**不擅自扩大范围**。想加东西 → 回到 ② 问用户。

### 3.3 开环境（统一入口单端口 —— 2026-09-23 起唯一形态）
```bash
docker compose build <改动过的服务>
docker compose up -d <改动过的服务>
docker exec attendance-unified nginx -s reload
```
> ★ **重建 `server` 后必须 reload `attendance-unified` 的 nginx**，否则 `/api/*` 全 502
> （根因：nginx `proxy_pass http://server:3000` 无变量，启动时缓存上游 IP）。
> 口诀：**`/` 200 但 `/api/*` 502 = 上游 IP 缓存问题。**
>
> 访问地址：`http://localhost:${WEB_PORT:-18080}`（教务 `/` ＋ 工作台 `/ai/` ＋ 后端 `/api` 同端口）；
> 容器名：`attendance-server` / `attendance-unified`。
> 生产形态的重建**留到第 ⑤ 步问用户**，本步不做。

### 3.4 自测：浏览器验证
- **首选项目自有回归套件** `_verify_test/*.py`（Playwright + 契约断言，已在用）
- 需要**新的交互式验证**时 → 加载 `agent-browser` 或 `playwright-cli`
- ★ **自测通过 ≠ 用户通过**。自测只证明 API 逻辑与页面能跑，**不能替代用户实测**。
  > 沙箱（`_verify_test/serve-dist.mjs`）**没有 nginx 层** → nginx 配置 / 跨容器路径 / 缓存类问题**永远测不出来**。

### 3.5 给出测试指引
测什么 / 怎么测 / 预期结果 / 访问地址。

### ⛔ 门禁 3：等用户实测。用户不通过，不得进 ④。
### ❌ 禁止：自己跑完沙箱测试就宣布完成。

> ★ **例外条款（2026-10-01 补）**：用户**主动要求**「先推上去」时，按用户决定执行，但**必须**：
> ① 提交信息里**如实写明**「用户尚未实测即要求先推送」；② 对话里明确告知风险；
> ③ `CURSOR.md` 保留「待实测」状态 —— **不得**把「已推送」静默等同于「已验证」。

## ④ 用户测试通过 → 文档同步 + 推送 git

### 4.1 文档清单（按变更类型对号入座）

| 变更类型 | 必须更新 | 附加门禁 |
|---|---|---|
| API | `docs/04-API/API.md` + `docs/04-API/openapi.yaml` | **跑 `_verify_test/check-openapi.mjs`** |
| DB 表结构 | `server/database.md` + `server/src/migrations/0NN-*.js` | 版本号**连续**（当前基线 **v25**），跳号会终止启动 |
| 已完成功能 | `docs/08-参考/PROGRESS.md` | — |
| 待做变化 | `docs/07-架构与决策/ROADMAP.md` | — |
| 拍板决策 | `docs/07-架构与决策/ADR/ADR-00N-*.md` | **只追加不修改**；并登记至 `docs/00-导航.md` ADR 索引 |

> ✅ **路径已于 2026-09-23 核对修正**（原文的 `docs/api.md` / `docs/openapi.yaml` / `docs/PROGRESS.md` / `docs/ROADMAP.md` / `docs/decisions/` 均非实际位置）。
> ★ **触碰 ADR / Non-goals 时**：按门禁 9 **显式新增 ADR 修订**（照 ADR-008 的做法：新 ADR 声明"部分取代/部分解除"，并在 `docs/00-导航.md` §7 标注解除项），**不得默默绕开**。

> ★ **只有「新建 / 改表结构」才要迁移** —— 往既有 K-V 表（`settings`）加键位属**纯数据写入**，不占版本号。

### 4.2 提交前审查

**先跑可执行检查（不许跳）**：
```bash
node _verify_test/preflight.mjs   # 过时表述 / 迁移连续性 / SQL 注入 / 调试残留 / 行尾提示
```
> ★ 为什么加这一步：`code-review-and-quality` 是「给人看的五轴 checklist」，**没有可执行部分**，
> 实践中容易退化成「口头过一遍」= 等于没审。preflight 把其中**可自动化**的部分
> （规范性、明显缺陷、注入风险）变成**真的会失败**的门禁。**先跑脚本，再做人工判断。**

然后加载 `code-review-and-quality`（五轴：规范性 / Bug / 性能 / 可读性 / 质量评分）。

### 4.3 推送安全三步
```bash
git diff --cached --name-only | grep -iE "\.env$|server/data/|\.db$"   # 必为空
# 扫手机号 / 身份证
git -c http.proxy= -c https.proxy= push gitee main                      # 必须清代理
git rev-parse HEAD                                                      # 与 ls-remote 比 SHA
```

### ⛔ 门禁 4：提交前给用户验收清单。

## ⑤ 询问是否重构 docker（生产形态）

**由用户决定，不自动做。**

若做 → 加载 `vite-vue3-predeploy-healthcheck` + 统一入口（`docker-compose.yml`）验收。

## 贯穿全程：门禁清单

### 必须停下来问用户（9 条）

| # | 触发 | 问什么 |
|---|---|---|
| 1 | 接到新需求 | 《需求确认》，确认前不动手 |
| 2 | 扫出同类问题 | 要不要一起做 |
| 3 | ★ 发现"待决策"事项 | 必须进 ROADMAP + 当面告知 |
| 4 | 需求有多种做法 | 列选项用户选 |
| 5 | 要改多份同步配置 | 其余几份要不要一起改 |
| 6 | 要加可编辑内容 | 同类可编辑项要不要一并规划 |
| 7 | 功能做完 | 等用户测，测过才继续 |
| 8 | 提交前 | 给用户验收清单 |
| 9 | 触碰 ADR / Non-goals | 显式修订还是绕开 |

### 不必打断
错别字、注释、纯样式微调（走 `tokens.scss`）、已拍板事项的重复执行、纯文档修正。

---

## ★ 待决策事项的归属铁律

> **待决策 → 只进 `ROADMAP.md`；`PROGRESS.md` 只记已完成。**

**事故**：09-14 发现通知铃铛是演示数据，记在 `PROGRESS.md`「新发现待决策」→ 一份"已完成"文档里放"待决策" → 7 天无人再提。

**执行**：
- 任何时候发现"需要用户 / 产品决策"的事项 → 写入 `ROADMAP.md`，**并在对话里明确告知用户**
- **禁止**把"待决策""待建设""搁置"字样写进 `PROGRESS.md`

## 开发结束前的自查（每次过一遍）

| 违规 | 检查 |
|---|---|
| 用户没确认需求就动手 | 《需求确认》在哪？ |
| 只修了被点名那一处 | 同类扫描五问做了吗？清单在哪？ |
| 新写的页面/组件观感与全站割裂 | 动手前有没有打开 2–3 个同类页面、照抄它们的组件与写法？ |
| 同类问题没问用户就自己决定不做 | 有没有问过？ |
| 把待决策写进了 PROGRESS | `grep -n "待决策\|待建设" docs/08-参考/PROGRESS.md` 应为空 |
| 自己跑完沙箱就宣布完成 | 用户实测过了吗？ |
| 漏改了同类的其它文件 | `git diff --stat` 对过了吗？（nginx 现只剩一份，重点是文档四件套与双端） |
| 跳过了文档同步 | 4.1 的表逐行对过了吗？ |
| 擅自扩大了开发范围 | 与《开发计划》比，多了什么？多出来的问过用户吗？ |
